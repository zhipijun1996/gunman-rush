# 分阶段灰盒规格

旧MVP-01角色/反冲/触屏工程是P1基线，不因新设计推倒。当前已有可运行工程、N跳/可变跳高、释放射击攻击弹体/反冲、补充点/机关、三输入和慢时/遮罩原型；旧即死检查点场景尚未迁移正式伤害。参数仍来自config/player_tuning.json与input_profile.json，物理60Hz。

## 本次边界

本次先整合权威设计/架构/任务/验收，保存并回归现有原型（P1）。没有实现玩家Health、敌人AI、正式环境回退、家园、商店、Boss、随机地图或永久存档。文档中的接口不能记成代码已完成。

## 六阶段可验证交付

| 阶段 | 最小交付 | 明确后续范围 |
| --- | --- | --- |
| P1 | 保留原型与真实失败退出码回归，标记旧即死/慢时为原型 | 真机输入/手感仍分别验收 |
| P2 | 固定灰盒Health、独立Stamina配置/接口、一个敌人、怪物伤害/环境段回退/零血结束run | 仅最小RunLifetime/返回Home占位；不做完整路线、永久经济或Boss |
| P3 | 一个补给、道具二选一、可撤销来源Modifier、一个最小商店 | 不做完整随机道具库/刷新/高级经济 |
| P4 | development_only的3关固定测试链、两出口、一个Boss与必出金奖励、最小家园入口/返回 | 无正式永久升级经济；不满足正式10关规则 |
| P5 | 每主题正式10关、Boss必达、固定核心/随机外围Boss模板、少量已验证模块和完整Manifest | 模块生成晚于固定挑战真机验证，不批量做全部主题 |
| P6 | 独立Meta/版本化永久存档，再按任务增加人物/枪支/主题/道具/剧情 | 货币/保留等未决定部分先规格确认 |

每阶段小任务见tasks；未满足依赖/验收不推进完整系统。正式角色未来有血量/精力/枪支/能力，但P1保留现有动作链，精力用途待定，不能隐式给跳跃/移动/射击增加消耗。

Android/iPhone共用Web快速试玩，APK按需独立构建，Windows预设独立验证；自动检查、解析、物理、Web/原生导出、真机是不同证据。当前不做原生iOS签名、Steamworks或商店发布。安全段回退≤0.5秒可操控是候选体验目标，旧即死重生的自动通过不算新DamagePolicy通过。固定挑战20–30秒目标记录游戏秒和墙钟，需真实试玩。
