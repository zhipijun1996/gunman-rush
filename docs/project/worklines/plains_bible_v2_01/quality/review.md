## 根因与实际证据

### 关卡：以补通路替代动作设计

最高优先级。房间职责表有不同名称和用途，但大量实地形用薄矩形、等距台阶补通高度；低层安全路径还承担了前进。P-R26 的职责写“移动台接反冲抬升”，又允许“地面绕行到检修梯”；`tests/world/plains_first_loop.gd` 对该房的连续路线沿长底层、固定阶梯前往出口，没有把双承载机关作为这条通行路线的必要条件。机关确实存在、可被射击启停，但这不证明它组织了玩家的决定。可选捷线允许存在，不能以其存在证明主路教学或反冲主导成立。

P-R35 场景有37个碰撞矩形，其中35个高度不超过32wu、21个为单向平台；中央连续高差多为72wu。统计只用于定位重复结构，薄梁本身并非禁止。当前错误在于用密集通路支架替代场所体量、主次路线和有意义的动作关系。

`tests/world/plains_motor.gd` 只在 P-R22 单个固定起点比较不射击与一次射击；无 H／无 D 测试证明对应资格门槛，不证明整区反冲价值。真实控制器和已知坐标回放可以证明这些路线能执行，不能证明初见可读、有趣，也没有完成 Skill 所要求的“保留弹丸和机关、关闭反冲位移”对照。此次没有实际运行该整区对照，不补写结果。

### 向下出口与草：把碰撞附着误当成构图成立

图1对应 P-R35 东行汇口。`game/world/regions/P/rooms/P-R35.tscn` 的主地面在 x1232—1584 留出352wu间隔，内部再塞中间落台与侧台，形成过度展开的凹槽。门口应该以连续地形上的适度缺口和明确下方空间表达；当前为补落脚把门口做成了平台拼盘。

`game/presentation/world/plains_v07/plains_room_art.gd` 按每个合格平台的左端+48、右端−48自动种同一种草，未排除单向薄梁。“不埋进碰撞、根点落在台面”只保证坐标附着，不能保证有土层、根系、植物群落和可信支撑。因而复制了悬空薄台上的孤立草簇。

### 美术：素材接入没有落实为参考图的空间与光色

`FixedWorldApp` 仍调用 `UnderworldParallax.configure(camera)`，未传房间或世界构图信息；实际背景读取旧 `assets/underworld_plains/scenery_build.json`，空 manifest 还启用了 `_home_landmarks`。导入新包并使用其中精灵，不等于整套背景消费者已按新房间重做。

`PlainsRoomArt` 的室外环境色接近白色 `(.94,.97,1)`，深度物件统一染色；灯光主要来自休息点和显式 light 放置。风中微粒是所有房间共用的18个2×1矩形及短拖尾。实现中确实有视差、草摆动、光源、遮光与粒子，但没有用参考画面逐层校准远景对比、地形厚度、支撑、局部光焦点和可感知风向；不能把“节点存在”写成“氛围通过”。

图2的关键是厚实有根基的地形、远中近层次、低对比远景、局部暖光与有方向的环境光、受控前景。平原应保持自身地域身份并达到这些构图和材质标准，不能以参考是森林为理由降低要求。素材包中候选图也不自动获得最终场景认可。

### 地图：主动降格成拓扑示意图

`tools/world/build.py::navigation_geometry` 在所有房间存在 `map_origin` 时，提前返回独立矩形与 `survey_with_explicit_connections`，绕过后续成对门口接缝定位；`world_map.gd` 再画长直线连接端点。图可达通过，只证明图论连通，不证明玩家看到的是一个连续地区。

我还把 `room_authoring.md` 原有“共享接缝开口，不以中心点连线替代连接”改成允许示意布局。这是为实现妥协而改验收标准，应撤回。最新 ZIP 仍是身份、连接和整区设计来源；问题不在需要退休旧地图，而在没有把新设计落成连贯空间。

### UI：缩放与字体规则分裂

`world_dialogue.gd::_fit` 按 `pixel_scale` 的倒数放大字号、按钮和边距以保持 CSS 阅读尺寸，并单独使用灰度抗锯齿字体与线性过滤；HUD及其他浮层则沿逻辑画布缩放，`DemoUiModalMetrics.ui_scale()` 恒为1。各模块都有自己的“可读”规则，却没有共同的字号层级、字面密度及相对角色/画面占比。

之前960×540截图只检查可读、不溢出，未检查实际浏览器可用视口、留黑与触控层叠加后的整体比例。用户图1没有打开对话框，不能将其全部比例问题归因于对话单一分支；HUD、菜单、回复和交互需作为整套界面复核。未测到截图设备的 CSS/DPR，不能从图片反推精确字号或宣称已真机复现。

## 为什么审查没有拦住

两份 Skill 已明确要求先校准可玩结构和真实合屏，再换第二种几何验证，最后按连通片区扩展；还要求反冲反例、恢复不绕过目标、地形形态先于装饰、风向可见和光照对照。问题是执行失效，不是文件未入库或缺规则。

制作顺序偏向先铺满35房、再补通路、再加贴图；审查又把代码存在、自动运行通过、截图已产出当成美术和体验通过。重复平台、通用背景和薄弱机关关系因此批量扩散。此前“统一”“有层次”“完整”的专业判断没有足够对比依据，现撤回。未要求用户认可，不能成为我降低自身专业审查标准的理由。

## 返工条件

1. 先按最新整区设计重排连续空间、接缝、主支路和回环。选择包含反冲挑战、机关、枢纽/下行出口、休息交互的相连片区校准，并在第二种几何中验证方法；这只是扩展前的校准，不是把35房目标缩成样房。
2. 每个承担反冲或机关职责的环节先落实“观察—决定—动作—结果—恢复”。用真实控制器检查普通动作、保留弹丸的无反冲、机关已开、低层绕行及不同来向；恢复返回当前任务，不直接赠送前进。安静房和普通战斗按各自职责审查，不强迫每个房间射击。
3. 先形成有体量和支撑的可玩轮廓，再按认可参考逐层拼装。正常镜头比较地形/人物/背景关系，同机位比较光照开关，按美术 Skill 的6秒定机位及360px预览检验风向和粒子可见性。不得只改粒子数量或套统一染色后判通过。
4. UI按同一视觉层级复核实际浏览器画布、CSS显示尺寸、留黑和触控状态，分别验证HUD、交互、对话、地图、暂停；扩大触控热区不等于扩大文字和可见面板。浏览器模拟与实体设备分别记录。
5. 按连通片区完成其余房间；每房说明实际差异与未通过项，再验连续主循环、支路、回访、失败恢复及保存。全区功能通过不能替代全区体验审查。交付默认短录像，遵守现行20秒/3MB规则。

以上由实施者直接执行和复核，不新增用户审批或独立审查前置。权威制作规则见房间圣经与开发流程，两份 Skill 提供具体方法；本节仅记录本轮恢复动作。
