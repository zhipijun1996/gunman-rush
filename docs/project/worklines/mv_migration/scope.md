## 本轮基线、范围与结果

核对基线 `main@a5a48a24d01fc3d12680b9379fa3ed4656c427ee`，任务分支 `docs/mv-runtime-architecture`，交付见 [PR139](https://github.com/zhipijun1996/gunman-rush/pull/139)。PR138已合入；旧PR择取、历史证据清理与旧原型存档兼容均不再是前置。进度和依赖唯一见 [任务表](../../tasks.md)。

当前正式入口、运行版本和线上build见 [当前状态](../../current_state.md)。PlayerMotor、战斗、工厂、库存/装配、表现、收据和存储可靠性已有消费者；固定房间、四种寿命世界payload、任务/修钟事实及新档继续入口未接通。Runtime/Stage和RunSession仍有旧地图身份与清空时机，具体适配边界见架构，不能由文档签收新世界运行。

## 首批闭环：固定原拓扑与实际结果

既定代表房仍是P-R03／P-R01／P-R06／P-R14。按房核查后，P-R01到P-R06之间必须经过P-R08，作为必要连接房施工，不另建直连或平行路线。下面仅是本次验收引用，源数据仍由 [世界输入](../../../data/world/README.md) 拥有；实施前用 `python3 tools/world/room_context.py <房间ID> --contract` 复核。

| 段落 | 权威连接/动作及本次落点 |
| --- | --- |
| P-R03初行草坡 → P-R01钟外小站 | 实际完成tutorial_move、tutorial_shoot、tutorial_recoil后，经START-P03-P01；不能以加载房间代替教学动作。真实抵达站点的station_briefing提交station_briefed；合同通用交互模板需按权威action类型适配，不能把所有事件都实现为拾取按钮 |
| P-R01 → P-R08 → P-R06风铃岔路 | 经L01（station_briefed）和room-link-139；P-R08只承担原有连接/场所意图。进入站点、对话、保存和普通过房不自动休息；在P-R01单独执行显式休息 |
| P-R06 → P-R14牧风者庭地 → 原路返回 | 经L02，复用已存在牧风者场景/Definition，补实际场地锚点与独立世界Boss绑定；真正胜利提交defeat_P_WINDKEEPER，再以get_H唯一领取H。重复互动/离房再访不刷Boss、不再授予H |

未纳入样板的相邻房/服务保留源身份，不伪装为已施工；错误/未实现入口可恢复并明确反馈。首批只证明这些必要连接，不能据此声称全部岔路、交通、NPC服务或地区内容已完成。

| 真实流程 | 验收观察与反例 |
| --- | --- |
| 新世界开始 → 出发 → 跨房 → 战斗/交互 → 返回/再访 | 从正常玩家入口进入P-R03；门台、相机和取消后的首个操作正确；角色/能力/动作资源不被换房重建；地图只增加实际到达知识，浏览地图不揭示主体 |
| 显式休息／存活地形失败／死亡 | 休息推进周期；普通过房不推进。存活失败回实际来侧且不穿越能力环境，致命失败转死亡。按现行试制政策检查恢复，金币政策保持未决，不从旧Run清空推导新规则 |
| 唯一胜利/领取 → 离房回访 → 保存 → 退出进程 → 继续 | 胜利与H收据、休息点、已提交知识和状态恢复一致，不能重复授予；窗口重开/节点重建不算退出重启证据。写失败、重复ID不同载荷及内容引用失效分别拒绝/安全恢复 |
| 同帧致命伤与未提交胜利/奖励；取消后旧请求返回 | 按既有帧伤害与生命周期裁决，回调顺序不同不改变结果；已提交永久结果不回滚，旧epoch/装载票据不能污染新房 |
| Q资格、冷却与危险过滤 | 首批房不授予Q，正式get_Q位于权威源K-R10。01E用同一运行实现、明确授予Q前置的独立输入夹具验落地/冷却/暂停/跨房和危险反例；首批正常路线另验未持有Q不产生保护。后续合法获取路线再签收正式Q流程，不能通过提前送Q改写首批进度 |
