## 方法收敛结果

设计权威仍为Visual Bible／区域Bible；场景生产主流程唯一为.agents/skills/godot-room-art/SKILL.md。新增references/regional-kit-production.md持有区域套件、完整资产、现有组合协议、跨房型验证和迁移方法。engine-first-2d保留为引擎职责／转译方法，明确固定组画的适用范围。

房间是构图与体验检查单位，区域套件是共享素材生产单位。普通房引用地形、结构、完整景深和已验证组合，重要地标按职责定制。独立移动／视差／破坏会露出的部分从开始画完整；同一静态画的受光分区不具备被遮挡背景，不能冒充独立素材库。保留Tile拓扑不等于冻结当前PNG；几何与素材能力协同校准，复验动作和邻接。

在真实样房中一起设计材质、结构比例、端头／中段和受光关系，再扩资产族。共享缺陷修母版或组合，房间构图问题修本房，避免逐房复制根土／支撑／灯光补丁。区域套件是生产分组，正式引用仍归现有目录、定义和房间JSON，没有在方法中发明未被消费者支持的新字段。

## 如何验收本次方法

本轮是制作者自审，不称独立外审。实际差异仅涉及文档／Skill，未改正式运行代码或房间数据；现有组合协议、分类和数据源可复用。静态检查支持规则入口、链接与包结构整理，不支持“美术量产已合理”的结论。当前可接受结论是待验证的试用方法。

| 判断 | 当前证据／待交付 |
| --- | --- |
| 规则与现有技术一致 | 已核实际catalog、单层members限制与正式消费者；未新增平行schema |
| 单房转译可控 | 有前次固定机位原生像素与效果证据、用户相对改善反馈；适用范围有限 |
| 同套资源跨几何仍好看 | 未验证；需同区不同房型的无标注实帧及实际镜头移动，不能只给概念图 |
| 新房成本降低 | 未验证；需列每房真实复用资源、新增资源与专属覆盖，并记录实际制作时间 |
| 共享修改易维护 | 未验证；需修改一次公共材质／组合，在全部样房复看，展示是否还要逐房补丁 |

下一验证由Codex制作与初筛，用户不承担阅读全部差异或基础跑图。交付同套件不同房型的整图、原速短片、实际复用／新增清单与一次共享修改前后。若每房仍需新整景／大量专属遮罩，镜头移动露底，组合导致重复构图或损害玩法，或公共改动仍需逐房修补，应判方法在该范围失败，回到素材／组合／流程修改，不继续靠增加规则或资源数量宣称完成。

## 下一阶段，尚未实施

1. 选择同一区域的真实可装载样房和有差异的验证几何。确定最小材质母版、结构族与完整独立景深，不先扩全部区域。
2. 复用已有定义和单层members组合，制作有明确接合／锚点／受光职责的代表资产与已支持尺寸。发现真正缺少的运行时能力后再按共同合同实现及专项验证，不把方法描述当代码。
3. 用同一批关键资产和公共组合验证横向通道、竖井、宽厅等实际不同几何，真实移动镜头、隐藏独立层并检查入口、恢复和完整覆盖。三种房型是本次建议的风险样本，不是所有任务的固定配额。
4. 在适用范围成立后逐批适配已有房间。普通房增加布局、选型与参数，少数独特场所定制；仍逐房审看，不能把套件通过签成309房完成。授权范围为整区时，样房只是校准环节。

上述是下一验证与实现范围，不是本轮已完成的区域套件或44房美术迁移。本轮不启动该阶段，也不以“一套新规则”代替实际多房型证明。
