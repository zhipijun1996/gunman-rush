# 世界内容接入

## 目标与授权

用户在世界漫游网页继续迭代世界、剧情和经济，主游戏通过固定接口采用网页输出。本工作线完成版本化输出、开发期导入、离线读取、稳定身份绑定和一个实际房间消费者；世界房间的具体施工继续按普通房间规范进行。

## 分支与写集

- 分支：`feat/world-content-channel-v1`，主游戏集成基线 `4d7dadd2b920e261f10cd5543ce2a40c7188dcaf`。
- 网页生产者：`clock-world-explorer-1117` Site 的 `tools/content_channel/`、导出脚本和 `dist/exports/channel-v1/`。
- 游戏消费者：`tools/content_channel/`、`production/game/content/`、导入配置、普通房间的显式接入、针对性检查及现行文档。
- 根工程与冻结平原继续由其原入口持有。

## 接口与所有者

生产者输出 `clock-world-content` schema 1 内容包和校验清单。当前协议及 Python 校验器在网页生产者中维护；游戏端保留其逐字副本，版本变更同时更新直接消费者。内容版本与协议版本独立。

直接消费者是开发期导入器、Godot `WorldContentCatalog`、普通房间的内容绑定，以及网页的下载入口。游戏在开发期导入后锁定内容字节和校验码，运行时读取本地文件。房间 schema 3 保持为真实几何和实例的摆放源；网页坐标只用于规划与地图。

共享文件由各端单一写者维护。网页持有世界连接、剧情、奖励和价格的设计定义；游戏持有房间文档、实例位置、物种／效果实现和运行存档。对同一个字段不再手工维护两份权威。

计划敌群只作候选预算。实际房间独立选择已登记物种和掉落档案、增减数量与摆放；差异只报告，不限制施工。生产者持久目录保留不再被候选组使用的档案，游戏更新也保留已施工文档。

## 接受、拒绝与取消

导入必须核对格式、schema、世界身份、文件大小、SHA256、重复身份和引用。验证成功后才替换当前锁；网络失败、损坏包和未知协议不改变原锁。同一包重复导入不产生新的内容身份。

尚未施工的房间和未绑定的对象可以作为设计目录读取；请求实例化时明确拒绝。普通房间通过显式引用使用内容，错误引用不得回退到默认怪物或默认价格。绑定的房间数据与内容包哈希共同构成保存版本。

网页旅程和游戏运行存档分别保存。导入内容不导入或重放玩家的网页动作。
