# 内容开发

按当前任务读取相关圣经和对象规范，先把受影响的设计正文整理完整，再修改实现、配置与素材。先验证一个有意义的样板，再决定推广；设计、实现、检查和任务交接在同一工作范围同步。

## 制作顺序

1. 明确玩家会观察、判断和操作什么，核合法构筑、真实场景、范围、预算与未决选择。
2. 整理现有对象／地区规范，写清行为、反制和视听效果；数值引用唯一配置，工程定位留在模块导航。
3. 用真实输入完成一组动作／攻防或一个完整场所，接身体、动画、声音、地形与奖励，核进入、退出和失败恢复。
4. 在正式镜头与实际消费者检查正常速度表现和连续体验，修复最严重缺口；成立后到第二种空间／组合验证复用。
5. 记录真实检查、独审与用户／设备范围，更新父任务交接，清理中间稿并保留必要原件。

## 专业与方法

从相关 `.agents/skills/*/SKILL.md` 选择专业方法。普通怪见 [完成标准](enemy_completion.md)，地区见 [关卡体验](level_design.md) 和 [地区审查](level_review.md)，独审见 [审查方法](review_method.md)，记录格式见 [质量说明](quality.md)。这些方法按任务影响选用，不使纯文档或小修复自动扩为完整内容生产。

## 手动创作工具

地区路由使用 `tools/level_design.py route`，视觉任务使用 `tools/visual_director.py route`；它们只生成计划。Bible 注册与当前方向位于 `docs/data/creative_direction/`，原始附件在 evidence，仅用于选择和来源核验。

实际执行协议见 [生产循环](production_loop.md)。全局任务只登记父议题，内部阶段、质量卡与恢复状态放其工作线；历史配方只作明确参考，不能提交当前执行器。
