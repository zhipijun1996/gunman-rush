# Codex 协作与交付

## 开始与恢复

新任务从最新 origin/main 建主题分支／工作树；接续任务先核原分支、未提交改动和依赖版本。按 [任务表](tasks.md) 找父议题，再读相关圣经、对象规范和 [模块导航](module_map.md)。管理与完成口径见 [项目管理](project_management.md)。

每条工作线只维护一份当前交接，记录目标与授权、分支／基线／SHA、写集、依赖、完成结果、检查与证据、阻塞和下一条可执行恢复动作。直接更新字段，不追加时间线，不复写任务表状态。沿用现有 scope 或 results；模板见 [交接](templates/cloud_workline.md)。

暂停前提交／推送可恢复工作，说明未提交项。另一会话先核代码、规范和证据身份；本机 build/ 产物只有具备持久来源才能复用。会话不会自动共享内存或接收后续反馈。

## 并行与验证

每个任务一个负责人；并行会话隔离分支、工作树和写集。共享文件由一个写者负责，其他会话交接口需求或可审阅修改。需要独审时提供冻结源码与实际证据。

共享接口/schema改动先在本任务交接列明生产者、全部直接消费者、接受/拒绝与取消语义、目标版本和集成检查，指定共享文件单写者。协议与必须同步的消费者一起合入；分步PR时先提供可运行的显式适配，不留默默采用旧默认值的中间状态。内容工作线引用已经约定的接口提交和数据版本，集成者在共同基线重跑跨系统流程，再扩展内容；并行素材制作可独立推进，但不能各写一份状态/条件权威。

固定世界先合入可证明等价的人工输入，再切权威/导出、房间装载/保存与真实闭环。具体依赖在任务表，场景协作者只读目标房和直接邻接；生成器不得覆盖他人手工场景。实现涉及系统边界、状态语义或内容身份时更新 [架构](architecture.md) 与对应规范，日常对象打磨只更新局部规范/实现。

按 [开发与审查](development.md) 选择记录和验证范围。普通任务不填质量卡；新内容重点验证美术统一与玩家体验。技术结果、专业判断、用户认可和设备观察分别记录，仅本任务明确需要的验收阻止其完成。

## 交付与清理

结果写明实际改动、检查覆盖、未验事项与恢复路径。任务结束把有效规则并入现行规范，清理临时审计／计划和重复交接，只保留现行功能必需的最小来源、许可和测试输入；临时日志、截图、录屏及报告进入被Git忽略的build/或构建产物。

录像交付按场景或连续时间段拆成可单独打开的小片段，默认约20秒、单段不超过3MB；提供分段观看入口，完整母版保留在构建产物中。用户不便观看大体积整段录像。

PR 面向 main，源码合入、试玩更新和商店发布分别按授权执行。试玩优先复用同源已验 Web 包，通过 deploy-prepared-playtest.yml 发布，`prepared_ref`绑定完整40位提交SHA（短SHA会被checkout当作分支／标签）；缺包或运行源变化时重建并执行相关检查。公开后核 build-info.json、PCK 身份和真实入口。

现有 prepared 工作流会替换整站；独立预览使用独立目标。构建、导出与部署方法按相关工程文档加载，不成为日常任务的固定上下文。
