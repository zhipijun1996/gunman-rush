# 项目管理

[任务表](tasks.md) 是当前进度的唯一可编辑来源，每个父议题一行，记录目标、依赖、状态及工作线入口。分组和下一动作表达现在需要谁做什么；已结束工作移出当前视图，历史由 Git／PR 及必要证据追溯。[当前状态](current_state.md) 只维护产品事实。

## 普通任务

修复、规则调整、工程和文档维护使用任务表一行与工作线一份当前交接。交接记录范围、基线／分支／SHA、写集、已完成结果、实际检查、阻塞和下一条恢复动作，不再复制任务状态。模板见 [当前交接](templates/cloud_workline.md)，跨会话规则见 [协作交付](cloud_production.md)。

进度使用 planned／ready／in_progress／review／blocked／done；等待决定、设备或他人操作写明具体原因和负责人。按本次约定交付与检查收口，不因其他内容尚未认可而长期停在 review。合并只证明代码合入，不能替未验项签通过；确需继续的验收保留具体后续事项。

## 内容与文档

新区域、新地图、新怪物等新内容按需记录 [内容审查](development.md)，重点是美术统一和玩家体验。质量卡不承担项目进度，不要求普通任务填卡；只填写适用检查与实际结果。

设计圣经规定方向，对象规范规定行为，运行配置维护具体数值。先按任务读取规范和真实消费者，先重整受影响的设计正文，再改实现和配置，同一任务交付。设计未决时用 design-grill 澄清，最终确认前不改正式文档。

长期规范保持完整最终稿，直接整合改动，删除被替代和重复内容。临时报告／计划在结束时清理，必要运行证据、来源与许可保留；旧原件不作为新的设计规则或当前通过结论。目录见 [文档索引](../README.md)。
