## 核心结论与原独审责任

这轮把“完善所有现有怪物”收窄成了“给现有图加同体运动，并录到基本事件链”。工程修复和可追溯录制确有产出，但没有建立并执行足以拦下参差成品的美术与动作准入。最早的偏移已写入`docs/worklines/enemy_all_02/spec.md:13`：盘点后直接预选“同体关节”作为全体方法；第29行的失败集又主要是重影、换形、撕裂、漂移、事件错误等技术缺陷。无这些缺陷，不代表动作设计或整体质量成立。

我自己的R1/R2提出了锚点、暂停、网格、灰盒身体及审核遮挡等具体问题，却在复审中围绕这些已知问题闭环，没有重新完成全体成品质检。R3首句“ACCEPT（可供用户逐怪审核的实现候选范围）”、R4“未发现新森林身体／恢复／死亡退步”虽附未验范围，仍给整体交付一个接受信号。**旧范围判断没有发现成品参差，不能充当E03–E05已达到用户目标的证据。** “用户最终审核未验”不能替专家先做正常速度、同屏、横向质量淘汰。我当时应把未执行的必需视觉／动作观察维持UNVERIFIED，而不是用宽泛候选ACCEPT包住它们。

保留旧报告能说明当时实际检查了什么；今后引用时须同时附本次用户拒绝与本补充说明。不能继续援引R3/R4为本轮成品质感背书。

## 二、规范本身不足或含混，需与用户讨论

1. **“允许程序动画”有原则，缺方法选择的质量否决例。** 现有标准不强制帧数是合理的；但缺乏可实际对照的“此状态只靠单图UV形变不足”的样板。需要从真实动作意图判断：轮廓变化、器官遮挡顺序、抬脚／换支撑、翼的前后翻转若要求新姿态，单图只能弯曲现有像素，不能自动提供缺失结构。程序动画可合格；选择程序法后仍须逐动作证明效果，不能默认全怪适用，也不能反向规定所有怪必须逐帧。
2. **“同母版”没有充分区分同一个体跨态一致与不同物种／Boss身份差异。** 同体连续性容易被做成复用一张图；旧Queen2×、Weave1×与Canopy共享queen图，是已记录的生产事实（boss-production-cards:13/23/25/26），不自动证明好或坏。规范需要明确新用途、实际像素密度、角色尺度、轮廓辨认、机制对应及材质档次如何比较；整数缩放和来源合法都不能直接准入。不能把“关闭灰盒”当成“成品美术达到同档”。
3. **黄金向批量扩产的用户里程碑不清。** 旧规范明确黄金先于推广，但没有“一切授权内黄金都必须先等用户确认”的统一硬要求。相反art-director:14及game-quality-gate:37允许内部专业准入后继续授权内验证，不能倒写为过去已有强制用户关口。本轮实际也没有本轮黄金单怪获用户确认的记录。是否在品质重建时改为“用户选定一只黄金整怪＋第二运动类型，再批量”，应列为待共同决定的改进，而不是宣布新冻结规则或要求用户批准每个小步骤。
4. **整体一致性缺直观、可否决的横向样本。** 原规范提风格／比例／材质，却未把“全体最低质量下限”落实成少量同尺度、同镜头、同速度的对照及明确淘汰理由。不同怪可有不同设计，最低一只不能靠其他精细怪抵消。这里需要讨论目标样板，不适合增加一个伪精确美术总分。
5. **ACCEPT范围容易淹没未验必需项。** 原四态和阶段已经够用，但候选交付的标题、制作卡、质量记录与独审之间缺统一的可见限制：某项技术接受后，用户看到的首先仍是“ACCEPT”。应讨论怎样让“素材待修／动作未审／整怪未过”直接可见，避免靠长篇尾注补救。不是另造一套状态机。
6. **技能篇幅累积、入口权威分散。** 同一skill同时有v5旧入口、当前registry绑定与多条历史补丁，现行任务又局部冻结source；读过技能不等于正确执行一条生产链。宜在讨论后压缩成当前工序、具体输入／实物输出和退出条件，历史放引用。更多守门文字或更多报表本身不提高成品质量。

## 三、自动验收代理指标怎样被误用

| 指标本来能证明什么 | 本轮不能据此推出什么 |
|---|---|
| HP accepted、state出现、恢复后仍活着、death/terminal事件、0coverage gaps | 只能证明驱动定义的事件被观察；不证明该状态身体真有对应动作，更不证明动作好读、好看。fan_sentry是直接反例。 |
| 网格顶点更新、UV连续、无非正三角、锚点误差小 | 证明部分几何健壮性；不证明解剖合理、步态承重、节奏与力感，也不能证明二维单母版适配全部姿态。 |
| 同一PNG／H3、source/bounds恒等、素材有SHA／许可记录 | 证明来源和身份的一部分；不证明静态H3适合中性live，或旧Boss放大后与新怪同档。身体“不换人”是下限之一。 |
| postdraw齐全、source_stable、精确commit、公开下载SHA一致 | 证明看的是哪份真实产物；无法证明该产物达到用户要求。追溯工作不能替艺术导演判断。 |
| 末尾210帧payload恒定、资源释放、暂停／epoch反例通过 | 证明终态持有与生命周期规则；不证明死亡演出设计到位，也不补签生前动作。 |
| R4 GPU44／0、15PNG空／非空、80路线540.378/600秒通过 | 证明相应裁剪谓词和专项预算回归；不证明逐像素前后相等、目标设备帧时或整体制作质量。R4已写明前者不是像素等价，今后仍不可扩大解释。 |
| 原音轨存在、PCM统计、音频事件唯一 | 不能代实际听感。|
| docs33、测试断言多、不同作者独审身份成立 | 证明结构／有限规则与独立身份；不证明评审执行完整，更不自动提供专业美术和动作判断。 |

自动工具应主动检出缺资料、漏分支、未调用、错误事件、几何与生命周期故障；对效果的必要判断仍要实际观看。工具全部绿时仍须允许专家拒绝，并具体说明哪里没有承重、读不出发力、不同身体质量档次或正式尺度失效。未发生这种判断时，应承认缺验，不能用“主观交给用户”完成交接。

## 待一起决定的最小议题（非新规）

先完成全资料素材与实际消费盘点，按“现用／被替换／孤立／候选／历史”、每条可见分支和实际尺度列事实；卡上的动作描述逐条回查到实物。再与用户讨论：以哪一只现有怪建立黄金整怪、哪些素材保留或重做、各动作适合哪种方法、什么实际片段足以否决，以及何时才值得扩到第二类和全体。

我建议优先把黄金的正常速度整段、静态同屏与必要帧对放在同一次讨论中，再确定批量机制。此处仅给议题，不继续改图、重写skills、冻结新门槛，也不以再录更多全量影片作为默认补救。用户尚未指出的每一只具体缺陷仍须从库存和实际画面独立发现，不能把本报告的几个例子当成全部问题清单。
