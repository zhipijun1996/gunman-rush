# ITEM-ART-01：独立道具图标与专用技能表现

日期：2026-10-28。分支 `feature/item-v5-catalog`；基线 `d9445c0e5d6516d4eb93ebbfbc5639efddf7fc04`。当前已完成72独立图标、32单帧语义资源及三套八帧家族的候选接入；最新专项1185／0、全72真实菜单534／0。最终冻结运行源56e639d7的33项受影响Harness全部fresh通过，主片54秒222断言、两区各12秒19／18断言，三段source_stable；用户／设备／完整G5仍未签。本文不修改地区圣经、全局像素方向或玩法数值。

用户当前明确指出道具复用图标、技能缺少专门美术，需要改进。该授权覆盖本轮美术制作；前轮“无新美术”是此前交付的范围，不限制本次。沿用已选 style-v5 的细粒度方向及当前 style-v16／creative-v19 技术绑定，不重新选择全局画风。规划采用 art-director、animation-vfx、game-quality-gate，与正在实施的 ITEM-AUTHOR-01 配置化工作配合。

## 现状与可观察目标

实际查看了上一源码的背包装备图和战斗视频抽帧，见 [权威与来源清单](authority-ledger.json)。P24 飞轮、P14 巡钟机等图标被通用枪管或线圈代替，不能只看图标辨认道具；实体与技能目前主要是圆、齿轮、细线和圆弧。

本轮目标是 72 件有效道具各有独立可辨剪影，并让真实可见的主动、召唤、弹体、标记、DOT、防御等效果拥有相应美术资源。纯属性道具只做合适的装备确认，不添加无意义常驻粒子。图标稀有度仍由菜单边框表达，资产不烘焙边框或等级数字。新道具可在数据中声明图标资源及表现 recipe，不在背包核心按 ID 逐件加分支。

[72 件逐项计划](coverage-plan.json)保留最初设计并附实际图集／region／绑定信息；映射不等于每件自然实战完成证明。每件有独立 `item.<ID>.icon`，不允许仅换颜色冒充不同图标；同类治疗、护盾等可共享时间轴基础，但必须保留来源身份和适合机制的造型。新增复杂机制仍由效果组件负责，表现 recipe 不执行伤害、资源或角色移动。

## 规格、材质与图标样板

旧图标真实来源为 `inventory_icons.png`，1774×887 原图、18 个非等格窗口；它们不是原生64px图标。当前正式网格 `icon_max_width=52`，详情图高90，ItemCard约100×90。因此“64逻辑像素”是本轮候选生产目标，不追认旧图为64原生。

新图标采用清楚的像素簇、厚薄受控的深轮廓、2–3级大明暗。暖旧黄铜、冷蓝灰钢、少量青绿能量和对应木/皮/晶体材质；主光左上，磨损集中在大边缘，禁止细碎噪声。与现有暖铜人物、深青UI和双区场景协调，不复制外部游戏形象。色觉之外由轮廓和负形辨认。

ItemPresentation在配置化修订后已技术重绑到style-v16／creative-v19；上一G0的style-v15清单原件保留于archive。新图按实际源图与消费者另行审查；任何SHA绑定均不继承用户艺术认可。

第一张样板先8件：B01磁盘、B03短枪管、B11木心匣、P24三孔飞轮、P14三机编队、G14电弧钟樽、G16裁决音叉、N01偏心摆锤。它们覆盖经济、武器、生命、投射、伴随、电弧、范围波和时间；在同屏中应无需名称区分。

[图标生成提示](golden-icon-prompt.txt)与[请求布局](golden-layout.json)定义4×2张1024×512候选板、每格256×256、32px透明安全边及64逻辑像素簇。请求坐标不是实际输出证据：返回后必须测真实尺寸、alpha主体和邻格污染，只有实测 region 可以登记到 AtlasTexture。不能把抗锯齿大图下采样后冒称原生64px；任何切片/采样/重建过程记入来源。若等格生成失败，保留原件，改为独立对象或实测非等格区域，不拉伸邻物来救布局。

## 专用 VFX 的三个黄金消费者

[P24 / P14 / G16 分镜与提示](vfx-golden.json)是本轮首批。实际播放时钟全部来自现有世界活动时间，暂停、失焦、死亡、卸装、切图沿原 owner/epoch 清理；不写新的技能冷却或伤害默认值。

| 消费者 | 专用资源与表现 | 正式触发与边界 |
| --- | --- | --- |
| P24 回环飞轮 | 原创三叶回旋铜刃、透明内孔、旋转帧、细薄带铜碎屑的双线尾迹、命中刀光 | `ItemV5Entity.kind=flywheel`，位置、方向、阶段和往返由 ActiveEffects 提供。尾迹停在真实实体路径上；命中刀光只能读真实HP提交结果，不因扫过目标框就播放 |
| P14 游钟机群 | 单机铜铃身、双侧短翼、轻微机械摆动、炮口花瓣闪光、细窄分段能束与单点接收火花 | `small_drone` 单体重复形成实际3机，不能用一张三机贴图代替三个实体。中心身躯36源px=18wu，含双翼全宽上限74源px=37wu（由radius9和1.7radius翼展推导），全高上限24wu；不能撑满64wu透明画布。`item_drone_fire` 是提交请求后的炮口/束反馈，尚不是HP成功；接收火花必须绑定策略提交回执 |
| G16 钟匠裁决 | 三齿裁决印、由紧到开的钟波边缘、断裂钟纹与短促目标接收印记，三段有相同家族但按 index 区分节奏 | `item_clock_pulse` 每段由现有0.18秒间隔触发，即使落空也有施放波；不能把它称为命中。目标印记需要真实伤害提交，不能由动画帧回调制造伤害 |

G0核查时G16 的 `item_clock_pulse` 不带 definition_id，且仅该技能发送此 cue。实现可为这个唯一事件配置显式 recipe，或仅补来源元数据；不得用猜测 ID 或全局 kind 自动吞其他效果。P14 的 `_fire` 在 `deal()` 接收排队请求后就发送 cue，所以炮口/发射与接收/命中必须分开。

活动技能的总范围不直接等于不透明贴图面积。G16 range280、P24当前视觉半径12、P14当前半径9及轨道参数都由运行配置/定义拥有；美术只能匹配，不改碰撞、半径、击中频率、攻击预算或角色位置来配图。世界光效保持低覆盖，主角、敌人预告、地面刺和下一落点优先。

## 实现接口建议

- UI资源以独立 `icon_key` 或 `icon_asset` 映射到已登记Texture/AtlasTexture；读取实际图集region和filter_clip。覆盖 ItemCard、网格、详情、奖励与商店，不能只改背包一个页面。旧非V5资源保留原图标路径。
- 资源定义独立于逻辑：图标目录/图集映射负责引用；表现recipe声明帧区域、锚点、方向、视觉尺寸、时钟、帧时长和淡出。ItemEffectView / ItemV5Entity 只读这些信息。
- 每个表现事件保留实例/定义来源、run/stage/actor/weapon/equipment revision和原回执身份。缓存图集不持有actor；长效资源卸装立即撤销，短效接收片不得跨场景误显。
- 绘制所有权唯一：资源接入后同一事件不能同时画旧圆弧和新贴图；保留明确开发回退仅用于缺资源错误诊断，不能把缺图静默当美术完成。
- 加载失败返回明确诊断。该道具玩法不能因此变成必需能力；绝不从动画通知扣共鸣、返能、造成伤害或启动角色移动。
- 素材逐项记录生成工具/可得模型信息、完整提示、参考SHA、原始PNG、处理命令、源与派生SHA、实际region/alpha/锚点、用途和授权来源。模型/许可不可得标 unknown，不补造商业许可。

## 黄金门槛与扩产顺序

1. G0：root/独立审查者核本规格、权威清单、实际消费者和预算；确认样板仅沿既有画风，不签新输出品质。此处没有要求用户重复批准已授权常规制作。
2. 第一轮8图标与3个代表VFX，返回即检查真实alpha、主体边界和安全边。透明底、深浅底实际采样；失败保留原图和原因。
3. 同源码正式1280×720和960×540菜单/战斗合屏。网格实际52px不看大原图自评；检查8图标错认、B01和P24环状轮廓、P14和G14金属装置轮廓，必要时改大形再加纹理。
4. 正常速度连续原生影片，实际道具获取/装备/施放、真实accepted-hit回执与逐帧视觉对应；分别验证空放、遮墙、单体/多目标、双向飞轮、三机叠加、三段钟波以及暂停/卸装/死亡/换图。带音轨不自动签听感。
5. 独立实际像素与连续动作审查后才扩72图标。建议批次：武器/移动、时间/能量、生命/防御、经济/伴机、主动/例外。各批使用已通过的家族与8件样板，而非再提出新全局画风。
6. 首批之外真实可见效果按语义补资源：飞雷钟樽/针雷/钟卫，标记/回响/雷丝/腐蚀，护盾/拦截/治疗，金币/返能；纯被动只加合适装备确认。每批更新72矩阵状态和正式消费者证据。

门槛依据是实际用途：0为透明底，32px gutter为当前256候选格的安全区，屏幕52px来自真实菜单，世界尺寸来自原定义。不得出图后降低alpha/遮挡/尺寸门槛追认。连续两轮同方向无实质改善停止该依赖并保留失败，其他独立家族可以继续。
