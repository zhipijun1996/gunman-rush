# 主角外观复用：本会话可沉淀的经验

适用：玩家要求复用现有玩法、制作更多角色外观。当前仍没有实际完成并验收第二个全动作角色，本文件不能证明批量稳定性或通用换装加载器已经实现。本次只将有反例支撑的经验补入现有player-creator、animation-vfx和原设计卡，不新增审批、验证平台或通用运行框架。

## 1. 明确允许“外观角色”成为目标

原player设计卡将“换皮/数值变化替代设计”作为通用失败条件，适合阻止声称新玩法却只换图的任务，但会错误拒绝用户明确要求的换马甲。现在先区分外观角色、玩法角色、两者；外观角色复用Motor/武器/输入/资源规则，不强制为每套衣服设计新能力。玩法改造仍沿原能力/武器/质量要求，不能借外观任务放宽规则。

交付约束并非只换一张PNG：角色ID/版本与来源、共用比例/调色板、实际帧表、脚底/肩/握持/枪口/接刀锚点、分层与当前接口绑定、缺失动作、正式消费者和证据都应明确。直接使用[更新后的原设计卡](../../templates/player_design.md#外观角色合同按需填写)和[动作覆盖卡](../../templates/player_action_coverage.md)，不再建第二份同义矩阵。

## 2. 一条真实连续黄金先于整套扩产

本会话[基线](checkpoint-01.md)实际看到Adapter停process但shot回调仍连、Courier卡recoil，且pixel分支真实由UnderworldPlayer绘制；三外观能在Home选中不代表能进入正式区域继续显示。已有M1还涉及权威枪口调整，是独立总控接口，不应悄悄算作无玩法影响的换衣。

先固定轮廓/比例和少量关键姿态，用实际Home/Plains主角完成转向/反向瞄准射击→受伤中断→恢复/死亡，再按角色补其余状态。围巾等附件加实际下落→落地链。每项写新作/复用/缺失，按动作需求安排帧数。本轮idle/fall各6帧和局部尘效有候选，但两版run原画失败、握持过渡未解决；因此不能以加帧数或素材合法覆盖这些失败。

证据：[motion交接](motion-handoff-02.md)、[高落差交接](feel-handoff-03.md)。黄金通过范围之外仍待验；现有的17消费者覆盖不得缩成一个Courier/ActionStudio helper。

## 3. 保留实际身体与锚点所有者

隐藏Courier仍供枪口等锚点，而实际pixel身体是UnderworldPlayer，Adapter处于禁用状态。查看节点存在不等于它真正绘制/推进状态；必须区分body、upper、weapon和附件。回旋V2首片虽有旋转刃，却落向过去的catch位置；跟随当前绘制手点并淡出后才完成本轮局部修正。它仍是当tick扫掠/伤害之后的视觉echo，不是新接刀身体动画，也不能反向改伤害时间。共享body/style变更继续先提交版本化影响并独审/显式重绑，不自刷旧SHA。

证据：[V2契约/返工](weapon-contract-06.md)、[V2最终手点与暗核原尺寸像素观察](../../evidence/PLAYER-PRESENTATION-01/weapon-v2/runtime-review.json)。

## 4. 音效先匹配语义，再看许可和格式

Freedoom的电台提示即使可合法使用，也不自动符合定时炸弹“滴滴”语义。后续实际改为Freesound电子timer公共HQMP3的一声85ms片段，固定音高，只由原age/fuse加速间隔。应提供单声与游戏短段旧/新对照；波形/频谱/音轨/AudioContext running不能代签听感。

开火、成功提交敌伤、普通固体接触、落空分开；持续音由原phase拥有，不能全局按cue名称静音。测试实际ready消费者的bank绑定；本轮服务跨Home/Plains复用，不能为凑预期假设每次切场景新建一个audio。首次/第二次绑定测试错误及修正后的实际859检查保留，不把它们归生产bug或静默覆盖。

证据：[滴声交接与公开素材](mine-beep-handoff-08.md)、[独立来源/重建/真实绑定审查](../../evidence/PLAYER-PRESENTATION-01/mine-beep-v3/engineering-review.json)。这是限域工程经验，仍未签用户听感/真机。

## 后续外观任务可直接使用的输入

> 基于当前已明确验收范围的主角母版制作外观角色〈角色ID/主题/参考〉。目标为换马甲，复用既有Motor、碰撞、输入、资源、能力、武器规则与授予；列清允许变化的服装、配色、剪影和附件。沿player-creator外观合同及原动作覆盖卡，先交实际Home/正式地区的一条带声连续黄金，再逐状态扩产；复用现有武器附件，记录实际全装备与技能兼容范围及缺失项。家园选择→地区采用→返回/切回旧角色必须实际验证；如共享入口或母版需调整，先交总控协调接口与版本化影响。不以helper、静图、帧数、来源许可或技术测试替代动作/听感/用户/真机认可。

“稳定输出”的下一步实证是按此合同完成一个独立新外观，确认其黄金、原武器姿势、选择流转和旧角色回退，再在第二个外观复用。此处没有承诺自动生成的图必然一致，也没有宣称新外观的全流程已通过。
