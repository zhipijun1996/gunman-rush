采用art-director，动作规格与animation-vfx共用本任务质量记录。风格权威是已选风铃平原V2 Bible及style-continuity v4；Visual Bible与art_quality_target的旧手绘/重起画风段落只作历史，不覆盖最新共享Underworld家族。本建议不要求换全局画风，也不改变AI、碰撞、伤害或奖励。

## 实际看过的内容与当前问题

实际用view_image打开：source_enemies.png整张、charger.png、aerial.png、人物run_sheet.png与states_sheet.png；用ffmpeg解码现有after.mp4的真实video n662、n970并打开。两帧只支持这些时点的合屏观察，未完整播放影片或听音。诊断帧在build/enemy-feedback-01/art-direction-v2/，不是新美术或动画交付。

- 原始敌人板已有上发条鸟、苔甲蛙、野猪形冲锋兽、铃腹飞虫、炮口守卫、根铃等差异，问题不是完全没有设计，而是它们几乎都用相近的深棕黑主体、暗苔绿覆盖与细金边。缩到当前30–40px上下的运行贴图后，内部材料与结构压成同一团暗色。
- charger的低重心、白牙/前刺是目前最清楚的识别点；背部苔藓和发条细节较碎，腿与腹部的暗形连在一起。它应先让人读到「重、低、向前顶撞」，再读到苔草与旧机械细节。
- aerial的大叶翼和铃腹在源图可辨，但翼面和身体都很暗，运行时更多读成一团轮廓及少量金边。它应先读到「双翼展开＋悬挂铃身」，再读到眼部镜片和铜件。
- 人物图集有明确分离的头部/帽檐、身体、四肢及独立姿态，多个状态确实改变身体像素与轮廓。UnderworldEnemy目前每物种只消费一张PNG，所谓运动主要是整图平移、缩放、翻向和flutter；这不满足用户的逐帧动画要求。
- 现有20秒反馈片是显式战斗夹具：视频n662/970里玩家仍是原Courier白帽身体，地面也是简化块面，不能称正式UnderworldPlayer＋正式平原地形的黄金合屏。其反馈比较成立，正式画风/色值比较还须在真实人物、地形、HUD与相机中验。

## 推荐方向：提亮材料面，拉开物种结构

保留家族共同的暗描边、上方受光、克制亮边、nearest像素簇和旧铜/草石材质语言。16px source tile /32wu是正式地形家族的尺度参考，不代表把所有角色强行压成16×16；人物和怪物仍按各自真实碰撞包络、源像素密度与脚底/身体锚校准。

建议把主要受光面画成足够大的中间调色块，让暗色主要留给轮廓、接缝、关节与背光面；不对整张图统一提曝光/饱和度，因为那会连背景、污渍、阴影一起抬高，也不能创造结构。

| 层次 | 建议用途 | 克制方式 |
| --- | --- | --- |
| 苔草/甲壳 | 明一些的鼠尾草绿、黄绿受光面，少量冷绿阴影 | 减少苔藓覆盖，让甲壳/腿分面显露；不是每个怪都披同一种绿色斑块。 |
| 铜件 | 中间调偏暖的旧铜主体，奶油黄窄亮边，接缝保暗 | 金属以边缘/平面转折表达，避免通体黑铜只剩一圈金线。 |
| 石/腹甲 | 偏暖的浅石灰色或灰米色，少量冷灰分面 | 与草绿和铜色有实际大面差异，不用密纹理模拟材质。 |
| 功能点色 | 镜片/核心用少量浅青或暖琥珀，与现有功能语义协调 | 不整身发光；危险预告和真实命中仍靠形状、动作及明暗共同区分。 |

同一灯光下先检查人物与怪物的主要受光面是否都有可读的中间调，而不是要求它们同色。可从草壳绿、旧铜、石灰腹甲三组开始做小样；这些是proposed调色思路，不是新全局palette或用户已选母版。

物种建议：地面保留低伏前重、明确头/前刺和可见支撑腿的冲锋剪影，以草壳/石腹的大面建立生态身份；空中强化双铜翼＋钟铃腹部＋中央镜片的组合，与Bible的铜翼巡铃机呼应。不能只改名字就宣称当前野猪图已变成草壳甲虫，也不能拿新增铃铛装饰替代真正不同的身体结构。

## 两个样板的逐帧动作卡（待资产制作）

所有关键运动都需要实际不同的身体像素/部件姿态。程序插值可用于姿态衔接和附加受击层，不能把同一图的缩放、旋转、位移或颜色变化登记成新动画帧。下面数量只是首轮制作的关键姿态建议，不是统一帧数门槛；最终以正常速度合屏判断节奏。

| 已有对象/状态 | 实际应画的关键变化 | 驱动与锚点要求 |
| --- | --- | --- |
| charger待机 | 2–3个有重心的呼吸/触角姿态，腿明确承重 | 身体脚底锚固定；不是整图上下浮。 |
| charger行走 | 6个左右腿交替的支撑/抬腿/伸展姿态，甲壳随步态轻反向摆 | 跟随真实Motor运动；停步能落回支撑姿态，脚底不滑动。 |
| charger转向 | 2–3个头部先转、前足换支撑、后身跟随的过渡 | 只读实际朝向变化；不增加AI转向延迟或把实体往回搬。 |
| charger预警 | 3个压低前身、前刺瞄向目标、后腿收紧的递进姿态 | 归一化映射现有telegraph_duration，保持原预警与判定时刻。 |
| charger冲锋 | 3–4个向前蹬伸/离地或短支撑变化，前刺和甲壳保持有力剪影 | 现有attack状态唯一决定运动；不凭动画新增冲撞窗口。 |
| charger恢复 | 3个前足刹停、身体回收、重心重新落稳的姿态 | 与现有recovery/blocked状态一致；速度归零时不继续假跑。 |
| charger受伤/死亡 | 受伤2–3个壳体错位/局部回弹；死亡4–5个失衡、腿收拢、落稳的姿态 | 接受的HP结果驱动；死亡优先、恢复死体静态终态；全部在父类现有可见窗口内，不改隐藏时钟。 |
| diver悬停/平移 | 悬停4–6个真正的翼上/下拍与铃腹滞后；平移2–3个前倾、翼幅不对称的姿态 | 世界轨迹仍由AI/Motor决定；身体中心稳定，翼尖变化不改变碰撞。 |
| diver转向/预警 | 转向2–3个侧倾/换翼支撑；预警3个翼收紧、镜片锁定、铃舌停顿姿态 | 转向读真实facing，预警读现有telegraph；不能提前表现已发起攻击。 |
| diver俯冲 | 3个收翼、头/镜片朝目标、尾翼跟随的姿态 | 跟随真实attack方向，保留现有攻击目标与速度。 |
| diver拉起/返航 | 3–4个张翼制动、铃腹滞后、恢复悬停的姿态 | 按实际recovery阶段和移动方向衔接，不把一张俯冲图倒放冒充返航。 |
| diver受伤/死亡 | 受伤翼拍失衡后恢复；死亡翼收拢、铃腹失去支撑，形成明确终态 | 只消费接受的HP；不新增实际坠落物理，终态/死亡反馈不重播。 |

切换验收必须覆盖走→预警→冲锋→恢复→转向、悬停→预警→俯冲→拉起→返航，以及各阶段受伤/致死、暂停恢复、重载和旧epoch。命中动画不能盖掉剩余攻击预告。跨帧必须稳定外包络、光向、材质、特征数量和脚底/中心锚，不能每帧换造型或抖动轮廓。

资产包应像人物一样包含可追溯图集和manifest：每帧state/index/rect/anchor/source SHA/时长或播放模式，附真实Godot绑定与状态转换。相同贴图多次登记、简单换色、程序扭曲或静态姿态拼接都不算完成。先两个样板做出完整运动链，再按同方法推广其他怪，未制作部分保持未完成。

## 受击与粒子的即时修订边界

root本轮可在既有样板内加强接受命中的身体短闪和粒子，不必等待全套新图。建议主闪用与人物/铜件共族的奶油亮色，突出短促起势再回原色；保留轮廓和alpha。粒子采用块状像素火星/材质碎片，允许更明显的数量、初速和散开范围，但仍有局部边界与短寿命，优先让弹道、预告和落点可见。

地面可以偏壳片/草屑，铜翼机可以偏铜屑与短火星；共享同一亮色核心、像素步长和淡出语言。现有接触火花有青色视觉，新的敌人粒子不应再叠上另一套大面积橙红雾/镜头闪烁。接触、拒绝与已接受HP反馈保持各自语义，不能因为看见火花就演已受伤。素材原色、正式音频和共享VFX仍由总控持有。

先做两对象的原尺寸静态合屏方向确认：真实Underworld人物、正式平原地形、两个怪和HUD同屏；看轮廓、材料明暗、辨识点，再画上表动作关键姿态并接一条完整运行链。只有程序受击变色/粒子改善，不等于满足本次美术与逐帧动画要求。当前静态美术保持用户拒绝状态；新配色、新轮廓、新动画帧均未制作、未验收。

## v4：活体亮材料、死体失去支撑（2026-10-22新反馈）

用户新要求是受击更大、更能区分活怪与尸体、参考《空洞骑士》的打击手感，以及怪物颜色仍太暗。本节只有只读审查与具体候选建议，不修改生产代码，不启动Godot；只追加本文，不代签新色稿或尸体已获认可。

### 再次实际看过的v3原件

打开现有charger.png/aerial.png；打开 `build/enemy-feedback-01/v3/review-final-v3/pixels/` 中两物种的before、actual-persistent-corpse；解码并打开 `docs/evidence/enemy_feedback_01/v3/final-movies/after.mp4` 的真实video n820（空中活体）及n1130（死亡后约2.7秒）。v3影片回执绑定 `bd8d130f3677ba80d569f16c05feee1977450c02`、1280×720/60fps、26.133秒、source_stable=true。未完整播放视频或听音；这不是新增实机运行。诊断图仅存build/enemy-feedback-01/art-direction-v4，不作最终美术。

当前不足比「尸体是否留下」更具体：

- 已有持久尸体确实留下，但仍是同张活体贴图。charger rest_angle约0.22rad（约13°），还能看到前冲、四足承重的原剪影；它更像一只斜着停住的活怪。
- diver rest_angle约0.96rad（约55°），但两翼仍张开、原眼点与金边仍亮；落地旋转解决了位置，不足以单独表达失去生命。在n1130尤其仍像一只侧停的飞虫。
- 活体本身的受光面仍以极细金边为主，主体深棕、苔绿的中间调不足。单纯把尸体再压暗只会让它融入地面，不能修正活怪与死体的辨识。

### 推荐的task-local配色起点

建议先把两对象做成**材料面亮、关节暗、眼芯亮**的活体；死体则**保持可见的材料中间调、眼芯熄灭、减少鲜亮边缘**。以下色值是两个样板的proposed调色起点，不是新全局palette、不是当前素材已有像素，也不是已制作资产。

| 材料角色 | 活体候选色 | 尸体候选处理 |
| --- | --- | --- |
| 共用轮廓/接缝 | 深灰绿 `#26342D`，保留完整外轮廓与关节缝 | 保留，避免再加粗成一团黑。 |
| 草甲主面 | 鼠尾草/黄绿中间调 `#8FA65C`；受光大面 `#C7D18D`；阴影 `#465A3B` | 主面偏灰橄榄 `#6F7753`，仍与轮廓分开，不整图压黑。 |
| 铜壳/铃腹 | 旧铜中间调 `#BD9457`；窄亮边 `#EAD498`；背光 `#69553A` | 主面偏旧灰铜 `#8D7D5A`；亮边减为 `#A8A085`，减少闪亮功能感。 |
| 石灰腹甲/前刺 | 灰米白 `#D9D7BA`，只保留几块清楚分面 | 保留材料识别，局部减鲜亮；不要死亡后仍像攻击预警的白光。 |
| 眼/镜片功能点 | 小范围浅青白 `#DBF1D2` 或现有功能色的同族浅色 | 熄成 `#4A5144`，去掉亮芯；依靠姿态和材料面仍能看清尸体。 |

实际做法应是对草甲、铜件、石腹、轮廓分别做task-local色表或显式材质mask，再按同一光向重画受光大面；不能把所有RGB乘1.5，也不应仅凭亮度阈值把黑轮廓、旧铜与苔绿混成同一亮色。眼点与金边很小，单做全图曝光很容易先爆这些亮点，而大主体仍缺结构。若仅作程序候选，也要显式保留轮廓、alpha和材料分区，并在真实人物/地形合屏验证；不是调整Gamma即可宣称美术完成。

### 尸体姿态必须承担主要辨识

| 对象 | 推荐最终尸体像素姿态 | 可先做的短期表现／边界 |
| --- | --- | --- |
| charger | 前足/后足明确收拢，腹部侧露或背壳着地，前刺失去向前顶撞姿态；形成低而不承重的静态外形 | 让现有侧翻幅度明显大于13°、停在不再四足支撑的姿态，配合熄眼/灰铜。旋转原图仍只是暂用表现，不能登记为重绘death frame。不能改Actor碰撞或实体位置来配图。 |
| diver | 翼片向一侧收拢或折叠，铃腹横卧，眼/镜片无亮芯；双翼不再保持飞行张力 | 现有落地/支撑流程保留，用task-local最终尸体图或只读死亡姿态层替代「张翼活图转55°」。暂时只转整图时明确标未完成，不能靠HP条消失替代死亡识别。 |

静止本身不是死亡姿态。验收时遮掉HP条和测试文字，先给同屏活体与落地尸体：即使都不移动，也应从支撑、翼张力、眼芯和外形立刻区分。再看暂停、恢复死体、镜头缩小和暗地面；这些判据优先于“尸体存在几秒”计数。

### 《空洞骑士》参考的可用边界

已查一手资料：[Team Cherry的Ari Gibson介绍](https://www.teamcherry.com.au/blog/introducing-hollow-knight)明确说明其简化、近单色和传统2D动画思路；[官方游戏页](https://www.hollowknight.com/)也明确强调手绘传统2D动画。可借鉴的是减少细碎信息后仍清楚的角色轮廓和真实动作姿态，把注意力集中在攻击结果；这些不是要求本项目复制其黑白虫形、轮廓线或素材。

本项目的建议是一次接受命中按「短促亮芯/身体强闪 → 有方向的大碎屑/反应姿态 → 很快回到可读的活体」分层，致死再接「失去支撑 → 落地 → 静态死体」。受击强度可以明显放大，但别让持续的大亮团遮住目标/预告，也别把受击闪色和尸体常态都做成同一颜色。身体闪白、碎片传播和轮廓反应应同拍，不能只在怪旁边播一团大粒子而怪本体仍无反应。

本次没有获得Team Cherry一手公开的具体hit-stop/震动时长参数；网络搜索中出现的反编译与二手分析数值不作为本项目参数权威，不照抄。全局顿帧、time_scale、额外击退、镜头震动和武器音效仍不由此美术建议扩入生产写集。
