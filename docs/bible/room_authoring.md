# 普通房间制作

普通房间由 TileSet、机关和怪物的实例组成。房间作者负责空间关系、入口、出口、视线、遭遇和失败恢复。共用装配器负责把数据转换为真实碰撞、机关节点和怪物。空房和通道按实际职责选择实例种类。

## 普通房间组装

1. 在新工程中编写 schema 3 房间文档。给出独立的 `room_id`、`bounds`，以 `room.standard` 为根，明确 `start_point` 和 `terrain_material`。从[组装夹具](../../production/tests/assembly_room.json)可看到最小可运行数据。
2. 用 `platform.solid`、单向平台或地形多边形确定碰撞；材质绘制消费同一几何。可用材质与接缝见[地形规范](terrain_materials.md)。
3. 从[机关库](../data/world_objects.md)取定义。实例写稳定 ID、定义 ID／版本与局部属性。连线写目标实例 ID 和输入输出名。同类机关可多次摆放。组合件创建时展开为可单独移动、配置和保存的子实例。
4. 给怪物出生点指定 `enemy.<物种>`、实例 ID 与位置。物种行为、受击、死亡和掉落由共享系统执行。需要新玩法时，先增加共用行为及定义，再在房间中引用。
5. 用 `OrdinaryRoomSession` 的 `document_path` 打开同一份数据。试玩用内存状态；显式提供持久化宿主后才读写对应存档。表现响应仲裁和提交结果，恢复既有状态时保持安静。

## 验收

在实际角色尺度和控制器下检查起点、地形接触、可见线索、射线遮挡、机关状态、敌人接敌、掉落以及失误后的重新尝试。一个验证用例是从门左侧击中铃，观察碰撞放开，穿门清怪并实际拾取。换摆放、断开连线、换材质和读回状态应有可解释的结果。正式房另验双向连接、连续镜头和首访／回访体验。

房间玩法可以复用反冲、能力协同、失败后的安全落点与场景可读性等方法。旧平原的房序、地图轮廓、指定房号、机关排布和数目只在[冻结版本](https://github.com/zhipijun1996/gunman-rush/blob/4f2bb5e41573e930603789c64b52a0c15a6a3dc4/docs/bible/room_authoring.md)中有效。
