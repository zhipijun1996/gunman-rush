# 普通房间制作

普通房间由 TileSet、机关和怪物的实例组成。房间作者负责空间关系、入口、出口、视线、遭遇和失败恢复。共用装配器负责把数据转换为真实碰撞、机关节点和怪物。空房和通道按实际职责选择实例种类。

## 布局与构图

设计新房或重做布局时，从同一个玩家视角推敲关卡和美术。先确定场所、本房职责及玩家应有的体验。选择玩家需要观察、作决定或辨认结果的位置，在已有房间简报或设计记录中把以下关系写在一起，详略由房间决定。

- 玩家在这里需要感知什么，何时应当注意到它？探索可以逐步揭示信息，舒缓空间也可以让人驻足。
- 关键地形在玩法上承担什么作用，在这个场所中是什么结构？按角色尺度和实际镜头安排空间、背景层次与可见轮廓，为重要信息保留辨识空间。
- 第一版用已有材质或简单色块，在可玩场景中搭出会影响判断的前后层和明暗。沿实际路线移动，检查所需线索在恰当时机出现、动作可执行、反馈可辨认。按问题调整构图或布局，改动碰撞后复验受影响的操作。再细化素材、灯光与环境运动。

房型、视角数量和表现手段由房间职责决定。简报是制作输入，schema 3 房间数据继续持有可运行的实例与参数。

## 普通房间组装

1. 在新工程中编写 schema 3 房间文档。给出独立的 `room_id`、`bounds`，以 `room.standard` 为根，明确 `start_point` 和 `terrain_material`，在 `root.properties.region_id` 写所属区域。从[组装夹具](../../production/tests/assembly_room.json)可看到最小可运行数据。
2. 用 `platform.solid`、单向平台或地形多边形确定碰撞；材质绘制消费同一几何。可用材质与接缝见[地形规范](terrain_materials.md)。
3. 按[基本库索引](../data/失序之钟_基本机关库.md#room-design)从房间职责、来向能力和玩家判断出发，再从[已接入机关](../data/world_objects.md)选件。需要可复用联动时查[预组合同](../data/失序之钟_预组与组合推荐.md)。调用 `WorldElementCatalog.instantiate_definition` 时传入房间的 `region_id`。公有机关的区域外观由库解析，拼装时可直接检视它与平台和背景的关系。实例写稳定 ID、定义 ID／版本与局部属性。连线写目标实例 ID 和输入输出名。同类机关可多次摆放。组合件创建时展开为可单独移动、配置和保存的子实例。
4. 给怪物出生点指定 `enemy.<物种>`、实例 ID 与位置。物种行为、受击、死亡和掉落由共享系统执行。需要新玩法时，先增加共用行为及定义，再在房间中引用。
5. 用 `OrdinaryRoomSession` 的 `document_path` 打开同一份数据。试玩用内存状态；显式提供持久化宿主后才读写对应存档。表现响应仲裁和提交结果，恢复既有状态时保持安静。

## 在 Godot 中放置机关

用项目指定的 Godot 打开 `production/project.godot`，在右侧选择「机关库」停靠面板，点击「打开房间 JSON」。面板读取房间的 `root.properties.region_id`。搜索审核编号、中文名或定义 ID，可以看到当前区域可用的基本件和预组。

1. 选择「放置机关或预组」，填稳定实例 ID 和房间坐标。基本件的矩形原点及预组的成员偏移相对这次放置原点；已经放在房间里的成员用房间坐标编辑。字段旁显示单位、模式约束和合法范围，点、矩形、成员列表与连线可以直接填 JSON。
2. 选择「校验并预览」。校验器使用正式房间装配入口，检查区域、字段、端口、分区、世界行动以及引用。预览显示将变动的实际实例、预组来源与派生结果，例如行程用时和稳定窗口。改参数后再次校验；通过后用「写入房间」保存。若另一位作者或外部工具先修改了文件，重新打开该房间，再预览本次改动。
3. 选择「编辑现有成员」调整已展开的单个实例。选择整个预组可以平移、复制或解除分组；复制会重接内部连线。外部引用映射按“旧外部实例 ID → 新外部实例 ID”填写，世界行动使用 `action:<旧行动 ID>` 作键。解除分组保留实际位置、参数和连线。
4. 打开引用该 JSON 的试玩场景，重新进入房间，用真实控制器走一遍改动的路线与失败恢复。

命令行可用 `bash tools/godot.sh --headless --path production --script res://scripts/list_mechanisms.gd -- <region_id>` 检索区域，或在 `--` 后传入 `--describe <definition_id>` 查看定义。[机关目录](../data/world_objects.md)

## 接入世界设计

使用网页世界内容时，按[内容通道](../data/world/content_channel.md)将稳定房号绑定到已施工文档，并用 `open_content(room_id)` 打开。`content_bindings.enemy_instances` 为各实际敌人引用 `species_id` 与 `drop_profile_id`；单只掉币从统一档案读取。

房间作者根据地形、镜头、战斗和动作节奏决定怪物组合、数量及位置，可以选择该房间候选组以外的已注册物种。网页敌群数量和总金币是规划估算，允许增减、换组或保留空房；`enemy_budget_review` 返回实际实例与候选预算的差异用于路线经济复核，不作为房间装载门槛。散币的规划锚点也是参考，实际位置应服务观察、绕路和失败恢复。

不要为了凑规划金币而塞怪。先完成可玩的房间，再按路线检查玩家自然取得的收入与商店目标；需要时调整掉币档案、散币与价格。导入内容不会覆盖已施工的房内几何和实例。

## 正式镜头

连续地形的门口位于来向画面的边缘。两侧以同一角色尺度对齐地面、井壁和远景参照；玩家越过边界截面时自动换房。室内正面门保留完整门洞和可站立的门前空间，玩家在门前按上交互进入。房门两侧分别定义通行截面、入口动作的起点和接收岸的落点。隐藏通道的发现只记录资格，玩家实际越过截面才换房。

跨场景时先收回操作并遮住画面，再重定位镜头、清除上一房的前瞻和瞬态输入。画面揭开时能看到角色从门内走进约一个身体宽度；从井口落下应对着下方的接收台，下方返入上层应有短跳和最近的可站立井肩。入场用角色运动和真实碰撞，落稳后才交还控制。持续按住的旧动作要先松开，再次输入才生效。

同一次越界只请求一次。接收岸须具备角色全身净空和实际支撑，房间身份、来向门和到访记录同次保存。接收或写入失败时，旧房恢复操作并说明原因；角色撤离触发处后才能重试。验收应从两侧分别接近同一扇门，观察最后一个离房镜头、第一段入场动作与交还操作的位置。

## 验收

在实际角色尺度和控制器下检查起点、地形接触、可见线索、射线遮挡、机关状态、敌人接敌、掉落以及失误后的重新尝试。一个验证用例是从门左侧击中铃，观察碰撞放开，穿门清怪并实际拾取。换摆放、断开连线、换材质和读回状态应有可解释的结果。正式房另验双向连接、连续镜头和首访／回访体验。

房间玩法可以复用反冲、能力协同、失败后的安全落点与场景可读性等方法。旧平原的房序、地图轮廓、指定房号、机关排布和数目只在[冻结版本](https://github.com/zhipijun1996/gunman-rush/blob/4f2bb5e41573e930603789c64b52a0c15a6a3dc4/docs/bible/room_authoring.md)中有效。
