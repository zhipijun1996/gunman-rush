# 关卡要素与可交互元素

主游戏持有行为类型、要素定义和组合定义；房间JSON持有实例，编辑器消费同源目录。定义、实例化、关联、状态和表现共用合同，不要求所有要素采用同一种绘制或物理节点。

## 分类与文档归属

统一注册目录是房间实例化入口；机关库只是其中一个业务分类。每个定义声明 `library`（业务归属）、`category`（库内编辑分组）和 `documentation`（已有权威正文）。目录索引的 `libraries` 提供分类名称与导航入口，编辑器直接消费，不建立第二份分类清单。

| 分类 | 范围 | 说明入口 |
| --- | --- | --- |
| 地形与静态结构 | 固定实体／单向平台、墙面、建筑碰撞及静态组合 | [地形与材质](terrain_materials.md) |
| 可交互元素（机关） | 风铃、开关、门、移动平台、危险、索点与恢复交互 | [机关库](../data/world_objects.md) |
| 美术表现 | 纯贴图、布景、建筑饰面和状态驱动的视觉表现 | [场景美术表现](../data/world_presentation.md) |
| 怪物与遭遇 | 怪物出生实例、波次和Boss遭遇宿主 | [已有怪物与Boss文档](../data/README.md)；定义指向对应物种／Boss正文 |
| NPC与剧情 | 人物放置、教学与剧情宿主 | [剧情](story.md) |
| 奖励 | 奖励宿主及权益引用 | [奖励与成长](rewards_and_builds.md) |
| 内部组装服务 | 房间根、组装与内部战场组件，不可直接放置 | [架构](../project/architecture.md) |

纯贴图不进入机关库；怪物沿现有怪物文档、Definition和行为系统管理，出生实例只是房间引用。组合可以引用不同分类的成员，归属由组合的主要用途决定，成员保留原职责。静态建筑碰撞属于地形，表面饰图属于表现；可破坏或可控制建筑的状态行为属于机关。分类不改变稳定ID、放置／复制／删除、参数校验及共享装载流程，也不授予原本没有的信号端口或持久状态。

## 房间组装

普通房间由空间／出口／镜头配置、对象实例、参数和稳定ID关系构成。房间根节点只编排服务及生命周期，实际碰撞、危险、交互和表现由注册组件或批量适配器产生；地形批量绘制，不逐格创建节点。怪物、装备、奖励继续委托各自系统；NPC、Boss、教学和特殊剧情通过登记宿主接入，不在普通房间增加专属玩法脚本。编辑器只有一个分类放置入口，内部技术组件不可直接放置。

## 定义与实例

行为类型登记实现、参数、输入输出、状态版本与生命周期。要素定义选择行为、默认参数、可用外观与编辑描述；组合定义声明子要素、局部坐标和内部连接。房间实例持有稳定ID、定义引用、参数覆盖、外观及外部连接。已有行为换皮或组合不修改房间脚本；新玩法登记行为及相应验证。

装载按校验、创建、解析稳定引用、连接、恢复、启用的顺序完成。失败清理临时对象，不运行半套机关。正式游戏与预览共享此入口。组合子实例由根实例ID和稳定局部ID标识；复制重映射内部引用，外部连接显式保留，删除被引用对象须同时处理关联。定义版本变化显式迁移，不能悄然改变旧房。

## 信号、控制与状态

可交互元素简称机关，包含发送者、接收者及兼具两者的元素。风铃、开关发送带输出名称与类型的信号，通过显式连接中的稳定目标实例ID送达；接收者按自己的输入契约改变状态。触发器提交意图，正式状态所有者接受后驱动目标。目标只开放登记的输入；一源多目标统一校验和提交；同一输出只向同一目标写入一次，禁止即时循环。目标ID在当前房间内解析；跨房资格继续交由世界事实／action所有者处理，不向未装载节点发消息。延时、顺序等新行为必须由登记组件表达，不在房间JSON执行脚本。运行时引用使用稳定ID，不依赖数组下标、节点路径或实例地址。

可持久化机关行为声明状态版本。当前机关实例支持永久（离房／读档保持）和尝试（离房重置）两种状态范围，同一信号链必须一致；周期权益继续由世界状态所有者管理，瞬态资格不保存。世界状态系统保存和恢复同修订快照，表现只消费已接受结果。保存失败不提前开门或播放成功反馈；暂停不推进运动；卸载取消未接受请求。存档使用统一类型、版本与状态包；旧存档不兼容，未知或过期格式明确拒绝。旧房间源数据仍迁入新规范。

受击破坏地形、伸缩刺、风场、弹跳蘑菇及浮石分别通过受击、定时、接触和运动行为扩展；共享创建、信号、状态、保存和编辑接口，不强制继承风铃行为。可攻击隐藏入口由实体几何和可破坏状态拥有碰撞，tile外观消费同一几何；破坏、伸缩和场域启停属于玩法状态，不能只隐藏贴图。未实现行为不得登记为可用素材或可放置元素。

## 平台、危险与组合件

实体岩土、砌体平台复用[地形与材质](terrain_materials.md)的47邻接及精确边界。木梁、钢梁和栈道使用端头／中段构件。承载方式与画法分开：静态实体、静态单向、移动实体和移动单向共享尺寸、锚点与外观约定，各自保留正式物理。移动平台不参与静态实体并集。

普通表面不自动产生伤害。危险定义拥有方向、伤害区域和行为；外观拥有单段／首中尾、适用方向、根部及尺寸约束。选择顺序为实例指定、区域与宿主材质匹配、明确兼容默认；没有兼容资源则拒绝并提示缺件。不同区域允许尖石、荆棘、金属刺等不同表现，换皮不改变伤害；减速或中毒必须另选相应行为。宿主改形、移动或删除须同步处理附着关系，不能留下无伤害刺图或悬空危险。

建筑组合件分别声明实体、单向楼板、门位、装饰和附着锚点。图片透明度不生成碰撞，背景不伪装落脚面；世界附着物和独立视差背景身份不同。美术与合屏标准归[Visual Bible](visual_bible.md)。

## 制作与验证

唯一注册索引为 `config/world_elements/index.json`，行为合同与每种对象定义分别存入独立文件；房间和编辑器不另维护注册清单。具体机关库的唯一说明入口是[世界对象](../data/world_objects.md)，只描述机关及配置来源，其余要素的文档由定义指向所属系统。新增机关行为登记脚本、`fields`、`inputs`／`outputs`、`state_version`／`state`；注册脚本实现 `element_bind`、`element_state`、`element_restore`，接收者额外实现纯校验 `element_can_receive` 和纯提案 `element_propose`。发送者提供 `can_commit`、`proposed_state`、`element_signal`、`accept_committed`、`cancel_pending`，向App提交自身ID，不直接操作接收者。信号负载支持bool、number、string、point和pulse，按已登记端口类型校验。恢复不重新发信号或播放触发反馈。

要素定义由 `component`、`version`、`defaults` 与 `position_field` 构成；放置工厂展开默认参数后生成完整实例。组合的 `members` 用固定局部ID、定义、offset和覆盖参数构成，内部 `links` 引用局部ID。组合实例保留 `assembly_id`，成员仍是独立真实要素。旧Demo与旧手机工作台入口退役；仍被主游戏消费的基础能力归共用模块，正式运行时不接受旧房间／草稿协议，存档没有旧格式转换。NPC、奖励和永久门锁继续复用各自世界事实所有者，不另造机关进度账本。

先以真实拼装验证地形过渡、四向危险、四类平台、触发与控制及建筑组合，再迁移旧房。目录参数、实例创建、复制／删除／撤销、当前schema3完整往返、存档恢复与取消都须验证。视觉逐房检查真实承载面、危险边界、机关反馈和镜头运动；自动测试不能代替视觉检查。
