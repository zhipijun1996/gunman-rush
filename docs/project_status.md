## 尚未完成或尚未认可

- 只实现平原两张地图；Boss后的大能力选择、森林及后续地区没有正式消费者，不开放，不宣称全游戏胜利。
- 完整真人两图/Boss通关、主观趣味与画风、Android/iPhone触控与性能、实体手柄和Windows实机仍待验。构建成功不能关闭这些项。
- 源图/图标有效、素材接入和关键姿态存在，不等于动画衔接流畅或最终合屏精美。需要连续录像、手机尺度和用户评价。
- 生成时主要检查图结构、内容能力资格和确定性重建；真实Motor路线来自独立测试，不是在每次出图时对所有可能操作搜索证明。
- 旧规格和历史任务很多。执行者应先读本索引、最新 AGENTS 顶部规则与交接，再进入专项文档；不能把旧八关、旧精力未定、旧Boss可退场恢复为正式规则。

## 后续顺序

1. **建立体验基线**：同一运行版本录制正式入口、教学、典型往返路线和两个Boss；记录玩家卡点、误读、疲劳、镜头、资源压力。为美术、动画和手感分别建缺陷，不以新增数量抵消旧问题。
2. **做一个完整体验样板**：选一段同时含真实动作、敌人/机关、背景、角色、音效、UI的正式路线，完成统一材质、轮廓、动作过渡与读图验证，再扩展全地图。
3. **改善生成节奏**：先测早到Boss、探索成长、拿高难宝箱再撤离的实际流程；按动作/压力签名统计重复。跨图去重、学习进度与恢复段导演另建任务，不从当前局部历史推断已完成。
4. **关闭设备问题**：按既有 A16 的60fps/20分钟标准和真实输入契约分别验收；记录设备、分辨率、p95帧时、加载和内存，不凭PC浏览器推断手机。
5. **再推进后续地区**：明确大能力授予/保留规则，完成首区体验和依赖后再扩内容。既有授权内的独立修复可继续，不把待真人验收误解为禁止开发。

后续任务采用 [开发质量流程](development_quality.md) 和 [任务模板](templates/development_task.md)，任务状态仍统一记录在 [tasks](tasks.md)，验收证据仍归 [acceptance_tests](acceptance_tests.md)。
