# ENEMY-FEEDBACK-01 · Skills改进提案与怪物制作卡

状态：任务专属建议，2026-10-23；没有修改共享skills，也未验证为批量生产能力。依据[本会话累计结果](enemy_feedback_01_session_summary.md)、[v8独审](evidence/enemy_feedback_01/v8/review.md)、[帧／尸体合同](enemy_feedback_01_frames.md)。继续使用原G0–G5、十一维和已有模板，不增加另一套质量体系。

目标是让后续输出更可预期：在扩产前发现身体身份、动作过渡、材质、生命周期和正式接入问题。技能不能保证一次生成就通过审美，真正的稳定性来自有界样板、可复现失败和明确的退出条件。

## 一种怪物的制作卡

复制到该怪物的既有[Enemy Design Sheet](templates/enemy_design.md)和[动画卡](templates/animation_vfx_specification.md)，以同一task_id／content_version维护；以下是补充字段，不是新登记系统。只做表现时保留原机制与Definition来源，新怪物才填写新的玩家决策及机制对照。

### 身份与正式消费者

- 稳定物种ID／地区／战斗职责／运动方式；与现有怪物的可见、可玩差异。
- 地区Bible、实际玩家与怪物参考路径／完整SHA；哪个母版已接受，哪些仍是候选。
- Definition／Actor／AI／Motor／Health／表现安装器／正式场景或生成池路径；**每条实际继承与替换分支各列一行**。
- 写集、共享资源所有者；伤害／声音／掉落／save各由谁结算。缺接口写具体请求，优先解决会决定尸体实现的保存合同。

### 身体与材质

- 同物种统一的neutral／live参考：正侧面／朝向、头身比、肢体／翼数、外轮廓、功能色与明暗重心；带真实玩家和背景的原尺寸合屏。
- 读取原消费者的实际显示尺寸／比例／bob和材质，注明旧图是深色材质输入还是已上色成品。新图不得盲目再套提色或去掉原映射。
- 帧裁区、透明阈值及比较符、clip固定比例、脚／中心／受击点／附件锚、视觉包络与碰撞包络分列；死体实际接触点与saved Actor脚点分列。
- Atlas shader使用的UV域、纹理切回和epoch初始化重置项；原图字节、import设置、manifest版本有据可查。
- 来源文件随资产保存，并接入原 `docs/quality/asset_records` 登记；动态加载目录要有检查器可审计的真实有限消费者，按实际PR基线跑 `check_quality_diff.py`。本会话存在这两类失败，不能把生成器provenance当成自动完成登记。

### 动作与过渡

| 状态族 | 该物种的可见动作／关键姿态 | 转换／中断需要实看什么 |
|---|---|---|
| 待机／移动／转向 | 呼吸或摆动、步态／拍翼、转身轮廓；不用整体缩放冒充所有帧 | 同速运动中方向变化、脚滑／附件脱离；保留物种自己的动作节奏 |
| 预警／攻击／恢复 | 可见蓄势、真实攻击姿态、收势；事件来自原AI／判定时间 | 预警是否明确；受伤中断、攻击结束是否回到当前正确动作相位 |
| 受伤 | 接触、身体反应、余势与恢复，按体材／运动差异配置 | live→hurt与hurt→live；连续命中、致死打断；不能只看中间最漂亮一帧 |
| 死亡／尸体 | 真实失力、关节收拢／倒地、灭眼／低姿态，和活体可辨 | 空中到支撑接触、D1→末帧、支撑移除／移动、暂停／卸载／死档恢复 |

不适用状态说明原因；局部任务未制作的运动帧明确未完成，不用默认recoil、整图翻转或姿态数代签。动画帧数与时长由物种动作和真实时间轴决定。

### 命中、声音与生命周期

- 真实弹体／正式接受回执是音画的因果入口；落空、碰撞但被拒、同event重复、旧epoch、terminal重复各有反例。
- 身体flash、方向接触、材质微屑分层；在实际战斗距离和背景上检查，强化后仍看得清怪物、弹道、落点与预告。粒子更大不等于覆盖更久／占满画面。
- 怪物受伤／死亡声对应身体材质；开火声归角色当前装备／武器所有者。先做短的实战A/B试听再接入，记录谁触发一次、谁节流、谁清理；不能以波形峰值或有音轨声明音色好听。
- 如留尸，开工前明确父节点何时隐藏／释放、尸体由谁持有、stage与epoch清理、实际落尸位置／支撑本地关系如何进正式save。恢复死体直接静态末帧、零演出／零重复掉落。
- 正常时钟验证音频池；离线fixed-fps影片不替代墙钟播放释放，不能为录制放宽voice预算。

### 本物种的验收出口

1. Development先一个完整真实消费者切片：正常速度连续输入，实际非致死命中、恢复、致死、落尸；需要操作评价再交独立Preview。
2. 同条件对照绑定Seed、输入、镜头、武器、Definition、源SHA；分别列实际HP接受事件、演出帧与音轨。局部fixture明确标记，后续正式自然消费者另验。
3. 在原G4做独立审查，逐条关闭进入／退出／中断的具体反例；技术、艺术、听感、用户手感、真机分列。没有新看像素就不签视觉复验。
4. 黄金样板接受后，再选体型或运动方式不同的第二物种验证共享配置与特殊分支；共享事件／生命周期协议，保留各自轮廓、材质和节拍。未接受家族不批量扩产。
5. Integration覆盖受影响完整系统与正式消费者，最终完整适用Release。Development通过不等于可以合main；连续两轮无实质艺术改善沿原停止／返工边界执行。

## 可复制的后续开工Prompt

> 使用enemy-creator、art-director、animation-vfx和game-quality-gate，在同一任务记录中设计／制作【地区／物种】。先读地区Bible与实际玩家、现有怪物母版，盘点正式Definition、伤害／死亡／掉落／音频／save和所有表现安装分支，列明确写集。先给玩家新增判断、与现有怪物的差异和制作成本；纯表现改造保留旧机制并说明。先完成一个物种的统一live身体母版与动作／过渡卡，再在真实正式消费者用实际输入／弹体验证移动→受伤→恢复、致死→落地→尸体、暂停／epoch／重载。每个运动和攻击状态有适合其身体的实际动作帧，帧数不统一硬定。保留轮廓、材质、脚／附件锚与动作节奏；先检查正常速度进入／退出／中断，再逐帧定位，不能用更多粒子掩盖动画问题。留尸前明确正式save与支撑所有权，枪声由角色装备管理，怪物音效先实战试听。保存逐字prompt、参考／源SHA及工具回包元数据。先交一个10–30秒真实片和未完成项，独审通过后再选第二运动类型验证复用；需要手感操作时交独立Preview，未经验证不批量推广。Development先专项，合入前原完整受影响系统、正式消费者与Release门槛保持。

若【地区／物种】尚未决定，可先按生态与玩家操作缺口比较少量机制候选；不要先固定要产多少怪物。已选画风和Bible不重新开放选择，也不承诺“套模板即可稳定出精品”。
