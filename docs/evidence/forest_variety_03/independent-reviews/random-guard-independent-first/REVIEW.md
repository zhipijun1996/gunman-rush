# 随机实体 guard 独立审查

结论：**限定接受新 guard 的反 metadata 口径**。只读检查生产 runner 源码，并在 round11 的20个原实际 JSON 上独立离线复算/构造反例；没有启动引擎，不冒充新源 native 收据。所读源码快照与 SHA 在本目录。

`shape_signature()` 仅读取 float规范化后的 rect四坐标 + one_way，以unique、排序后编码；不读取ID、instance、动作程序或原数组顺序。`anchor_signature()` 仅用真实目标坐标，同样unique排序。ID重命名、program替换、顺序反转、重复描述不会让这两种实体签名改变。独立克隆20个样本实际执行上述反例全部不变；真实移动一个支撑1wu才改变支撑签名。

当前20个原样本重新复算新增平台矩形/oneway布置每map均只有 **1** 种，新增目标坐标每map **2** 种。因此新硬断言应真实产生 **2项失败**（两map各1），这是尚未做到随机地形变化的实质问题，不追改原round11六条native通行证据。目标变化/奖励口变化可保留独立计数，不能覆盖平台布置未变。

production反例中 anchor 那一项标签写ID/order/duplicates，但当时源码只实际修改了order/duplicates；函数本身不读ID，故不是逻辑阻断，建议让反例动作与标签一致。检查未加入普通full/CI去制造无关主线红，也未改生产几何凑第二种。

边界：此计数仍是“新增矩形支撑布置”，不是轮廓union、不是新机制、不是整体拓扑或有趣随机完成。1wu变化或把同一长平台拆成两矩形都可能改变表示，因此通过>1只是一条最低必要约束。当前不建议继续增加复杂union流程救指标；后继必须通过真实空间决策、不同出口目的地、奖励/恢复以及正常画面判断新增模块价值。不得把新hash/count复用为用户FUN验收。
