## 为什么以前持续失败

PR89 已将有限尺寸、美术家族、肩部和留白预算前移，但其[真实失败](../plains_art_language/independent-review.md)表明：参数提前不等于拥有能画出体积的消费者。旧画源与坐标合同可以严格一致，依然无法补出源画没有的转肩、侧壁和根脚。兼容任意旧几何进一步迫使同一材质承担不同体量，画尺和笔触发生变化。

本轮用两次真实失败验证了这个问题，而非仅靠推测：

| 实际方法 | 实机结果 | 对应生产层 |
| --- | --- | --- |
| v1 `e76e5c24` 完整体积＋按实体宽高归一UV | 根须变长、肩缘被切、连续体积仍像贴皮；首次驾驶短跳也失败 | 绘画映射与测试输入策略分别有错 |
| v2 `5871a02b` 固定画尺＋边界反求UV | 下溪反冲往返成功，但竖缝、拖色和镜像地层仍显著，独审RETHINK | 消费者改变了画源内部形体关系；增加纹理无效 |
| v3 源绘画构造先行，直接等比呈现 | 圆肩、岩层、草根完整保留；实际碰撞、可信接触线与画源共用frame | 制作对象改变，源画与可玩空间联合设计 |

v1/v2 的源码、原始报告与独审保留在 Git 和 [records](records/index.json)。没有为了新消费者删除原物理负例；退役网格专属断言保存冻结版本，v3 验实际Sprite变换、画源SHA、源接触、真实碰撞、角色层级和拒绝反例，原模块1310项保持原件。

## 真正发生改变的制作动作

1. 从一段开敞草岸—裂隙—溪床世界截面出发，画完整可承重的顶面、转肩、侧壁与根须。源图是地貌实体，不含角色、HUD或整屏场景。
2. 在原图坐标标定可信可站线和语义轮廓；画幅、比例、方向、源SHA构成 `paint_frame`。不将每片草叶做碰撞，也不把任意多边形反投影回图像。
3. [生成器](../../../game/world/generation/plains_world_rebuild.gd)从同frame变换出实体、站面、路线、出生点、敌人和树棚依附；[前景消费者](../../../game/presentation/world/art/plains_world_rebuild_composer.gd)直接呈现完整源图，[舞台](../../../game/world/levels/providers/plains_world_rebuild_stage.gd)安装实际多边形与原敌人。无法匹配已登记源构造的尺寸、源、变换、接触或碰撞必须拒绝。
4. 先真实输入试操作，再正常镜头拍片。连续两轮绘画映射不成立后换方法，没有用更长缺陷清单继续原映射。v3还真实修复了斜坡出生全脚宽安全、源图后绘吞角色和未接延展口进入正常镜头的问题；各失败帧保留。
5. 首构造内部准入后，保持四张主要画源及尺度不变，改变东岸相对位置与高差、拓宽溪床，把上跨路线改为下溪—行走—反冲攀岸，再实际去返验证与独审。

## 有限复用证明与边界

两布局都消费 `terrain_cliff_v2.png`、`terrain_east_v3.png`、`creek_bed_v3.png`、`environment_source.png`。没有为第二布局生成图片，也没有烘焙整屏。第二布局东西岸高差增加120、主开口增大，真实路线与视觉负空间均发生改变；不是整图平移或镜像。四源SHA和源框架见原生实际收据，首构造保留比对见 [原样压缩的首构造比对](records/raw/first_layout_preservation.json.gz)。

当前合法目录只有variant0/1，Seed记录身份，不改变结构。**这不证明任意随机地形、跨屏连续延展或完整风铃平原生产已经解决。** 外侧延展口尚未被另一实体真实消费；正常相机仅覆盖实际加载域，不将空接口展示为完成世界。下一个关键实验应只消费一个真实外侧截面，验证笔触/地层/接触延续与往返；若失败应改连接语法或画正确接头，而非扩更多Seed。

背景目前是独立画源的远景、树与钟棚加空气层，非完整区域级景深协调或真实多层视差求解。HUD与角色沿用实际系统，尚未做完整风格重构。两局部获得的是值得保留的制作范例，商业品质、用户偏好、完整探索生态仍需另外验证。

## 测试与真实成本

最终同源 `ba787df7`：首布局原生124项、第二布局138项、原模块1310项通过；两布局均通过真实PlayerMotor操作。首片17.2秒/1032帧/60fps，1003tick、9点、3次接受射击；第二片22.9667秒/1378帧/60fps，1347tick、11点、9次接受射击；两片最低/最终HP5。严格退出与源前后指纹保留，不等于全部CI通过。

图生实际5次，当前消费4张，另1张历史失败源保留。模型名称、计价与商用许可没有工具证实，不估算金额。本轮原始阶段耗时来自各report而非主观效率分数：首最终电影采集/编码104.26秒，第二137.70秒；最终原生约11.95/12.14秒，原1310约6.35秒。固定60fps影片编码比游戏时间长，不能当设备帧率基准；所有运行与失败的详细时间见records索引。

电影编码音轨为48k双声道，审查实际看正常帧与战斗抽帧，没有完整播放听音或真人/手机/手柄测试。没有执行无关全量CI/Web发布。候选Linux包单独验证当前PCK字节、空cwd启动、完整实际消费者snapshot和严格退出，见[交付](delivery/README.md)，不以旧包代签。
