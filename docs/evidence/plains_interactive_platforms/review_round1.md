# D081 第一轮独立严格审查：当前实现与可执行设计

审查者：独立只读代理 d081_strict_review1。审查范围：AGENTS.md、D080 实现与交接、PlatformingModule / PlainsTerrainSkin、ShotLatch / GeneratedShotLatchEncounter / PlainsShotLatchPlanner、ModuleMovingPlatform、WindkeeperEncounter / WindkeeperArena / WindkeeperDamageable / WindkeeperPresentation / WindkeeperHud、现有 Boss 与荆棘模块资源。未修改运行代码、测试、参数、资源或发布；本报告是唯一写入。

结论：**以 D081 新要求审查，当前 D080 实现不通过。** 历史回归通过不构成本轮通过。本报告为源码审查与设计建议，未执行真实运动验证，不能作为可玩证明。

## 一、目前已经存在什么，缺口是什么

1. **荆棘已有 AI 根床，但并非附着地形的玩法数据。** PlatformingModule._draw_spikes 调用 draw_rooted_bramble，根床仅在危险条底部或与实心地形相交区域画装饰；definition.danger_bounds 仍是独立矩形。plains_thorn_bridge 两岸为 x=0..100 与 230..340、y=300，危险位于 x=100..230、y=340..370，下面并没有承载平台。仅换贴图无法表达“五格平台左两格危险”及墙面危险。
2. **牧风者一阶段可以从地面向斜上击颈铃，但缺少明确视觉教学；二阶段确实限制上侧；三阶段完全没有上侧限制。** accepts_core_direction 只检查 storm_profile 且 stage_phase==2。第三阶段 final_hold 在最后桥墩永久重复 pier_warning → pier_impact → pier_open，容易退化为在最后一个位置站定输出。三阶段动作不同，不等于三阶段越来越要求平台跳跃。
3. **仅给第三阶段加一个宽上侧锥仍不充分。** 基础弹速 1200、寿命 2 秒，整个 Boss 场地宽 1120。原 upper_core_dot=0.18 允许很浅的向下射线，固定高处可能覆盖多个铃位。应以普通玩家输入验证固定站位反例，而非仅检查 direction predicate。
4. **正式远端风铃门没有完整配对信息。** ShotLatch._draw 在 formal_presentation 时隐藏门端 link_id 和连线；GeneratedShotLatchEncounter 直接把 link_id 设为空。颜色可以辅助，但不能只靠颜色把多个同色铃和门配对。return_side_only 依靠开火时来源位置并用真实弹体接收，应保留。
5. **现有 ferry_bell 是“从船上射门”，不是风铃控制船。** ModuleMovingPlatform 始终由 definition.at_time(module.clock) 运转；没有受机制控制的局部相位或暂停状态。若直接停止 module.clock，会同时冻结同模块齿轮、计时等，违反机制独立性。
6. **表现已有咆哮音效、形变、姿态切帧，但不是阶段新形态或完整过场。** WindkeeperPresentation 使用同一个 body_actions 图集，intro/phase_transition 播 roar，没有真正咆哮粒子/摄像机震动消费者。新增表现必须跟随接受的阶段事件，不能替表现动画擅自决定伤害、开铃、拆地时机。

## 二、建议的最小完整实现

### 附着荆棘

新增可验证的 surface attachment 描述：稳定实例 ID、承载平台索引、面 normal、沿面起点/长度、突出危险深度。用该描述生成真实危险 Rect2；渲染读取同一描述，避免图片与碰撞两套来源。顶面/左墙/右墙先实现，不默认允许把有重力的模块旋转。

首个实例应为真实五格宽平台（例如 5×64），左两格顶面荆棘、右三格可站。AI 素材应包含与现有草/石/木材融合的荆棘面、危险—安全过渡、壁面根系，不把完整五格图水平拉伸到任意尺寸。危险实际只覆盖左两格，并留给玩家身体和落点的余量；荆棘不可盖住安全格边缘。

坑内旧危险若要迁移，应先明确到底是掉落危险还是扎根坑底荆棘。为“让图看起来扎根”偷偷增加地板，会改变跌落、射线与回程，不可作为纯美术替换。迁移后 bump generation/definition version，保留旧开发测试入口和失败证据。

### 牧风者阶段升级

- **阶段 1：地面读招 → 小跳越地波 → 地面瞄准颈铃。** 用 AI 发光环/颈铃开放姿态和地面到铃的方向图示。真实地面站位击铃应通过；同一位置不跳吃地波的反例应成立。第一阶段不能提前要求攀台或假二跳。
- **阶段 2：爬到草台 → 读持续侧风 → 在高处/跳起时向下射背铃。** 阶段新形态可为竖起的风车背架、暴露背铃上方开口。提示在过场和开放窗口都出现，不只在玩家已经撞甲后给文字。向下扇区与上侧箭头必须准确对应真实方向条件。
- **阶段 3：断桥连续换台 → 靠近当前桥墩 → 空中向下击铃 → 移动到下一桥墩。** 推荐明显更窄的上侧锥（例如 dot ≥0.65，须真实验证，不视为已确定数值），搭配三个桥墩巡回而非最后一墩永久 final_hold。核心位置与可站高台之间有安全、可射的下降视线；窄锥防止从单个远端高台覆盖全场。巡回真实移动并清楚预告，不瞬移 Boss。

阶段 3 必须保留 WindkeeperEncounter 现有“玩家到安全草台或岸边才拆桥”的条件。段回退后 Boss 阶段、巡回段、时钟、核心状态与地面破坏保存；回退锚点不可落在新荆棘或拆除平台上。过场可有演出镜头、咆哮震动、尘土与铃粒子，但不能夺走正在平台间腾空玩家的镜头或把玩家挪到安全处。跳过过场仍通过相同的安全迁移规则。

### 有标识的远程机关

生成稳定机关 ID，对铃和目标都画同样的 AI 铭牌图案（字形/形状，颜色辅助）；至少有方向箭头与目标类型图示，触发时有沿路径传播/门端亮起反馈。不要把未探索目标直接显示在迷雾地图上，可以显示已见机关的本地未知目标提示。

先落地三种真实用途：不同位置开门、从有限射击孔瞄准侧向门闩、启停/召回移动平台。平台采用自己的 local_motion_clock / running / stopped_at / control receipt；暂停累积平台自己的时钟，恢复不会从全局 module.clock 跳到另一个位置。状态进入 region mechanisms snapshot 并使用稳定 ID，不由段回退复位。岸边和对岸都具备合理召回/回程条件，空中停船后仍有落点或重新启动射线，不能让一次误射锁死唯一回程。

## 三、主动玩法建议（不只是用户前三条的换名）

| 玩法 | 玩家实际操作 / 决策 | 独特压力 | 复用与边界 |
| --- | --- | --- | --- |
| 风墙与背风窗 | 在实心挡风墙后等风段，跳出后用反冲抵消侧移，落入下一背风口 | 速度环境与遮挡决定起跳窗口，不是躲一颗弹 | 复用 queue_local_velocity；风的遮挡以真实壁面/区域记录，安全必经线不用道具 |
| 缺口落点平台 | 先观察平台危险格，选择从左越过两格荆棘落到右三格；返程用另一条较低接桥 | 落点精度与返程路线改变；同平台不等于到处能站 | 新附着荆棘；安全落点至少身体宽+余量，正反方向分别验证 |
| 投影落击引诱 | 跃扑敌人先锁定一个平台落点，玩家诱使其扑到一端，再跨到另一端/下一台 | 通过位置诱导释放通路，不能用杀敌当唯一解 | 复用 hopper 锁定 attack_goal，预警和实际落点一致，冷却能留下安全窗口 |
| 射中续航支路 | 可选高处奖励线由两个可瞄准空中敌人串成；玩家边移动边击中获得续射反冲 | 瞄准、命中回能与轨迹同时管理，失败可撤向低处 | 复用 D079 真实伤害返还；不能给无敌靶退款，敌人已死时仍有明确退路；主路不用此技术 |
| 折返升降井 | 上升时看见侧壁凹室奖励；选择早下船侧跳，或者继续上升再从另一口回落，开近路 | 相对运动中改变探索计划，奖励与通路共用空间 | 复用真正升降台/网图环；离开船也能召回，两方向全相位验证 |
| 交错横扫落点 | 第一台起跳时两枚齿轮分别扫过“常用落点”和“备用落点”；可等相位或反冲改变落点 | 两个落点选择不同风险，不是同一跳法重复两次 | 复用独立 ModuleSawHazard，相位图示不替代真实运动；危险不同时封死所有可等平台 |
| 退路先开的风险宝箱 | 高价值箱从难跳进入，箱前先射侧向机关开下层撤离桥；也可先绕路从另一边开桥 | 先观察回程，再决定投入资源，解决“去得了回不来” | 复用 stable opened 与反侧捷径；领奖不强制开机关、不刷新资源、不锁探索顺序 |
| 窄顶旁路与下穿窗口 | 看见上方齿轮横扫后，短跳走低拱避扫，或绕较高路线拿金币并承担空中瞄准压力 | 操作选择改变风险和奖励，不强称短跳是唯一通法 | 复用低拱的真实控高差异；两路线均基础能力可达，不偷改跳跃参数 |

首轮优先做“缺口落点平台 + 投影落击引诱 + 折返升降井”，再与远程机关结合。每种必须提供一个普通输入成功轨迹，以及一个体现压力/决策的对照轨迹；不要把表中八条设计全部写成已实现。

## 四、严格验收条件与否决规则

1. **美术、几何一致：** 五格平台左两格碰触真伤害，右三格左右边缘及站位无误伤；墙面危险可见朝向与身体扫掠吻合。AI 新素材记录来源/hash/图集区域/消费者，PNG 原图不靠脚本涂抹冒充 AI 新绘。
2. **真实遍历：** 附着危险模块、新机关至少入口→出口、出口→入口，全移动/齿轮初始相位；无配置更改、传送、资源补注、碰撞放宽。丢掉两发后能等地面回能或绕行，不会机关一次性消耗导致软锁。
3. **Boss 正负例：** 阶段 1 地面实际弹体命中；阶段 2 上侧命中、侧/下侧拒绝；阶段 3 两处以上独立桥墩真实跳跃向下命中，侧/下侧拒绝。相同固定高台、不移动只瞄准无法覆盖全部巡回核心；若可以，则不通过“逐步平台挑战”。
4. **演出真实消费者：** 普通网页进入 Boss 看见名字、咆哮震动/粒子、两次形态变化与对应方向提示；跳过、暂停、死亡、回退、卸载后无旧震动/粒子/延迟拆桥泄漏。演出不给玩家资源，不改 Core18px 伤害形状和已有批次规则。
5. **远端配对：** 至少一对铃/门距离达到不在同一个普通镜头内；两个同色机关仍能根据铭牌图形区分。正式消费者不能隐藏所有门端标识。风铃启停平台的真实位置连续，暂停不动、恢复不跳，乘员仍由 Motor 唯一 move_and_slide 携带。
6. **状态与死亡优先：** 地区 reload、环境段回退保留远门/平台启停/计时，不刷新箱/商店/敌人；死亡同帧射铃/领奖优先死亡。机关恢复顺序必须先创建平台与连接，再装载对应机制状态，不读取尚不存在对象。
7. **密度与趣味区别：** 对至少三种新增玩法验证操作/压力差异；单纯追加 hazards/敌人数量、换名称、镜像或 layout_hash 不计。主路支持早打 Boss，可选难线有可判断线索，不能每个连接都是强制密集战斗。
8. **回归与发布：** 保持 PlayerMotor、基础 player_tuning/input、一跳/未命中两发、D079 精力与命中回能、奖励/Meta 账本与两图边界；必要旧/新测试完整通过，公开 build-info 与实际 PCK 一致。设备与真人趣味认可仍单独待验，不以 headless 或导出成功替代。

否决优先级：软锁/无损路线不存在/真实动作预算失败/死亡优先破坏为 P1；新玩法无正式消费者、Boss 固定站射等功能要求不符为 P1；仅轻微表现欠佳且消费者真实为 P2。下一轮审查应读取实际变更并亲自验证至少一个新模块和一个 Boss 正负例，本报告不能代替下一轮。
