# 工坊触屏菜单修复

2026-10-13，分支 `fix/foundry-mobile-menu`，基于 `f721795` / PR56。用户报告右侧乱码、点击后卡住、无法换关。

旧版实测：Chromium 触屏模式真实 touchscreen.tap 可以打开 OptionButton，但不能选择 PopupMenu 项；弹出层持续遮挡下方列表。主按钮中文字正常，弹出层没有继承中文 Font。计时仍前进，说明本次复现为模态输入被锁住；不能据此断言用户手机的物理线程同样未冻结。独立反例与截图见 [审查](independent_review.md)。

修复：能力改为普通触屏 Button，关卡改为 ScrollContainer + 普通 Button；参考视频也使用可展开/关闭的内嵌列表。取消此消费者中的三个鼠标依赖选择控件，不更改全局 touch-to-mouse 禁用政策、不动 Motor/输入适配器/正式玩法。按钮高44，统一中文字体；关卡标题限制在右侧宽度内，钩子仍禁用。更换能力/关卡沿用原有取消动作、停止回放、释放旧世界并开始新尝试的流程。

Godot 4.7.2.stable.official.ed1daf0bf：实际 InputEventScreenTouch 回归438断言/0失败；原工坊消费者34/0；Core5942/0；全部36片段和18连续路线重新验证并提升批次。头部暂停、新关卡解除暂停、基础/二跳/四发、禁用钩子与中文字形有实际断言。消费者退出存在原有 ObjectDB/资源仍在使用诊断，日志完整保留，不标为零诊断。

本地 Web 导出、分块包完整性与缓存策略检查通过。桌面和两种触屏尺寸的 GUI/翻页/回放/暂停恢复继续实际截图复核；浏览器仿真不是 Android 真机验收。公开发布及构建信息在完成后补充，不以源码提交代替已部署版本。

第一次修复被独立审查否决：原生 ScrollContainer 在禁用鼠标模拟时也无法触屏拖动，只有前几项可选。失败截图与审查保留，第二次改为明确上一页/下一页按钮，关卡每页3项、来源每页2项，最后一页纳入实际触控测试。

第二次界面检查发现页码自动换行把按钮推入跳跃区域；新增布局断言在修复前437项/2失败（退出1），修复页码不换行与固定最小宽度后通过。最后增加短时间连续触点切换的回归，总438项/0失败。见[布局反例](rejected_pager_layout.txt)。
