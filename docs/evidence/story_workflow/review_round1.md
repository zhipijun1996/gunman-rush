## 必修 1：简版把求援信的轮次写早了

来源：`story_overview.md`“主角为什么出发”第一段：

> 他第一次因为道路改道进入家园，开始保留经历，随后收到上一轮老师写下的求救信。

问题：基线 `story_bible` §4 是入站当轮傍晚收到老师当轮写出的求援，午夜见证回返，下一轮黎明才带着上一轮的求援出发。简版把“上一轮”直接放在首次入站后的收信动作上，略掉午夜，容易让后续创作变成一封跨轮寄到的信或不明来源的旧信。

最小修正：写成“他因改道第一次进入钟外站，自愿留下。当晚收到老师的求援；午夜亲眼看见外面回到同一清晨。第二天出发时，只有他仍记得这封求援。”其中‘第二天’最好用‘下一轮黎明’，避免误称真正跨日。

## 必修 2：区域模板预设玩家总在事故前到达

来源：`story_templates.md` §4：

> 这一天的顺序：黎明 → 玩家到达 → 事故前 → 午夜；不能事后救已经遇难的人

问题：该顺序在模板中把‘玩家到达’排在‘事故前’，与 S4 冰川固定傍晚到场、午后已断桥不合。模板正是为后续 Codex 填卡使用，容易再次诱发本轮已经修正的“傍晚提前改道”。

最小修正：“这一天的顺序：黎明 → 预警/调度 → 事故发生时点 → 午夜；另标玩家何时到达（可在事故前或后），到达前由谁执行了什么。不能用晚到的动作阻止已发生的事故。”保留当地人员可受 S1 预警提前行动的接口。

## 非阻塞建议

- 开始任务模板的‘故事位置’可直接用 A 首通阶段 / B 揭露阶段 / C 最后救援阶段 / 真结局后，与既有三阶段表对应；目前‘首通后 / 知道真相后’有交叉，但不构成规则冲突。
- 区域模板‘不能事后救已经遇难的人’可以明确‘同一轮不能复活；网内当日死者下一轮恢复仍按 loop_rules’，防止被断章理解成旧版“死人从不回来”。
