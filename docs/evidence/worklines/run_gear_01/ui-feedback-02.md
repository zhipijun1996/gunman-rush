# RUN-GEAR-UI-02：正式暂停背包与分页

- 用户反馈：此前固定开发关卡录像无法看出主游戏接入；暂停应直接进入背包，左右切换页面；背包参考用户图片的已装备区、图标网格和选中道具详情。
- 追加反馈：负荷槽必须为齿轮形状，不用线段；已用／空余需清晰区分，沿现有主题画原生UI形状，不重做美术。
- 基线：RUN-GEAR-01 PR110，`631f50e2322f2b26a3d67bdc5c480dde19232dd4`，main仍为`26e7f2a`；在原独立分支更新同一PR，不自动合并。
- 范围：DemoMenu默认入口与分页、图标网格／详情布局、必要当前UI消费者测试及前轮CI发现的旧自动装备测试假设；不新增道具或美术，不改交易／核心物理。
- 接口：保留`visible_panel=build`与装备会话信号；进入背包时打开正式会话，切页／关闭立即作废旧操作。方向键在网格选中，Q/E及手柄肩键或屏幕左右按钮切页。
- 分工：inventory_layout唯一负责DemoMenu及新专用UI脚本；ui_feedback_tests负责现有UI消费者和新交互验证；ci_audit负责前轮远端失败定位及独立的旧自动生效假设迁移；formal_capture负责正式游戏入口录像；root负责整合、调度引擎、文档与PR。独审另行只读。
- 验证：窄parse→正式DemoApp默认暂停／鼠标选择详情／装卸／换页失效／小屏滚动与触控／关闭输入隔离→原相关Harness。主游戏演示必须实际正式平原场景，任何位置／收入fixture明确标注，不能冒充自然路线。
- 交付：更新PR与权威规则，提供正式入口的新画面与短片。独立Web沿原托管预算尝试；若900MiB上限仍阻塞，保留旧入口并明确说明，不以旧网页冒充本轮。
- 质量：沿game-quality-gate、project-integration；技术／AI审查／用户视觉／实体设备分别记录。用户参考图是结构方向授权，不是新画面验收。
