# Independent source review: --forest-places browser option

Reviewed `tools/verify_forest_browser.py`, SHA256 `1cffd0dcc915feef33a0e8d068230146ab8b5fc3e4f48a421178ec30ede2b52a`. I did not author or edit this script. No engine/browser launched; this is source/isolated pure-Python validation, not a GUI pass.

The CLI change preserves the default four map entries (Plains1, Plains2, Forest1, Forest2), for both existing mouse and emulated DOM-touch modes. Default `forest_places=False`; default labels and scroll=False match the former code. It does not replace the default v15 forest consumer.

With --forest-places, exactly Forest1/2 are selected. `click_text` screenshots the actual page, obtains the full normalized label `FOREST PLACES MAP n` from tesseract word boxes, and performs mouse.click/touchscreen.tap there. Missing text triggers bounded actual scroll and screenshot retries, not a fallback to default Forest. Production menu renders `FOREST PLACES / MAP n`; punctuation normalization makes this the same full label. The production requested_forest_places signal binds to explicit DEPTH_LAYOUT_PLACES, rather than a default generator.

CLI requires expected layout v18; that in turn requires region-v2. After the actual click it requires exactly one debug acceptance plus exactly one actual region_assembled event with matching region/map/device, debug_entry=true, exact layout18, content-v2, full manifest-hash form, correct per-map Boss scene/resource and grapple-only abilities. Rendered complete HUD heading/map and actual pause/resume interactions are retained. Existing PCK/source/badge identity checks stay in place. Therefore an honest old15 region_assembled event or a menu-only acceptance cannot satisfy the explicit18 CLI path.

Pure-Python counterexamples and selector checks in `/tmp/forest-v18-browser-option-review.py` and `.json`: missing layout, v15 expectation and missing version all CLI-rejected; v18 forwarded; actual old15 layout rejected; debug-only v18 rejected; synthetic default-label/wrong-map OCR words rejected while full candidate words accepted; default4/candidate2 expressions retain exact expected membership. Mocked OCR is explicitly not actual screenshot/browser evidence.

Boundary: assembled manifest_hash is checked for 64hex form, not matched to a predetermined seed-specific manifest. This tool verifies chosen actual GUI consumer/version, not native traversal, OR rewards, map variation, natural campaign continuation, physical touch devices, art, timing or fun. Existing report labels correctly say these limits. Internal callers invoking verify(...,forest_places=True) directly can bypass main()'s argument coupling if they omit expected versions/layout; only the reviewed CLI entry guarantees the guard. No such direct caller was used in this review. This is a small API boundary note, not evidence of CLI false pass.
