# region-generator

## V3实际生产依赖

短地区任务继续通过现有 `tools/level_design.py route` 读取权威阶段、单武器/能力与有来源经验，再由现有 `harness --mission --execute` 和真实活跃宿主执行。先核正式消费者及已有失败，不重画已有效资产、不把未来能力当已授予。地区设计必须同时派生态/Boss差距审查与视觉家族审查；未发现实质缺口不强制增加敌人或重做Boss，失败空间不阻塞无依赖的合格家族。

实施租约前运行原预检并核真实检查argv、sparse证据和冷import潜在写路径；不可把缺证据当内容失败浪费模型。普通feature整合遵循逐文件basis/child/target SHA、冲突停止、独立scope与原失败并存。当前原生/过程入口包括 `harness --check terrain-family-tests --check root-bell-tests --check forest-h-slice --release --jobs 1`；真实完整遭遇可调用 `python3 tools/run_root_bell_formal.py --default`（仅已准入的当前平原类，不是跨地区通用能力）。原样板/副本的通过不能代签修改后源码；最终另做正式镜头与Web预览。

既有森林仅S2-H隔离技术切片：短请求自动选择该切片是真实最小执行入口，不代表九个地区生产包已执行、森林开放或正式H授予；若完整制作受开放/素材/机制门槛阻塞，保留实际做到的切片及下一依赖，不能只生成计划却称全自动地区完成。

## 空间美术任务的协作入口

主要诉求为画面品质、景深或空间身份时，交 [visual-director](../visual-director/SKILL.md) 统筹像素闭环，本技能仍提供真实区域身份/Manifest/连接语义/支持面及正式消费者。若任务冻结玩法生成，仅开放表现分支，不重新抽Seed、移动平台、重排敌人或改能力资源迁就构图；大结构视觉可跨多个模块，但不能制造新的碰撞承诺。

先从实际空间和路线推导开阔/纵井/庭院/回廊的围合、大轮廓、负空间、观看顺序和主焦点，再由scene-composer布局，art-director确定资产家族。区域图节点不自动代表固定矩形美术房间；禁止每格套同一背景/拱门，用种子/Hash差异冒充空间身份。读取真实运行分支，单幅全景的默认消费者不能因为源码还有未启用多层而宣称已有景深。

提供跨纵横移动、回程、镜像、长通道及不同尺度节点的覆盖清单，保持玩法层/敌预告/船/奖励/HUD优先，根基/连接/植生挂点有来源。使用 `python3 tools/visual_director.py route --help` 生成共用原production_loop的任务，再按 `run --help` 真正执行；计划文件不算专业worker已执行。`capture --help`、`inspect --help`、`compare --help` 关联同Seed/路线/能力/相位的实机前后证据，详见 [视觉合同](../../../docs/quality/visual_director_contract.md)。

先一个正式静态/动态黄金内部准入，再在第二种空间以简短目标验证同族资产和方法；不复制黄金坐标当通用规则，也不把第二技术片签整区完成。连续两轮独审无实质画面改善或关键工具不可用停止该依赖，保留源/失败/调用耗时；客观覆盖、AI构图判断、用户审美/真机分记。新经验写来源、版本、消费者与适用范围，不将局部视觉经验改成全游戏能力或生成硬锁。

## 触发与边界

修改随机区域拓扑、段落编排、模块池、内容奖励分布或体验节奏。 从仓库根目录调用 `$region-generator`。使用 [总门槛](../../../docs/development_quality.md)；重要内容由 game-quality-gate 建立一次任务，专业技能补充同一记录，不重复执行共用阶段。

## 输入与依赖

读取 [AGENTS](../../../AGENTS.md)、[实际状态](../../../docs/current_state.md)、[handoff](../../../docs/handoff.md)、[架构](../../../docs/architecture.md)、[验收](../../../docs/acceptance_tests.md) 和相关最新设计。输入用户目标、基线完整 SHA、任务 ID、内容版本、受影响路径、正式消费者、已知失败与前置能力。缺信息先记录 unverified，独立可逆工作继续；重大创意不可伪称用户确认。

## 阶段流程与交付物

输入最新 [生成实现](../../../docs/generation_current.md)、Manifest/RNG 版本、真实能力和已验模块。复用 PlainsRegionGenerator、PlainsExplorationTopology、PlainsRouteRecipes、PlainsRegionAssembler、RunRandomStream；不能重造不兼容框架。
G0 分五层设计：①主/支/环路、捷径、分岔汇合、上下连接、单向与回程、Boss 接近、长度；②教学/观察/平台/战斗/机关/休息/探索奖励段落；③已验微观模块的速度/资源/能力/相位接口；④敌人机关商店宝箱补给故事线索与风险收益；⑤学习顺序、连续高压、安全恢复、操作交替、路线价值、惊喜、重复、回程疲劳与情绪地标。第五层可用离线观察设计，不假称已存在运行导演服务。
G1 分开验 A拓扑、B真实物理、C能力资源、D种子复现。保留分流 RNG、Manifest、有界重试和已验保底；真实 Motor 不能被图连通替代。
G2–G3 接入正式两图探索和地图消费者，检查地形拼接/背景/地标/雾图可读性、生命周期、保存与回退。使用 level-module-creator 的已验端口；新素材/动作分别调用专业技能。
G4 验 E结构多样性、F玩法动作多样性；采集拓扑签名、动作序列、机制组合、风险收益、连续压力/恢复、重复遭遇及回程成本。写抽样依据和观察定义，不把 Seed/Hash/模块数量不同当作丰富度。保留最差种子反例和修复前后。
G5 验 G探索趣味：真实路线①尽快找 Boss ②正常探索成长 ③高级奖励绕路并返回，逐条记录选择、疲劳、公平与奖励合理性。设备性能和用户反馈分开。
交付：五层 Design Sheet、版本变更理由、种子集/Manifest、结构统计、真实操作/完整探索证据及独立报告；未实现能力解锁不得冒充当前已有能力。

## 设计要求

使用 [专用模板](../../../docs/templates/region_generation_design.md) 写场景/前置、方法、可观察结果和失败条件。复用真实配置/Definition/架构，禁止重复数值默认值、无消费者框架或为通过测试改基础物理。占位仅限明确标注的原型，不能冒充最终内容。

## 自动验收

运行 harness gameplay；直接定位 [15 套地区](../../../tools/run_plains_region_tests.py) 与 [共享生成消费者](../../../tools/run_generated_consumer_tests.py)，保留适用回归。结构统计、Motor 专项、完整体验三类证据不能混为一条 PASS。 记录实际命令、环境、退出码、日志和版本；计划命令不算执行。执行 [质量检查](../../../tools/quality.py)；静态检查、运行测试、实际宿主调用分别记证据。

## 人工审查

采用 [通用审查方法](../../../docs/quality/review_method.md) 的不变量与对照/变形测试，覆盖实际绘制与正式消费者；用户反馈是回归样本，不是发现问题的唯一列表。

gameplay-reviewer 检查三种路线实际决策、学习与恢复节奏、地图/动作重复、回程成本和公平奖励。美感/趣味须玩家体验，不用自动随意打分。

## 准入退出与返工

按 [policy](../../../docs/quality/policy.json) 的相关 G0–G5 执行。进入一阶段前上一相关阶段通过、输入与消费者明确；退出须专用模板的可证伪判据及对应证据成立。设计失败退 G0，操作/公平失败退 G1，表现失败退 G2，接入/状态失败退 G3；修复后重跑受影响门槛并复审。保留失败原件，不删除测试/降标。依赖阻塞写 blocked，缺审查写 review，缺真机写 awaiting-device。

## 完成与证据

使用 [质量报告](../../../docs/templates/quality_gate_acceptance.md) 和 docs/quality/records/<task_id>.json，逐项记录 design/technical/formal_integration/visual/animation/audio_vfx/gameplay/performance/independent_review/device/player_acceptance。只允许 passed/failed/unverified/not_applicable（有理由）；证据需路径、SHA256、提交/内容版本、观察和来源。技术通过不能宣称完整内容完成；所有适用条件具备才可 done。本技能文档本身不提供任何内容的 PASS 或用户认可。

## Level Design Harness V2：完整地区生产与优化

本节把旧五层设计升级为六层；旧运行入口和质量门槛继续有效。读取 [V2 总合同与真实命令](../../../docs/level_design_harness_v2.md)，使用 [地区模板](../../../docs/templates/biome_design_profile.md)、[优化模板](../../../docs/templates/level_optimization.md)、[验收模板](../../../docs/templates/level_experience_acceptance.md)。

所需输入增加：需求类型（optimize/create）、玩家原始反馈、目标设备、支持的合法基础构筑集合、区域身份与学习前置、源 Manifest/版本、代表及最差 Seed、实际路线和轨迹。权威能力来自正式消费者授予点、PlayerMotor、运行 Weapon/Ability Definition、config/player_tuning.json、config/input_profile.json、[动作最新要求](../../../docs/design/player_actions/README.md)；MovementCapabilityEnvelope 是规划输入，不能替代真实 Motor。读取最新资源/动作修订，不把 Studio 的十五装备、H/W/D 或 Foundry 开发 profile 当作正式平原能力。

| 层 | 本技能负责的集成结果 | 专业协作 |
| --- | --- | --- |
| 1 宏观拓扑 | 有语义的节点/边、路线选择理由、环路/捷径、授予与锁、回程 | region-generator |
| 2 身份与空间语法 | 行为目标、空间轮廓、机制生态、地标与奖励 | scene-composer |

执行 A（优化已有地区）：冻结正式消费者和基线 → 收集反馈并复现 Seed/路线/模块 → 用 V2 analyze 取得基线，区分规则网格事实、重复动作和实际空白 → 按影响选择优先体验问题 → 少量黄金改进 → Motor/路线/构图验证 → 仅推广通过样板 → 同 Seed/能力/路线/版本依据 compare → 原有两图及保存/随机流回归 → 独立审查。不得为赶指标塞机关；反馈“无聊”须落到具体动作、决策或回程。

执行 B（新地区）：定位世界观与进入能力 → 明确区别于已有地区的机制和空间身份 → 比较语义约束图、非规则嵌入、多尺度分配与手工骨架变体 → 写地区/构图/挑战合同 → 黄金技术切片 → 真实机制和连续动作 → 可复用模块库 → 多种非线性布局 → 遭遇奖励/能力锁 → 美术系列/合屏 → 正式消费者集成 → 最差 Seed、回归和玩家评测。未实现区域先 fixture；继承 regions_v0.3 已确认 S1–S6/16地区框架，具体候选连边/机关不自行定稿，不能悄悄开放地区。

八种体验标签可并存：安全探索与环境叙事、基础教学、普通平台、多动作组合、战斗平台混合、高收益技巧、隐藏大师、Boss 空间。主路短动作链/低卡关与明确恢复；奖励支线允许更长、更复杂且收益匹配；大师仅隐藏可选且失败可学。难度记录已学机制、连续深度、机制耦合、路线复杂度、空中修正、时序、资源、恢复成本、战斗混合、能力深度；不改单独地区的重力/手感，不用动作数量单独定级。

能力锁逐条证明授予路径、无循环、锁前后探索变化、每个基础合法单武器构筑的替代路线、返回/撤离、换装不困死、低资源/冷却/相位下的恢复。动作/结构/机制/探索/视觉五签名分开；坐标、贴图、ID、Hash 变化不直接计新体验。

输出合同：同一任务目录保存地区设计卡、生成 Manifest、能力快照、路线清单、真实轨迹、LevelExperienceReport、对照报告和质量记录；意图/结果/运行状态/物理证据/主观评价独立标注来源。不复制 RunManifest/RNG，也不把设计 JSON 写成物理通过。

必须验证：V2 validate/analyze/compare/route（参数以总合同和 --help 为准）、每个新增检测的通过与故意失败例、harness docs/gameplay，涉及资产再 art；基线阈值按地区/体验类别/设备记录且版本化，黄金样板和玩家反馈后才校准。图可达和未互动距离只是诊断；无完整路线 Motor 证据则 traversal=unverified。人工看三种探索策略、正常速度音画、PC/手柄/手机操作；缺设备 awaiting-device，缺趣味/审美 review。

失败按所属层最小返工并保留反例；正式准入要求真实消费者覆盖、全支持基础构筑路径、原回归、独立审查及适用玩家/设备认可，不以 V2 诊断命令成功代替 G5。

适用示例：“优化风铃平原”执行 A、先找最长重复/空白路线；“制作荆棘森林”执行 B、先做不同空间身份的合同和技术切片；二者共享上述消费者与证据格式。

## 自主生产闭环与 Q1–Q8

每次关卡任务先执行 [统一质量维度的权威加载与来源账本](../../../docs/quality/level_quality_dimensions.md)：自动读动作入口、regions_v0.3、weapons_v0.8 全文及最新覆盖合同，核对 LOCKED/PROPOSED、实现消费者与正式授予三种状态。继承 S1–S6/16地区、H/W/D/U1/U2、S2单能力、S4替代、S5双移动+U1；不从旧八关或旧V2摘要重创规则。Q1–Q8 映射既有十一维，不增加质量编号。

依据当前任务的最新用户授权及可写范围直接设计、实现、测试、审查、返工；历史“仅工具”或“有限切片”不覆盖后来的整区授权，也不自动授权其他地区或核心规则变更。PlayerMotor/武器/资源/随机流/保存与未授权地区仍是边界。用户负责核心创意与审美偏好/最终体验认可；常规缺陷由团队主动发现修复。

本技能统筹 Q1/Q4/Q7，并合并其余维度证据。输入先列阶段/地区条款、合法单武器构筑、已学机制与实际开放范围，再决定局部拓扑、路线和身份；每个挑战只要求其必要子集，不能为展示全能力破坏 S2 或主路合同。森林 dry-run 必须从 S2-H+基础动作出发，不重新征询已确认阶段框架。

优化先选一个有正式消费者证据的 Q 问题，提出最小修改与不改方案，写真实玩家行为差异和反例。将改动分成设计→实现→真实检查→独立审查→返工的依赖包；发现不成立可保留原设计，但不得只回传 TODO。新任务若授权正式切片，完成准许路径实现和回归后再报告主观待验。

本轮冻结至少10个不同root Seed ×两张正式地图×不同路线的覆盖矩阵，标计划/实测、派生 Seed 与敌人范围；保留最差 Seed，不随机重抽规避失败。既有capture无敌人只作辅助，必须补正式敌人及画面；同条件before/after和至少一正式优化切片由原质量记录验收。Q7五类差异各有描述与来源，不能用Hash或总体配方数证明路线丰富。

把独立发现定位到对应Skill并附最小返工包、预算与恢复指纹；按统一标准保留可复用规则的来源/适用范围/反例。没有真实worker日志和消费者变化，不称自主生产完成。


## 平原整区重设计范围（2026-10-15，覆盖旧轮有限切片范围）

最新用户已授权全面重设计正式平原的布局、路线、模块组合、敌人与机关编排、构图和随机策略；仍保留核心物理、单武器/资源/能力成长、RNG服务、保存和两图流程。不要把上一轮“仅工具”或“只做最小切片”当成本轮上限。先验证代表性黄金，再按有意图的宏观骨架推广，并对整区实际路线/最差Seed/动态画面独审与返工。未知的新需求仍按其实际授权范围执行；本条不自动开放其他地区或授权合并/发布。

生产经验：portable证据目录必须在实施租约前纳入allowed_paths，超界须保留blocked后修订租约；每条连续链的出程与返程均需完整动作/边界/真实事件和资源因果，删事件、删返程或仅保留reached标记必须拒绝。策略升级时在冻结旧内容上用同字节策略复采，分清驾驶策略收益和内容收益。历史坐标专属测试在可重建的冻结源中保留原断言，新默认消费者必须另有实际强验，其他适用回归仍跑新默认。


## 先保住设计承诺，再产生变体

生成结果中的路线合同不是愿望清单。在剪边、转单向、分配锁和空间之前确定教学短路、可选发现、汇合营地与回程；每个变换须保护这些实际step与进入条件。不能把删断后的8边绕路改名“短技巧路线”消除失败，也不能只保护第一边却宣称整条路线存在。变化优先放到学习后有意义的分流、重汇合、捷径与Boss接近；同时保留既有差异/动作覆盖等断言，不能用保护所有边制造重复地图。

对代表Seed和原corpus审核每条声明路线，再用同body真实输入验证最差Seed及替代路线。不同variant数字必须实际改变挑战组合或决策；未参与内容选择的随机字段不得计新体验。失败、候选与最终接入分开归档。[本轮实际返工](../../../docs/quality/plains_redesign_spatial.md)是有适用范围的例子，不是所有地区都采用相同轴向布局的规则。


反重复应按玩家实际动作家族/状态变化审查，不只recipe ID。稳定图1教学可以复用，图2应有明确深化；相邻不同ID若都要求相同短按释放，不自动算新体验。每条长绕路必须有可读发现、风险收益、恢复或回程价值。先验证真实黄金，再推广；将现有箱预算搬到新岸时，必须有真正可达支撑/取奖输入/回程，不能只修改坐标与标签。


探索顺序也是反重复输入：同一地区至少检查“先主路学会→再发现高奖”“先上层支线→回主路”“拿奖后异路返回”。直接deep策略避开主路，不能证明玩家正常探索不会连续复考同一个题。允许复用已学模块，但高奖深化应体现在入口状态、资源、时序、空间耦合或可选熟练解；若到相同满资源静止岸再做完全相同双铃，只增加前置台阶不足以证明新深度。先用真实帧/资源核对，再选已验证组合或做有证据的深化，不按ID数量做决定。

叶节点并非错误：有独特发现、恢复、景观或叙事也可以成立。但不能把700高度原路爬回、只有普通守卫掉落的尾枝，仅凭地图有环/后台打了探索tag就认作有意义。比较真实返程连接、现预算奖励与明确场景目的，避免每个角落塞币。参见[实际中期设计审视](../../../docs/evidence/plains_redesign/design_midreview/report.md)，其中候选设计与实跑证据分开，不能自动扩成所有地区的度数硬规则。


## 短请求自动选择首个可执行阶段

`python3 tools/level_design.py route --request "制作荆棘森林" --output build/forest_mission.json` 默认 `--phase auto`。路由先加载最新权威、地区上下文与经验账本；已登记但尚无正式消费者的地区自动选择一个 G0/G1 开发原型包，并在 `production_plan` 保留完整九包及生态、Boss、美术、动画和正式验证依赖。用户不需了解 prototype 参数。显式 `--phase production` 仍返回完整九包，逐包原生地区 proof 门槛保持严格；不以共享 Plains/Foundry PASS 代证。

荆棘森林当前首阶段只取 S2/H：现有 Studio 授予 API 在开发初始化授 H，使用真实 PlayerMotor/Controller/InputRouter、单 PulseLv1、锚点牵引踢跳、整身体稳定枝台落地与连续安全返回。`forest-h-slice` 在共享 engine lock 下运行真实原生正例、删除锚点和不授 H 反例；原 Harness 消费当前源、日志和调用回执绑定的 region_proof。删除落地事件或返程、混入 W/D/U1/U2、缺原生证据均不得通过。技术轮廓不代表森林成品美术，开发授予不代表正式 H 成长或森林开放；G2–G5、生态/Boss/完整资产动画、用户和设备仍为后续门槛。

# level-module-creator

## 触发与边界

新增平台跳跃挑战、模块端口/时序/连接改动及模块准入。 从仓库根目录调用 `$level-module-creator`。使用 [总门槛](../../../docs/development_quality.md)；重要内容由 game-quality-gate 建立一次任务，专业技能补充同一记录，不重复执行共用阶段。

## 输入与依赖

读取 [AGENTS](../../../AGENTS.md)、[实际状态](../../../docs/current_state.md)、[handoff](../../../docs/handoff.md)、[架构](../../../docs/architecture.md)、[验收](../../../docs/acceptance_tests.md) 和相关最新设计。输入用户目标、基线完整 SHA、任务 ID、内容版本、受影响路径、正式消费者、已知失败与前置能力。缺信息先记录 unverified，独立可逆工作继续；重大创意不可伪称用户确认。

## 阶段流程与交付物

G0：模块名称、玩法目标、必需动作、真实能力要求、进入位置/速度/资源/冷却、入出口端口、操作序列、机关时序、观察区、安全落点、失败恢复、接缝净空、敌人允许点、镜头提示、美术语义、难度收益。先读 [模块契约](../../../docs/platforming_modules.md) 和 [能力](../../../docs/ability_components.md)，不能使用未授予能力。
G1：用现有 [PlayerMotor](../../../scripts/player/player_motor.gd)、实际能力/动作次数和反冲弹体执行。正向、需要的反向、动态相位、资源能力边界、完整身体碰撞/危险扫掠、接缝、失败恢复分别验证。入口速度/冷却写在证据里，不靠传送/手改坐标或几何路径冒充成功。
G2：art-director 验证功能色、地形端头和镜头落点；涉及动作/特效调用 animation-vfx。正常游戏尺寸合屏及连续操作录像，不能为拼图改碰撞。
G3：Module Lab 只作为定位工具；在真实邻接模块、不同端口/镜像/高差和正式随机池验证连接。单模块成功不代表拼接成功。核对正式能力/资源、存档回退和恢复位置。
G4：运行真实 Motor 专项及生成回归；gameplay-reviewer 主动检查危险扫掠、不可见落点、偶然相位和不可恢复状态。禁止擅自调整 PlayerMotor 基础参数使模块过关。
G5：玩家实操可读性、手感、公平性和设备控制；有证据才允许正式池准入。原型可保持 review/blocked 并清楚列出缺项。
交付：设计卡、可玩模块、端口/相位表、邻接矩阵、真实输入轨迹、截图录像和质量报告。

## 设计要求

使用 [专用模板](../../../docs/templates/level_module_design.md) 写场景/前置、方法、可观察结果和失败条件。复用真实配置/Definition/架构，禁止重复数值默认值、无消费者框架或为通过测试改基础物理。占位仅限明确标注的原型，不能冒充最终内容。

涉及可变形状地形时，执行 [邻接与拼接契约](../../../docs/quality/terrain_tile_contract.md)：枚举局部邻接、不同分块的同图对照、薄结构与孔洞、真实 GPU 与正式合屏分开验收。不能用覆盖率代替美术品质。

地形表现接入时引用 [地形契约](../../../docs/quality/terrain_tile_contract.md)：一行平台也须覆盖长度×厚度、短端头、相邻间隙和移动相位。物理尺寸先定，素材按外露边界适配，不为图片改变已验模块。单向桥、实体台与危险的轮廓语义分开；用正式模块合屏证明落点可读。

## 自动验收

运行 harness gameplay，定位入口 [地区测试](../../../tools/run_plains_region_tests.py)、[共享消费者](../../../tools/run_generated_consumer_tests.py)。保留正例与必失败反例，记录 Seed/Manifest、能力、入出口状态；结构测试和 Motor 验证分栏。 记录实际命令、环境、退出码、日志和版本；计划命令不算执行。执行 [质量检查](../../../tools/quality.py)；静态检查、运行测试、实际宿主调用分别记证据。

## 人工审查

采用 [通用审查方法](../../../docs/quality/review_method.md) 的不变量与对照/变形测试，覆盖实际绘制与正式消费者；用户反馈是回归样本，不是发现问题的唯一列表。

在镜头中观察危险/落点、提示与安全空间；玩家是否学得会、失败能理解且能恢复。审查相邻组合及资源边界，不能只看蓝图。

## 准入退出与返工

按 [policy](../../../docs/quality/policy.json) 的相关 G0–G5 执行。进入一阶段前上一相关阶段通过、输入与消费者明确；退出须专用模板的可证伪判据及对应证据成立。设计失败退 G0，操作/公平失败退 G1，表现失败退 G2，接入/状态失败退 G3；修复后重跑受影响门槛并复审。保留失败原件，不删除测试/降标。依赖阻塞写 blocked，缺审查写 review，缺真机写 awaiting-device。

## 完成与证据

使用 [质量报告](../../../docs/templates/quality_gate_acceptance.md) 和 docs/quality/records/<task_id>.json，逐项记录 design/technical/formal_integration/visual/animation/audio_vfx/gameplay/performance/independent_review/device/player_acceptance。只允许 passed/failed/unverified/not_applicable（有理由）；证据需路径、SHA256、提交/内容版本、观察和来源。技术通过不能宣称完整内容完成；所有适用条件具备才可 done。本技能文档本身不提供任何内容的 PASS 或用户认可。

## V2：动作链中的模块

使用 [挑战卡](../../../docs/templates/challenge_sequence.md) 与 [V2 入口](../../../docs/level_design_harness_v2.md)。challenge-choreographer 负责玩家连续动作与决策，本技能负责把它实现为 PlatformingModuleDefinition/现有模块消费者，不另建相互冲突的模块池。

输入必须包含“为什么需要这个模块”、所属主路/奖励/大师合同、动作链位置、上下游模块、合法单武器能力快照、目标设备、空间/美术需求。权威能力与资源读取实际装备/授予点、PlayerMotor、Definition、player_tuning/input_profile 和最新动作文档；规划中或仅 Studio 授予的能力不得进入正式主路。

实际步骤：把每个动作转为入口位置/速度区间、身体碰撞包络、动作次数/能量/冷却及稳定站位条件 → 列主要与替代输入序列 → 定义落点/出口状态、动态相位、观察/恢复窗口 → 检查上段出口是否满足本段入口（资源和时序也须满足）→ 复用 Foundry 验证单模块、连续短语和 itinerary → 验真实邻接、反向返回、失败恢复 → scene-composer/art-director 合屏 → 正式候选池及原生成回归。

优先验证射击在同一动作中触发敌人/机关并产生反冲的双重作用；不能为证明恢复而直接加能量、重置相位或中途传送。敌人可改变路线/时机，但不得无预告占据唯一合法落点。移动落点必须验相对运动和最低观察时间；多摇杆同时精确输入在手机上单列人工门槛。

输出在原设计卡增加：compatible_predecessors/successors、进入/退出真实状态、行动依赖、拒绝组合及原因、目标设备操作、相位矩阵、完整输入轨迹和失败帧、镜头/素材接缝需求。数值从真实运行采样，未校准写 unverified。

自动验证：执行 V2 validate/analyze（以总入口 --help 为准）、Foundry 原真实 Motor build/回放及适用 harness gameplay；保留“各单模块可过但串联资源不足”反例、错误入口速度反例、不可见落点与低能量/不利相位例。记录单模块与连续 itinerary 的独立结果，完整地区路线未回放不能外推。人工按普通/进阶/大师三张卡检查可读、流畅、失败学习、设备可操作性。

任何碰撞/资源/相位变更使相关旧轨迹失效；返工 challenge-choreographer 的衔接或本模块几何，禁止改 PlayerMotor 迁就模块。Foundry --promote 只进开发工坊，不是正式模块准入。正式晋级仍依 G0–G5、真实消费者/独立/用户和设备证据。

示例：短“跳跃→向下射击反冲→方向修正→稳定落地”作为普通黄金技术片；仅在实际 Definition 和 Motor 确认后采用。更长组合为进阶/大师候选，不能仅凭动作数命名难度。

## 自主生产闭环与 Q1–Q8

每次关卡任务先执行 [统一质量维度的权威加载与来源账本](../../../docs/quality/level_quality_dimensions.md)：自动读动作入口、regions_v0.3、weapons_v0.8 全文及最新覆盖合同，核对 LOCKED/PROPOSED、实现消费者与正式授予三种状态。继承 S1–S6/16地区、H/W/D/U1/U2、S2单能力、S4替代、S5双移动+U1；不从旧八关或旧V2摘要重创规则。Q1–Q8 映射既有十一维，不增加质量编号。

依据当前任务的最新用户授权及可写范围直接设计、实现、测试、审查、返工；历史“仅工具”或“有限切片”不覆盖后来的整区授权，也不自动授权其他地区或核心规则变更。PlayerMotor/武器/资源/随机流/保存与未授权地区仍是边界。用户负责核心创意与审美偏好/最终体验认可；常规缺陷由团队主动发现修复。

本技能负责 Q2/Q3 的真实模块消费者及 Q8，不把“编舞卡完整”当模块已完成。接卡先确认上段实际出口速度/资源/相位能进入本段，写具体 Definition/装配路径与邻接测试；沿用真实武器，不把最大能力包络当当前装备。

实现时用正式敌人/机关组合验地形：敌人存活、走离、死亡、未激活的最坏状态，唯一落点/资源恢复/返回不应消失。边界 fixture 与真实输入产生状态分别留证；单片通过后测试相邻连续链和正式地图，改动消费者不能只在Foundry有效。

修改后自动运行受影响Godot/生成/Harness与故意失败例，再交独立审查；不让用户发现穿模/盲落点/死路。返工包指出物理位置、期望/观测、失败帧和最小几何或时序调整，禁止改基础Motor/武器/资源。只有完成本轮实际正式切片与同条件对照才声明实现范围，不以计划命令或模板签收。

# challenge-choreographer

## 触发与边界

用户要求“连续反冲挑战”“这里操作单调/衔接不流畅”“黄金普通/进阶/大师样板”时调用 `$challenge-choreographer`。负责动作编舞；level-module-creator 负责物理模块实现，region-generator 负责地区/路线集成；不发明未实现动作或改变武器。

## 输入与依赖

任务/源提交、主路/奖励/隐藏大师定位、经验标签、已学机制、单武器能力快照与合法备选构筑、真实资源/冷却、空间边界、上下游状态、敌人/机关、设备、玩家反馈、正式消费者。缺能力数据先采集授予点/运行状态，不能从最大跳高猜动作能力。

## 阶段流程与交付物

1. G0 填 [挑战设计卡](../../../docs/templates/challenge_sequence.md)，先写一次有价值的判断和失败可理解性，再选择 AtomicAction → ActionPhrase → ChallengeSequence → Encounter/Room → Route。原子动作逐个引用实际输入和 Runtime/Motor 消费者；未来动作标 future 且排除正式主路。
2. 为每个转移记录前置位置/速度、武器等级、空中次数、能量/冷却、观察信息、允许下一动作、稳定站位或恢复要求；主要序列及替代序列必须均遵守同一时刻单武器，钩索独立。射击命中/机关触发与反冲可在同动作耦合，但真实提交命中才允许资源恢复。
3. 把状态转移映射到空间/碰撞和机关时序，列安全观察区、目标落点、失败恢复、镜头提前展示、输入容错测量方法。禁止只写模块 ID 串；入口/出口的速度、资源、相位要能连续衔接。敌人不得无预告阻断唯一落点。
4. 按普通/进阶/大师模板做小样：普通主路短链流畅/容错；进阶支线更深资源决策和机制互动；大师隐藏可选、长链与精密控制且可学。难度用机制耦合、时序、恢复成本等向量描述，不单靠动作数/缩台/加障碍。
5. G1 委托 level-module-creator 用现有 Foundry/真实 PlayerMotor 建单片和连续 itinerary；至少测基线、低资源、错误入口、最坏相位及一次失败恢复。轨迹中的接受动作/拒绝动作和真实资源变化要能追溯，不中途重置身体或资源。
6. G2–G3 与 scene-composer/art-director 验实际镜头可见信息和目标设备操作，接正式相邻组合；G4 将正反例交 gameplay-reviewer；G5 单独收集玩家学习/流畅/公平反馈。

## 完成与证据

docs 下任务设计卡（使用挑战模板）；已有 Definition/Foundry 配置的最小修改；build/ 下运行 Manifest、能力快照、输入回放、轨迹和失败日志；docs/evidence/<task>/ 下精选复现索引；同一质量记录。ChallengeSequence 的动作关系和证据引用按 V2 schema，设计状态与物理状态分开。普通/进阶/大师卡均给实际可运行入口，不把空 JSON 当黄金样板。

## 自动验收

按 V2 文档调用 `python3 tools/level_design.py validate` 与 `analyze`（完整参数查 --help）；运行现有 `python3 tools/foundry.py build --profiles base --count 6` 和受影响能力 profile 的真实回放、`python3 tools/harness.py --profile gameplay`，文档至少 docs。不能拿 base 通过证明可选能力 profile 或正式整图通过。新增规则必须有通过例和故意失败例，尤其未授予能力、双武器拼接、连续资源不足和错版本证据；记录结果，不把命令清单当执行证据。

## 人工审查与协作

gameplay-reviewer 独立看正常速度轨迹/画面是否可读和公平；PC 键鼠、实体手柄、手机触屏分别评同时操作负荷、预判与误触。region-generator 检查主路线准入和学习前置；encounter-director 检查前后压力/恢复；art-director/scene-composer 检查落点/预告可见；animation-vfx 检查真实动作反馈。无设备/真人数据明确未验。

## 适用示例

“向下射击攻击敌人并反冲到平台”先证明敌人真实受击与位移是同一输入结果，再验落地/能量和下一短语；“jump→recoil→directional_correction→landing”是候选语法，只有引用实际消费者并回放后才有物理证据。

## 设计要求与权威来源

先读 [AGENTS](../../../AGENTS.md)、[current_state](../../../docs/current_state.md)、[handoff](../../../docs/handoff.md)、[V2 真实合同/CLI](../../../docs/level_design_harness_v2.md)。实际参数来自 config/player_tuning.json、config/input_profile.json、运行 Definition 和正式消费者授予点；[动作入口](../../../docs/design/player_actions/README.md) 中规划/候选不是已授予能力。复用 RunManifest、RunRandomStream、PlayerMotor、PlatformingModuleDefinition 和现有 LEVEL FOUNDRY，不改物理、武器规则、资源、保存或随机流以让设计过关。

同 game-quality-gate 共用任务 ID、G0–G5 和 docs/quality/records/<task_id>.json，不重造门槛或质量类型。十一维 design/technical/formal_integration/visual/animation/audio_vfx/gameplay/performance/independent_review/device/player_acceptance 分别记录 passed/failed/unverified/not_applicable（理由）。命令保存版本、退出码、日志；轨迹保存 Seed/Manifest、能力、相位、输入、失败位置和来源哈希。意图不冒充运行，单片不外推整图，AI 不代签用户/设备。

## 准入退出与返工

保留失败证据、发现 ID 和最差 Seed；设计失败回 G0、真实操作失败回 G1、表现失败回 G2、消费者失败回 G3，修复后重跑受影响检查并独立复审。依赖不足 blocked，缺主观/独立审查 review，缺设备 awaiting-device；不能删断言、放宽阈值、无限重抽或用静态结构掩盖失败。

正式准入依 [policy](../../../docs/quality/policy.json) 的所有适用门槛。黄金技术片明确 production_pool=false 和未完成视觉/创意项；Foundry 开发池晋级不等于正式地区准入。本技能文档不提供内容 PASS。

## 自主生产闭环与 Q1–Q8

每次关卡任务先执行 [统一质量维度的权威加载与来源账本](../../../docs/quality/level_quality_dimensions.md)：自动读动作入口、regions_v0.3、weapons_v0.8 全文及最新覆盖合同，核对 LOCKED/PROPOSED、实现消费者与正式授予三种状态。继承 S1–S6/16地区、H/W/D/U1/U2、S2单能力、S4替代、S5双移动+U1；不从旧八关或旧V2摘要重创规则。Q1–Q8 映射既有十一维，不增加质量编号。

依据当前任务的最新用户授权及可写范围直接设计、实现、测试、审查、返工；历史“仅工具”或“有限切片”不覆盖后来的整区授权，也不自动授权其他地区或核心规则变更。PlayerMotor/武器/资源/随机流/保存与未授权地区仍是边界。用户负责核心创意与审美偏好/最终体验认可；常规缺陷由团队主动发现修复。

本技能主责 Q2，联合 Q3/Q5/Q8。先用“观察→选择→承诺→修正→落地/恢复”解释一次短语，再给实际动作转移；优先让射击方向同时决定攻击/机关效果与自身落点。至少比较一个替代编舞和保持现状方案，不能只追加动作数量。技能合同继承地区权威，不要求每段使用所有可用能力。

与encounter-director共同标敌人位置/感知/攻击窗口、危险扫掠与镜头。对敌人死亡、移动离开或未激活逐一验证：命中恢复/可钩目标消失后仍有合法主路或可恢复返回；不可把“玩家先不杀”当保证。输入请求与接受动作/伤害提交分开，资源连续性以真Motor状态为准。

输出给实现者的不只是动作卡：包含模块/端口变更位置、相位与资源测试、成功/失败输入轨迹要求、误差测量和独立审查的反例。失败回到最早不成立的动作转移，保存原轨迹→改动→复验；不传送/补能/改手感。低互动候选先核查观察与恢复用途，安全区成立时保留而非加动作。


## 从真实平原返工中校准输入容错

固定输入与多相位成功不代表操作余量。主路线的短动作链还要少量、有界地扰动真实起跳位置、释放时间与进入状态，保存成功与危险接触边界；不要用自动轨迹的精度要求普通人。平原实战中低拱18个方向/位置/释放组合有12个身体接触危险，修复几何后同样本复验；只证明这个局部包络，不等于玩家成功率或手机手感。保留原危险、低顶与动作判断，并用地面直走/长按等反例防止靠删除挑战通过。先改障碍空间关系，禁止改Motor或输入、注能或降低守门阈值。

连续段必须记录每leg的真实停稳、有效射击、资源、机关/船状态及返程；中途领取回调要发生在实际安全岸，traverse成功不能代替正式modal/claimedID。参考[实际体验返工](../../../docs/quality/plains_redesign_experience.md)，不是要求未来所有地区都采用嵌地齿轮。


证据要能被反证：仅统计callback次数或末帧grounded/open不证明动作链。删除实际跳跃/落地、移动岛上callback到起岸、删返船drop输入或最终真实机关伤害提交，都应使相关合同拒绝；每个关键事件绑定实际frame、支撑、位置与前后状态窗口。不要硬编码成功轨迹的tick，也不能只针对已知五个坏样本写特判。原生执行真实与验收器严格是两种证据，缺一须返工。[本轮EXPERIENCE-R1](../../../docs/quality/plains_redesign_experience.md)应保留原拒绝及修复复验。


## 编舞候选的具体取舍

先写一句可观察的核心判断，例如“向上射击开门，同时向下制动落在接收岸”，再布置地形；攻击/开关与位移只是同时发生、互不影响时，不称双重作用。先稳定观察，再作承诺，允许一次可理解修正，最后落地读反馈；普通主路通常只教清楚一个判断，奖励链才耦合已学判断。不要在每次空中同时要求新瞄准、新敌人预告和不可见落点。

改重复优先改变决策关系：把三个同样长按跳改成“短释放穿低顶→稳定岸辨认铃门→射击方向影响下一落点”是候选方向，不保证此排列已实跑；每个转移仍须真实Motor和合屏。反例是三个换皮窄台、每台同一输入，以及为了多样性强加与前后无关的新障碍。动作链值得保留的证据包括熟练后减少无效停顿、错误可定位到具体判断、替代打法有可读差异；没有真人证据时只作为待检设计假设。
