# 游戏开发质量门槛

规范版本 **1**；自动策略来源 [quality/policy.json](quality/policy.json)。目标是原创手绘童话 Roguelike：平台操作、射击反冲位移、随机探索与有记忆点的 Boss 战共同构成体验。技术可运行只是基础；正式内容还须设计完整、合屏精美、动作连续、反馈准确，并得到真实玩家认可。

## 范围与路由

重大敌人/Boss/模块/地区/机制/UI/美术/动作任务由 game-quality-gate 选一个专业主导技能，再按需组合。一个任务只保留一份 G0–G5 记录。纯流程建设 process 与小修 small_fix 使用 G0/G4 和 design/technical；影响正式消费者的小修还需 formal_integration。扩大玩法、美术或物理的改动不得标成小修以跳关。prototype 可以在 G1 交付阶段成果，但完整内容任务保持 review/in_progress。

[通用任务模板](templates/iteration.md) → [专业模板](quality/policy.json) → [质量报告](templates/quality_gate_acceptance.md)。先写可观察的玩家体验、相关限制、任务依赖和失败条件，后实现。用户的新授权优先，重大创意记录 user_confirmed/proposed/not_required 及出处；AI 提案不能变成用户确认。可借鉴《空洞骑士》《蔚蓝》《死亡细胞》《奥日》的设计方法，不复制角色、素材、地图和具体实现。

## G0–G5

| 门槛 | 准入与工作 | 阶段产物 | 退出证据与失败返工 |
| --- | --- | --- | --- |
| G0 设计规格 | 核对真实基线/能力/既有内容；回答体验、趣味、差异、核心操作、反冲融合、教学、策略、视听UI、失败恢复和验证 | 设计卡、流程/必要示意、场景化验收项、创意决策状态 | spec 证据；设计价值缺失或与现有内容仅数值差异则返工 G0 |
| G1 完整灰盒 | 使用已明确的候选设计和真实 Input/PlayerMotor/弹体/碰撞/资源/伤害与开始结束流程 | 可玩切片，输入轨迹、成功/失败/边界反例，Seed/能力/配置 | runtime_trace；传送、改坐标、直接调用成功函数、几何代实际操作均不合格；失败返回 G0/G1 |
| G2 视听样板 | 已验证动作规则，按 Visual Bible/真实镜头接入美术、动画、VFX/声音/UI | 正式画面截图及正常速度连续录像、动作时间轴、母版/资产账本 | screenshot + video；素材导入/静态姿态/单图不能替代运行表现，错位或不统一返工 G2 |
| G3 正式集成 | 样板技术可用；接真实入口/实例/内容池与状态所有权 | 正式 GUI 流程、奖励/存档/暂停/死亡/回退/重载/取消旧请求及对象性能证据 | gui；Lab/fixture 不替代正式消费者。集成失效返工 G3，设计缺陷回 G0 |
| G4 自动与独立审查 | 适用自动检查完成，提交规格、实现和失败历史给独立审查者 | 命令日志、反例、逐条发现与修复复审报告 | command + review；可 REJECT。独立审查者不修改被审生产代码；无法独立就 unverified。修复后审同一内容版本 |
| G5 玩家与设备 | 正式集成及技术审查通过，目标设备、操作路径、版本明确 | 用户对画风/手感/难度/趣味的原始反馈、设备测量与限制 | user_feedback + device_measurement；AI 自评不替代用户，浏览器模拟不替代真机。未验保留，不虚构最终通过 |

阶段允许为缺陷诊断临时执行后续检查，但不能据此宣称前置门槛通过。某阶段确不适用要记录理由；重要内容的必需门槛不能靠 not_applicable 跳过。单纯美术资产任务复用已验玩法，G1 可不适用并说明复用依据；修改操作规则时重新归类。纯流程任务 G1/G2/G3/G5 可不适用，未来游戏尚未真人试玩不阻塞流程工具交付。

## 十一维验收和任务状态

每份记录必须包含 design、technical、formal_integration、visual、animation、audio_vfx、gameplay、performance、independent_review、device、player_acceptance。每项只允许 passed / failed / unverified / not_applicable；passed 需证据，not_applicable 需具体理由，failed 需缺陷与返工路径，unverified 说明缺什么。

| 工作流状态 | 对应含义 |
| --- | --- |
| planned / ready | 目标/依赖已记录，尚未制作/准入；不是通过 |
| in_progress | 正在 G0–G4 制作、验证、修复 |
| review | 阶段成果可审查，或仍有主观/独立审查未验；报告具体维度 |
| blocked | 当前必要依赖/工具/缺陷阻塞；指出可独立推进项 |
| awaiting-device | 适用技术门槛完成，尚缺真实设备证据（其他未验仍列出） |
| done | 本任务类型所有必需门槛/维度已通过，无未解决拒绝；scope 明确。process done 只表示流程体系完成 |

完整内容中技术 passed、视觉 unverified 不能 done。最终主观维度需要用户反馈覆盖对应范围；用户认可某张原画不覆盖实际动画、完整 Boss 或后续随机图。旧 PASS 不覆盖修改后的内容版本。未适用维度不计分，不以平均分冲抵失败。

## 证据最小合同

记录任务 ID、基线提交、审查内容版本、受影响路径、目标、玩家体验、限制、交付物、创意决策、门槛/维度、逐场景测试和未验清单。每条验收项写 scenario / method / expected / failure / status / evidence。证据带路径、SHA256、source_commit、生产者、方法、观察结果；命令带 command/exit_code/environment。截图与录像注明入口、种子、配置、设备、正常速度时间段；设备测量注明型号/系统/输入/分辨率、帧时间/峰值对象/内存及目标预算出处。禁止凭空规定统一 FPS、帧数或主观评分阈值。

review 证据记录 author/reviewer、独立依据、审查提交/范围、发现/复现/严重性、REJECT/ACCEPT/UNVERIFIED、复审链。user_feedback 保存原话与可追溯来源，不让模型代写同意。检查器能验证字段和归属，不能认证真实人的身份或视频质量；这仍须审查。

## 不可走捷径

仅功能无体验设计、几何占位称最终美术、静图称完整动画、加 HP/速度称新机制、换名称新敌人、模块数量/Seed hash 称丰富度、几何连通称真实可达、fixture 称正式接入、单截图称动作流畅、构建成功称设备性能，都不能作为完整交付。

不得删失败测试/放宽危险判定/无授权改 PlayerMotor 基础参数来取得通过。原型可占位，但记录期限、范围和后续任务。未实际审查不能产出 PASS；用户未认可的美术/趣味/手感不得声称最终通过。脚本不会自动将 pending 变成 passed。

## 返工闭环

失败 → 保留原证据和发现 ID → 定位所属门槛 → 修改最小范围 → 重新执行受影响测试 → 独立复审 → 更新十一维状态。新内容版本使旧的相关通过失效，引用旧报告需说明未受影响范围。不得删除失败记录后只留成功截图。
