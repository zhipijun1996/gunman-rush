# 剧情任务模板

只填本次用得上的部分。改一句对话，不必填整套表。模板用于发现缺口，不要求角色按表格说话。规则以 [loop_rules](loop_rules.md) 为准，操作顺序见 [写作流程](codex_workflow.md)。以下内容是文档格式，不是已实现的存档字段或游戏接口。

## 1. 开始一个任务

```text
任务：
范围：只写文档 / 接入游戏（必须符合本次授权）
基线：分支、提交、引用的设定文件
故事位置：A首通救师 / B揭露试验 / C最后救援 / 真结局后
本次只解决：
玩家会知道什么：
允许修改：
不确定的设定：标明提案，并给出理由；不要当作已经确认
交付：场景文本、状态变化、检查结果
```

## 2. 一个剧情房或环境碎片

```text
文档编号与名称：编号仅便于引用，不代表代码已有对应ID
区域、当天时段：
出现条件：哪些是保证出现，哪些是随机补充
角色此时知道什么、从哪里知道：
玩家先看到/听到什么：
可以做什么：
对话：先写2—4句，信息不足再补
玩家因此理解的新事实：
它和主线的关系：可选碎片 / 必经信息；必经信息的保底入口在哪里
可达条件：本阶段已授予能力、单武器、入口出口、安全站位
离开后的结果：
回家后：
下一轮再来：
中途零血/未完成：
重复互动/重复领奖：
真结局后：
状态：哪些只在本局有效，哪些拟跨局保留；由哪个真实系统提交（未接入就写待定）
```

随机房可以解释“为什么”，但不能独占“下一步必须做什么”。必须读到的事实应有主线路径或同层合法路线的稳定入口。

## 3. 一个可加入家园的NPC

```text
姓名、原来的工作：
循环之前的生活：
今天想做成的事：
不愿离开的原因：
和主角的关系：
性格通过哪个动作表现：
知道的事实及来源：
被救前：看到什么、说什么、做什么
救援完成点：何时才算安全到站，失败如何处理
到家后：住在哪里，做什么，第一次和下次说话有什么变化
原来的地方：下一轮不再出现本人；岗位/家人/区域后果如何处理
个人故事：开始、变化、收尾；不把可选NPC变成真结局唯一钥匙
真结局后：仍有什么想做的事
```

若NPC说出上一轮的事，先检查他是否已进家园，或是否确实读到留存记录。不能因为玩家知道，他就跟着知道。

## 4. 一个区域及其Boss

```text
区域ID与层级：沿用现有16区，不新增路线门槛
引用：region_narratives / boss_narratives / 地区能力规范
这里原来的生活：
这一天的顺序：黎明 → 预警/调度 → 事故发生时点 → 午夜
另标玩家到达时点：可在事故前或后；到达前由谁执行了什么，不能用晚到的动作阻止已发生的事故
死亡边界：同一轮不能复活已死者；网内当日死者下一轮恢复仍按loop_rules
画面证据：前景可互动、中景生活痕迹、背景地标，各自说明什么
两张图各承担什么：探索/铺垫、冲突/后果；不保证玩家看全所有支线
本轮能改变的事：
下轮恢复的事：
留在家园的知识或人物：
任意合法路线如何完成同层必要工作：
Boss是谁、为什么阻挡主角：
战前可见的动机：
胜利意味着击退/停机/救援/其他：明确对象是否存活
本轮失败与下轮重遇：
和已有美术、名称、战斗行为的兼容：不借剧情擅改正式内容
```

所有区域都生活在同一个反复发生的日子里。冰雪是地理与天气，旧树是本来就长在那里；不要再给每区另造时间机制。

## 5. 一个结局或一轮审查

```text
结局：玩家以为完成了什么，实际完成了什么
这次真实保住了谁、留下了什么：
还没解决什么：在画面中怎样看到，避免旁白突然推翻胜利
下一次出发的理由：
终止循环前：本轮必须实际完成哪些安全步骤，谁负责，先后如何
前轮可继承：知识、已安全入站的人、家园权限
不能继承：外界阀门位置、已疏散但未入站的人、已扑灭的火等物理结果
失败/零血/提交失败：不能记录一半成功或重复奖励
真结局后：真实第二天与旧日回放分清，不把回放人物带入现实
```

审查意见写具体位置和后果：

```text
来源：文件、段落、当前规则
问题：哪两件事不能同时成立
玩家会遇到：哪个实际场景会露出矛盾
最小修正：改哪一处，是否影响其他文档
结论：可继续 / 需修改 / 缺证据；不代签玩家认可
```

## 填写示例：平原面包师的第二句话

**候选样例，只作写作示范，未新增正式NPC或剧情系统。**

- 位置：首通前的风铃平原，白天。可选小屋从侧路进入，按平原当前已授予能力和普通跳跃/反冲设计，具体几何待实现验证；不要求二段跳或钩索。
- 第一眼：桌上摆着五个面包。面包师反复把最小的一个放进布袋。
- 初见：“小的这个给我女儿。她说大面包吃不完。”主角不能凭这句话知道循环原因。
- 救援：她愿意跟主角走，但只有安全到站并完成登记才算加入家园。途中零血，没有成功提交就不记救援完成。
- 到家后：“今天也烤五个？……不用了，先数数这里住了几个人。”她从家园的连续生活学会不再照旧日清单做事。
- 下一轮：小屋没有第二个面包师。她在家园保留记忆；出发前已完成的救援不因本局失败撤回。
- 没救她：仍按当日旧习惯装袋；这条支线不会阻止主角救老师或完成结局。原岗位后果沿区域设定处理，不凭空安排另一个本人。
- 重复对话：只复述或换生活短句，不重复发放救援奖励。这里只描述预期，具体保存提交仍须查现有Run/Meta契约。
- 真结局后：“明天想吃什么？”真实第二天她还活着；旧日回放不再生成可带走的她。

本段只让玩家看到“家园里的人能开始过新生活”。她的女儿身处何处、是否需要救援尚未设定；若后续扩写，必须先补清，不能用一句台词默认为已经获救。
