# 怪物开发手册

由enemy-creator统筹，art-director、animation-vfx、encounter-director和audio-director按具体工序交接；game-quality-gate管理同一任务，gameplay-reviewer独审。本手册回答「怎样做」，[完成标准](../../../../docs/quality/enemy_completion_standard.md)回答「做到什么程度」。沿原G0–G5／十一维，不新增阶段状态、评分或登记系统。

## 开工：把缺口变成制作任务

先读当前AGENTS／状态、目标地区Bible、当前registry／共享风格与实际消费者；排期和声音选择按当前权威，不从旧skill段落重开已选方向。只加载本任务相关历史证据。填写原[Enemy Sheet](../../../../docs/templates/enemy_design.md)的「开发计划与专业交接」，用同一task_id／content_version关联[美术卡](../../../../docs/templates/art_asset_specification.md)与[动画卡](../../../../docs/templates/animation_vfx_specification.md)。

由skill从用户目标和仓库生成、补齐这些卡，用户不需要逐格填表或手工串联专业技能；能从现有源查到的信息先查。只在缺少无法推断的重要偏好／授权时提具体问题，同时继续无依赖工作。

| 用户目标 | 起点及具体工作 | 保留边界 |
| --- | --- | --- |
| 新怪物／新核心行为 | 第1步比较机制，先真实灰盒，再做身体与动作 | 新增玩家判断；不先定批量数量 |
| 补齐已有怪物 | 按E01–E12盘点，找最早未满足的依赖，从相应工序补起 | 已验机制与未受影响证据复用，不强制重做全部AI |
| 美术／动作／特效修复 | 用发现ID、实际片段、当前源定位第2–5步的责任层 | 旧HP、时序、碰撞、资源、奖励和保存政策不为画面偷偷改变 |
| 只问流程或只核对 | 交过程定义／实际观察与缺口，制作记录保持真实状态 | 不把示例prompt当作已执行生成，也不签怪物完成 |

计划每行写「当前输入 → 要做的操作 → 实际文件／运行入口 → 谁接手 → 下一项最小验证」，并声明写集、来源、预算、已知失败和恢复点。获得制作授权的任务应实际改资源／代码并进Godot验证；不能只交一张清单。工具缺失报告具体阻塞，先做无依赖工作；常规授权内返工不逐步要求用户确认，重大画风／玩法方向变化沿原授权规则处理。

## 1．先让行为与遭遇成立（enemy-creator＋encounter-director，G0–G1；E01／E02／E09）

1. 写玩家在什么地形、用什么已有武器／能力、看到何种信息后改变什么判断；新怪比较多个真正不同的机制和保留旧方案。旧怪表现修复直接引用原机制。
2. 用现有EnemyDefinition／AI／Motor／Health／DamagePolicy组合最小灰盒，参数只来自真实定义。先做一条可打、可避／可按设计绕过、能失败恢复的遭遇；攻击状态、伤害和资源要由真实输入／弹体触发。
3. 从实际激活函数核距离、视线、安全区、并发、落地等条件，建立成功与拒绝对照。看到telegraph不等于进入attack；没攻击先查哪个谓词拒绝，再调整合法接近路线或显式初始fixture，不能加射程／关保护／伪造state救影片。
4. 输出同一制作卡中的行为图、反制、定义／实例路径、遭遇与运行轨迹。几何和机制无解先改设计，不花预算给失败灰盒批量画皮肤。

## 2．先确定同一个身体（art-director，G2；E03／E11）

1. 实际打开最终绘制宿主使用的live图、现有H／D图和同屏玩家／背景；追安装器与替换分支，不能只看被覆盖的父类。以正常游戏比例判断身体，不只看原尺寸大画布。
2. 在美术卡明确一种母版策略：保留当前live身份并重作不一致动作，或在授权范围内统一重作live与整套动作。更换全局画风不属于常规修复。冻结轮廓、头身比、肢体／翼／角／装置、材质分区、光向、功能色、可见尺寸及脚／附件锚；受击亮色和变形可变化，身体身份不可无意变化。
3. 先制作neutral／移动关键姿态、受伤压缩、受伤退出等少量代表姿态并在真实尺度对照；这些是本次选样，不是全物种固定张数。重点先证live↔hurt与live→death属于同一身体，再扩动作家族。
4. 使用宿主实际可用的图像生成／编辑工具，带同一母版引用和逐态姿态意图；编辑本地参考前先实际看图。透明图按实际用途请求透明背景。不要把每态作为无共同参考的独立角色生成，也不要把旧procedural SVG重建器当作新的成品美术生产能力。
5. 调用前保存逐字prompt、编辑意图、引用路径／SHA和来源；回包立即保存原图与工具结果，未知model／许可如实登记。测实际alpha、padding、跨格污染、整数裁区和锚点；生成器不保证等分网格，按实际图建manifest，不裁掉角／翼以强塞格。
6. 原图保留字节，派生按现有管线记录；导入资源清单、原asset_records和有限真实消费者，不造第二套资产登记。先一件母版及合屏成立，再扩该家族；失败按原预算停止／返工，不用改阈值追认。

交给动画的实物：已记录版本的身体参考、实际原图／裁区、全clip固定显示比例、脚／附件锚、材质处理与使用边界。概念图或「母版通过」一句话不够。

生成／编辑指令按实际任务填值，例如：「以所附【母版路径／SHA】为同一个体，保持【轮廓、器官数／位置、材质分区、配色和明暗】；只改变【本动作的受力／关节／姿态】，按【当前实际世界尺寸和采样】观看仍清楚；交【本轮少量关键姿态】及透明背景，保留完整角／翼／脚与留白，不加文字／场景。」动作指令同时写进入来源与退出目标，不能只说「受伤四帧」。这只是生产输入模板，真实结果仍须逐项检查。

## 3．按运动和攻击制作动作家族（animation-vfx，G2；E04／E05）

1. 读取实际AI状态／时钟、Motor轨迹、朝向和接受事件，为待机、移动、转向、预警、攻击、攻击恢复、受伤、受伤退出、死亡、终态选择逐帧／骨骼／程序方法；补物种专属态。不机械规定帧数，不把整体缩放默认当所有物种的步态。
2. 先定关键姿态与受力方向：地面步态核承重／抬脚、空中核拍翼／滑翔，预警有蓄势，攻击有发力，恢复有收势。可见运动服从真实位移；表现不写root motion搬Actor，不改判定或强行stagger。
3. 以同一身体参考派生完整动作，固定clip级比例与基准锚，不逐帧按bbox归一化。根据真实动作相位配置帧时长／程序参数；攻击有效窗读取原玩法，不能为配图改伤害窗口。
4. 给每条转换定义进入姿态、退出目标、混合／桥接方式与中断所有者。受伤结束读取当时真实AI／运动相位，不能回放受伤前缓存的错误状态；死亡覆盖非致死演出，暂停冻结既有世界时钟。
5. 先在真实宿主跑「移动→受伤→当前动作」和「当前动作→死亡→终态」；先看正常速度再逐帧。若H4与live解剖结构不同，回第2步统一身体；若身份相同但脚／重心突跳，修锚／相位／桥接，不用辉光、交叉淡化或更多帧掩盖错误身体。
6. 最后展开左右、转向、攻击中受伤、连续命中、慢时、暂停和取消等转换。父类有动画不代表正式替换身体显示该动画；始终核最终可见叶。

交付实物：实际clip／程序实现与manifest、状态／转换表、原时钟和锚绑定、完整资源引用、连续样板与具体反例。只出sprite sheet尚未接运行，不算该工序完成。

## 4．让命中、死亡和声音跟随结果（animation-vfx＋audio-director，G1–G3；E06／E07／E08／E10）

1. 从真实接受回执接反馈，核APPLIED／负增量／event_id／epoch／terminal；落空、拒绝、重复回执、旧epoch分别走正确分支。复用原反馈叶／配置，只在真实新消费者需要时扩接口，不另造万能事件总线。
2. 按接触点／来向／身体材质设计短闪、形变和碎屑，先身体可读再调特效层次。身体tint与预警／HP／Boss弱点分层；特效只表现结果，不结算伤害、回能或位移。
3. 死亡开始就明确谁持有D1至终态、谁释放、谁结算奖励；父Motor会隐藏时由现有Stage兄弟叶持有尸体。按当前政策接真实支撑、有限坠落与保存的support-local锚；恢复直接终态，零重复死亡音画／掉落，不改消失绕过留尸缺口。
4. 怪物选声先用现有`audio_director.py brief`读取当前风格／事件／已选声音，再实际选材或制作配方、A/B实战试听。开火声归武器，怪物声由原接受／败亡事件唯一触发，复用原声音池；不重开已选BGM或启用历史被拒声音。
5. 按当前实际并发预算设置特效／尸体／声音上限与降级／回收，测峰值和卸载后存活对象；fixed-fps录制和真实音频backend释放分别验证，不能放宽声音池换通过。

## 5．从样板进入正式游戏（enemy-creator＋encounter-director，G3；E09–E11）

先接一个真实正式实例和该区当前生成／安装器，保旧稳定ID／UID及实际配置所有者；按授权范围版本化真实资产和内容绑定，不能只刷新SHA继承旧通过。核自然接近、真实相机／HUD、地形／同伴、资源与允许的击杀／非击杀策略；再补最差相位、墙／台边、回退、重载与死亡恢复。新行为按原准入后才扩正式池，局部表现修复不擅自增加物种投放。

新clip先跑相关专项、再受影响完整系统和正式消费者，最后沿原Release交付。观察局部动作可交真实MP4；操作与策略需要交实际版本Preview。一个家族的黄金成立后，再选不同运动／体型的第二物种验证复用，不一口气套到所有怪物。

## 6．按失败层返工（原G4–G5；E12）

| 观察到的问题 | 回到哪里、实际改什么 | 复验 |
| --- | --- | --- |
| live／H／D像换了物种 | art-director第2步；改身体母版／同族派生，保原失败 | 相同事件与比例，进出两端及死亡首帧 |
| 身体相同但脚滑／回接跳 | animation-vfx第3步；修锚、步态／相位、退出桥接 | 同运动／朝向／攻击相位的正常速度连续片 |
| 只有预警，没有attack | enemy-creator第1步；查真实谓词／路线／fixture覆盖 | 实际attack与伤害／躲避回执，不靠发射请求 |
| 命中好看但没扣血／重复出声 | 第1／4步；区分真实接受、拒绝和表现层重复订阅 | 实弹与拒绝／重复／旧epoch对照 |
| 尸体漂浮／消失／重放 | 第4／5步；现有Stage／Remains／save所有者修支撑与持有 | 落地、移动／释放支撑、当前正式状态恢复 |
| 组合必损血或堵唯一落点 | encounter-director第1／5步；改空间／时序与反制 | 正式遭遇、允许替代策略与失败恢复 |
| 导入／解析／工具缺失 | 工程定位实际依赖、版本和消费者 | 原入口与错误对照；不消耗新美术调用救工程 |

修复交具体版本、发现ID和新证据给原独审，不自行撤销REJECT；用户／设备认可由原G5记录。没有独立执行条件写self_review／unverified；不冒充独立技能调用。连续两轮无实质改善沿原停止规则保留失败并停对应依赖，重新设计须有新依据，不换任务名重抽。

## 现有工具怎样接入

以下是已存在入口示例，当前宿主需实际执行才有证据；不适用的物种不能生搬该样板。所有新录制使用尚不存在的目录，先看`--help`，不能覆盖失败。

```sh
# 同一原记录；ID与输出路径按任务换成真实值
python3 tools/quality.py init --id ENEMY-EXAMPLE-02 --type enemy --output build/quality/enemy-example-02.json
python3 tools/production_plan.py --stage development --base origin/main --plan
# --plan只规划；确认实际选中范围后使用原--execute执行
python3 tools/production_plan.py --stage development --base origin/main --execute --jobs 1

# 当前两类旧样板的原生入口示例：选本次相关项，不宣称覆盖其他物种
python3 tools/run_integration_four_tests.py --case enemy-feedback-native
python3 tools/run_integration_four_tests.py --case enemy-feedback-support
python3 tools/run_integration_four_tests.py --case enemy-corpse-save
python3 tools/run_integration_four_tests.py --case enemy-corpse-snapshot

# 原工具仅录charger／diver显式fixture，两表现链各自采证
python3 tools/capture_enemy_feedback_01_remains.py --output build/enemy_example_02/underworld-take01 --variant after --chain underworld --expect-remains
python3 tools/capture_enemy_feedback_01_remains.py --output build/enemy_example_02/legacy-take01 --variant after --chain legacy --expect-remains
python3 tools/quality.py check build/quality/enemy-example-02.json
```

已有原录制fixture没有charger attack状态的[实际反例](../../../../docs/evidence/enemy_completion_01/continuity_review.md)说明：上述影片工具有用，但不覆盖完整攻击／自然正式遭遇。新物种或缺窗口需在既有采证架构补真实消费者和反例，不写空runner或拿旧片冒充。

## 一句话调用

> `$enemy-creator` 按统一标准补齐【物种／地区】，使用当前已选画风。先盘点缺口与真实身体／行为消费者，把工作分配到现有美术、动画、音效和遭遇技能；先制作最早失败依赖及一个完整真实样板，实际交付原图／资源／代码和正常速度运行证据，再推广。复用已验未变范围，记录仍缺的工具、正式场景、独审、用户和设备证据。

`$art-director`可以单独接「统一该怪live／H／D身体母版与同族动作素材」；`$animation-vfx`可以单独接「在这套母版上实现步态、攻击和受伤退出」；它们仍回填同一任务。SKILL.md是当前宿主按步骤调用工具的工作方法，不是无人值守自动生成／修图服务；本手册的存在不证明已生成新素材或整怪生产能力通过。
