## 从实际画面修设计

本包先复看旧基线与当前 HIGH B 的真实 840/1440/2287 帧，再制作两种正式合屏。最初实际 `golden1_meadow` 和 `golden2_creek` 分别记录 1100/2600 tick；都是 `frame_budget_exhausted` 的片段，不能宣称整条路线通过。前者首次看到真实厚岸/偏置风车与清楚的井铃反冲角色；后者真实经过受控船、侧岸箱与营地，仍有一次俯冲接触 HP5→4。这是实际伤害，不是输入 TTL，也不是无伤或无解结论。

清掉 760 宽 HUD 与全屏动作字符串后，第一版仍把井铃接收岸挤到画底；原生投影又发现岛岸右端在视域外。于是正式区域显式选择 `StageCameraRig.region_composition`：zoom1.60，保留旧默认1.95及原边界/弹簧/支撑跟随。溪船附近按真实 Manifest 岛岸作至多100世界单位水平构图前视，主岔口700高处不假称可见岛箱。摄像机从不读取测试策略目标或移动角色。原生判断的必要目标不按画外过滤而消失。

三次专项失败保留：画外必要目标、边缘活敌被地图chip遮挡、取得奖励后的toast遮挡低处角色；另有负例清理时释放仍在运行的driver造成脚本错误。这些都不能当 PASS。修复使用有限边缘布局、角色/活敌/弹体优先权、toast出生即布局、真正 process 完成后的同tick观测，并在负例退出前保留活消费者，未降低几何或证据阈值。
