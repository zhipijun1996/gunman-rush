## Critical API traps verified in code

* `EnemyAttackBehavior._serial` increments only when `_fire` emits each sentry/fan projectile. Charger/diver/hopper telegraphs do **not** increment it. Retain production `projectile_serial` and add a test-observer-only monotonic transition serial from the real `state_changed` signal; record behavior/state/clock/locked_direction/origin/goal/home. A state serial is observation, not a gameplay mutation or universal attack identifier.
* `Damageable.receive_damage` returns immediately through `damage_sink` in the formal DemoApp. It does **not** emit `damaged(context)` on that branch. Do not use that signal as proof of formal projectile hits. `FrameDamagePolicy.batch_resolved` supplies the committed `result.request.event_id`, source/target, real health snapshot/lethal. The player's projectile event ID is `owner_id:session_id:shot_id`. Capture exact projectile owner/session/shot/energy_receipt_id and matching applied stamina receipt from the real projectile inventory/resource signal. This join needs no change to production damage components.
* Existing `event("damage_committed", {"kind": int(...)})` loses the integer kind because Dictionary.merge does not overwrite the outer string `kind`. Use distinct `damage_kind` in new observer output; retain outer `kind="damage_committed"`. Never rewrite old raw evidence to repair this.
* Actor `.is_physics_processing()` is expected true for living enemies while EnemyMotor self-processing is false: actor drives motor. Actor `_active()` does not consult activation_range. A living enemy outside range is **engagement-ineligible**, not engine-disabled. Label this exactly; retain `actor_processing=true`, terminal=false and range/occlusion reason.
* `recovery` does not imply a safe landing: diver/hopper physically return home during it; sentry shots may remain live. Read actual body and active `_projectiles`/spent/position/direction/radius/remaining, not only AI state. `blocked` remains a live contact hazard.
* No safe-bank request can be approved from a centre-point ray alone. Real body is read from actual CollisionShape2D, supporting collider, all applicable static hazards/moving saw sweeps, enemy contact extents, and projectile motion. Use actual physics queries and previous/current body sweeps. Scene anchors suppress attacks near them but do not eliminate all collision/body exposure by implication.

## Driver control and safety (minimum implementation)

Use existing live `tick` and Router path only. No call to Controller.physics_tick/move_and_slide/try_fire or direct actor position/state writes. Interception runs only when grounded, Router has no pending actions, and a physically safe bank can be established. A private `_enemy_policy_busy` guard prevents recursion while helpers await the same `tick`; all nested physics frames remain observed. Save and restore the original **axis intent only**, after real settling on the selected bank. Do not save/replay timestamped action queues, inject waits after a jump/shot is already queued, or interfere in a committed airborne phrase. If no safe intervention is possible, record a positioned bounded failure, not claim the controller solved it.

Preflight boundaries: before entering a real module/edge, and grounded walk segments when a projected upcoming contact or incoming projectile enters the bounded look-ahead. The existing BranchModuleDriver has its own move loops and calls live tick; interception must therefore cover grounded safe tick boundaries too, not only LevelFormalTrace.move_to. It must not treat every grounded frame of a landing as a new combat episode. Maintain per-target attempt/transition receipts and a whole-route frame/encounter budget. Observations happen every frame around nearby hazards; the existing six-frame runtime inventory alone is too coarse for causal shot/contact proof.

`threats_for_corridor(target_aabb)`:
- map enemy ID to actual instantiated EnemyMotor and actor, definition health/size/radius/activation/attack phase, no cached manifest-only death;
- predict conservative contact envelope from actual home/goal/current body/patrol extent and observed previous/current motion; include live enemy projectiles even if shooter recovering;
- query whether actual shot/muzzle swept line is blocked by solids or bells; a shot first hitting a bell is not enemy damage;
- choose a same-connected-floor bank with body support and backwards recoil clearance from the actual weapon motion/tuning. Existing Pulse1 ground recoil is about84.7px, but implementation must read motion rather than duplicate this audit number;
- moving ferry decks are not automatically a stable combat bank. First implementation may explicitly decline those interception points and pre-clear from real shore.

`kill_from_bank(enemy)`:
- approach/retreat to chosen bank with bounded axis input; wait actual grounded cooldown/energy, remain within physical bank boundaries;
- aim real KeyboardMouseAdapter.world_direction(canvas_transform * enemy.global_position), Router.request_action(shoot_release); never call ShootAbility.try_fire;
- correlate each actual shot accepted to applied `shot/<session>/<packet>` stamina consumption and real projectile context. Wait real DamageResult with matching event_id/target and terminal actual health. One accepted shot without damage is a miss/block, not a kill;
- at most six attempts/target, one bounded encounter window (e.g.900 physics frames) plus existing route budget; abort on no safe support, health loss, recovery, scene change, no progress or impossible visibility. Report reasons and last target state. If enemy moves, use next actual position; no homing projectile or aim-after-fire retag;
- land/settle/restore axis on original bank before ordinary module motion. True killed enemy actor may cease processing by actual _on_death; policy never disables it itself.

`bait_then_bypass(enemy, takeoff, receiver)`:
- choose legal supported bait position visible/in range while outside body sweep; wait actual telegraph transition and capture locked goal/aim; legally retreat off locked sweep;
- wait actual attack movement/projectile arrival/clearing; prove receiver and transfer path clear using live sweeps and sufficient recovery timing; call the original traversal from this actual pose;
- ranged projectile still crossing receiver or diver returning through it => wait/reject. Safe re-entry is not equivalent to fixed sleep(0.7s). A live `blocked` enemy on the path cannot be waited into nonexistence: diagnose and stop/choose an explicitly declared alternate legal route; do not silently kill it in this mode;
- charger/diver/hopper transition observation uses local transition number. Sentry/fan includes true projectile event IDs. Non-kill success demands target living and real reached exit; unavailable opportunity remains unverified, not success.

## Enemy four-state verification

Each state is established by actual input and observed, continuing with the same player/session/phase:
- alive: normal formal spawn, actual health>0 and actor processing. Run both policy modes independently from identical seed/start setup.
- moving-away: real bait commits attack or return motion, actual body leaves receiver and velocity/position trajectory demonstrates it. A dict label or serial increment is insufficient.
- dead: kill with real accepted shots + applied consumption + committed enemy damage + terminal health, then traverse the unchanged geometry. No force health/current assignment and no restore_instance_health shortcut.
- inactive boundary: call it **engagement-ineligible/out_of_range or occluded**, actual health>0/actor processing, player legally walks to out-of-range/occlusion bank; subsequently traverses a path not reliant on that enemy. If current formal layout cannot make this state from supported entry, retain bounded unverified; a separate fixture boundary is allowed with explicit fixture scope, and cannot sign formal coverage.

Different policy attempts use distinct actual runs; within one run do not reset player, enemy health/phase or map. If closed bell blocks the kill ray, opening bell by real input first is legitimate and must be recorded, not assumed. Enemy death does not serve as a required air-resource refill or sole landing solution.
