## 1. 高奖同题复考：观察到实质改进，但不是资源连续锁

**工程事实：** 旧 midreview 的 advanced rolled0 是 `recoil_step + remote_sequence`，会在主路刚做过两站位远程双铃后，再做相同 remote 模块。当前审查快照 `_deep_loop` 对 advanced/rolled0 选择 `recoil_step + windchime_rush`，保留原 rolled_variant 与明确选择理由。后者是已有800宽、3秒定时门、130宽缺口的模块，不是把旧双铃换名字。

**实际轨迹：** run_vzsf83hr case5，Seed `level-design-v2-baseline/01`、map2、main_then_high，3898 tick 完成。主路双铃射击在648/795；高奖先在2949跳跃、2967向下反冲、3001落地，之后3083择角射铃、3146跨缺口、3188落地、3262已整体穿过门，3441进入高奖 modal。故玩家从主路的“换站位解决两条射线”进入“反冲攀升，再决定定时开门与跨沟承诺”，动作目的确实不同，M1 的精确重复在这个已观察变体被消除。

**设计判断：** 这是有学习关系的两段组合，比重做双铃更有深化价值；中间稳定落地可作为观察/恢复，没必要为了‘连续’去删除安全区。但3053已站稳、能量100；不能声称两模块具有稀缺资源承接、长空连锁或大师精度。3083到3262的179 tick 也不是玩家容错：门受实际命中时刻影响，driver 有停顿，熟练玩家可以改变输入。最终高收益挑战是否足够精妙，仍需正常速度影片/多策略与真人判断；这一条成功不覆盖其他 rolled variant。

## 2. 外环死端：真实新增了有风险的前向回程；“实际 ferry_dock”在本快照不成立

任务输入曾称“canonical outer area3_3→4_3→4_2 已加实际 ferry_dock”。**工程反证：** 快照 Generator 的 purpose 分派没有消费 `outer_return`；Recipes 虽有 `intent == outer_return → ferry_dock`，该分支没有被新边调用。两份 Scene 和 spatial 原件的真实新边一致为：

- Seed `level-design-v2-baseline`，map2，`plains/passage/area_3_3/area_4_3`，(4140,1210)→(5420,1210)。outer_return=true，但 purpose=`explore_creek_return`，recipe=`double_gear`，动作=`observe_two_phases>hop>recover>second_hop`。
- 紧接 `area_4_3→area_4_2` 是升降机，上升700，汇回已探索准备区一侧。

**实际轨迹：** run_vzsf83hr case3 outer_return，4415 tick 完成。新边2704..3243，540条逐tick记录，约9秒：2704/2733/2762清除区内守卫，2844/2871/2898处理齿轮落点拦截者，3001→3043、3077→3119实际两次跳落。该边开始HP3，未见该边新增玩家伤害。升降回程3244..4178，首末tick差934（935条记录，约15.57秒）；3817登台、3850落到载体，4140跳离、4173落上岸。时间包括本 driver 等相位，不是对人类固有耗时的断言。

**设计判断：** 原度1尾枝已有真正的前向环路：不用原路重复进入边，可经过两相位跳跃与另一条纵向返回。它有不同的风险/时序，不能只用 degree 增加概括；也不能称为已证明更快的捷径、新奖励发现或已经实现的第二渡船。本次仅见保守击杀策略；未证明此边的非击杀替代解。

最小处理有两种，由作者选其设计意图，不能用改标签冒充重测：

1. 若保留已验证的双齿轮回程，修正水路/ferry 的设计说明和 intent 消费，明确它与上侧现有渡船是不同的回程风险选择，添加真实 recipe 语义断言。
2. 若确需下侧水路以减少横向跳跃重复，实际接通 outer_return→ferry_dock，并用新源重新验证同岔口/同汇合的上下路线、渡船支撑/相位、敌人状态与回程。作者正在处理此方向；本报告不预先认可其尚未读取的结果。

## 3. 主路线与构图：现在有可辨认的探索行为；前庭是休息空间，不是狭长回廊

**已有可见证据：** growth 正常画面1680有侧岸箱/敌人与水上路线的关系；1920箱已开、角色回到船上、界面显示+16 coins且HP4/5；2400回到小屋营地并自然恢复到HP5。这比单纯横向走到奖励坐标更能表达“发现→靠岸→取物→返船→回到已知安全地标”。实际完整 growth 轨迹3950 tick 到达，第一侧岸遭遇1185..2084、回营上升2179..2328，后续渡船2793..3713；前后渡船共享操作基础，但首次发现/靠岸与后期遭遇角色不完全相同。这里确有探索内容；不能据一段脚本宣称所有主路都已摆脱空白/重复。

**画面判断范围：** repair1348看到的是开放小屋前庭、商人、安全银行/恢复物和上方平台。它可承担缓压、恢复和方向地标，不能写成已经实现的压缩钟楼回廊。若 RoomIntent/构图叙述仍写‘回廊’，应按真实前庭修正文案；不必为了名字强加顶棚压缩空间。clock840/960显示高入口/攀升角色与落点，extra720是可选额外上反冲，不是主路落点的证明。它们都只是八张指定历史帧，没有看完整电影、没有听音，不签最终Q6。

**保留的质量问题/追问：** 整区的多Seed重复密度、高奖不同变体的真实掌握深度、敌人存活/诱导时路线选择、主路长地面尾段是否承担观景与恢复，仍应由最终真实同源影片与策略复采判断。当前事实支持‘两处反馈已促成可观察的内容改变’，不支持‘整区已足够好玩’。有限恢复区与奖励前期待可以合理存在，不能因空白统计就强塞敌人/障碍。
