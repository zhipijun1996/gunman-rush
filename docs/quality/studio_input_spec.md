# STUDIO-INPUT-01：实际点选武器与巡逻练习敌人

2026-10-14，基线15ddcbf186768381cb577a0d08f54ee5849d4dfa；用户反馈“下拉菜单后，点击武器没有反应。而且这里的敌方怪物为什么不会动？”

旧公开5d30e7185549实测：桌面鼠标可选择激光；手机CDP触屏点击激光项没有weapon_equipped事件，弹出菜单仍打开。此前全部武器验证用键盘导航菜单，仅真实触屏验证了打开菜单和技能/H操作，遗漏了触屏菜单项选择，不得把旧8项外推为全部GUI可用。

本轮只修动作练习消费者：不在每帧重选当前装备，不覆盖打开菜单时的焦点；在原PopupMenu所属Window内处理触屏事件，使普通GUI选择链触发装备与旧实体取消，不直接调用玩法伤害/移动。取消手势不能选装或射击，鼠标/触屏每次合法选择只能提交一次。

四只附近敌人原为明确passive训练靶。改默认巡逻，复用现有EnemyPatrolAI/EnemyMotor和巡逻Definition，不造新AI或修改正式敌人池。新增“敌人：巡逻 / 敌人：静止靶”按钮，切换会明确重启当前武器练习段：恢复本段敌人位置/生命，维持既有练习资源规则，不伪造共鸣。静止靶保留用于可控武器样板，并要求录像/回归明确选择该模式。人物遭遇中的原8敌人与3Boss入口保留。

可证伪验收：鼠标和CDP触屏逐项点选全部15装备，不使用键盘替代菜单项选择，读取已接受装备ID且恰好一次；实际画面定位弹出菜单和动态HUD，不依赖固定坐标侥幸。正常敌人真实Motor改变位置，静止模式不变、恢复后继续运动、暂停冻结；旧全武器2639和动作2932不得回退。修复后导出再GUI串行验证，同冻结CI/source_commit与公开版本一致，保留原失败日志/截图和中间失败。

范围不包含新敌人美术、新正式成长/保存或新地区。实体Android/手柄与用户最终手感未验证，CDP触屏不签真机通过。

引擎根因已核查当前Godot4.7.2对应提交ed1daf0bf：PopupMenu::_input_from_window_internal只处理MouseButton/MouseMotion，没有ScreenTouch分支；嵌入窗口转发的内部输入也被window_input信号过滤。原Window信号/子Viewport push_input尝试均不生效，保留日志。最终本地Node._input接收原触屏，转换菜单局部坐标至根Viewport，再经原嵌入窗口转发触发PopupMenu原生鼠标选择链；只在弹出菜单可见时使用，并处理取消。

附加真实反例：桌面关闭菜单的外侧点击曾泄漏为普通枪射击，关闭时消费当前输入并清理意图；网页touchcancel经4.7.2变成普通release，使用仅菜单范围的DOM捕获回调先关闭/清理，退出场景移除监听。保留本地38/40失败数据，不降取消门槛。实际点选定位改用每项可见radio标记，与邻接灰色背景作对照，避免将窗口边框/阴影算进行高。
