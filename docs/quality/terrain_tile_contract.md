# 可变形状地形：邻接、素材与验收

状态：2026-10-13 用户认可 v5/v8 水粉石灰岩合屏并授权完全接入。此认可不追认被拒绝的边框拼贴、褐土稿或密集花草稿，不替代设备实测。正式接入见 PLAINS-TERRAIN-02。

## 研究依据与适用边界

2026-10-13 阅读以下实现文档，借鉴自动拼接方法，不复制商业游戏素材或假称研究过其私有实现：

- [Godot TileSet terrain](https://github.com/godotengine/godot-docs/blob/master/tutorials/2d/using_tilesets.rst)：区分匹配边、角、边与角的 Terrain Set；变体不能破坏连接条件。
- [Tiled terrain sets](https://github.com/mapeditor/tiled/blob/master/docs/manual/terrain.rst)：两类角标记可有 16 种，混合边角可有 256 种；不是所有规则都能用九宫格覆盖。
- [Blob / sub-blob tiles](https://www.boristhebrave.com/2013/07/14/tileset-roundup/)：单一实体/空域的八邻接可归约为 47 种；四个象限各使用外角、两种边、内角、填充五类局部配置。
- [Unity RuleTile](https://docs.unity3d.com/Packages/com.unity.2d.tilemap.extras@3.0/manual/RuleTile.html)：邻居条件与规则顺序用于自动选择，不等于素材已经无缝。

47 是本次**单一实体材质的局部边界拓扑**，不是所有游戏地形的全集。不同材料相接、悬浮木桥、单向平台、坡面和超出一格的外轮廓需要各自契约。不能用土墙代替应可穿越的木桥，也不能因为视觉裁切改变物理。

## 形状和连接契约

- 基准格 32 世界单位、材质源 4 像素/单位。每格判断 N/E/S/W/NW/NE/SE/SW。相邻两条直边不同时存在时，相应对角位不影响该实体的内凹边界，256 种输入归约到 47 种合法形态。
- 同时支持单格、单行、单列、多行、L/T/十字、台阶、孤岛、内凹角和洞口。不能仅画上边和左右端头。
- 1×1 是完备兜底；1×2、2×1、2×2、4×2 是画面分块，不是改变碰撞的工具。宏块覆盖的每格仍保留自己的邻接 ID；不能跨空格或覆盖洞口。可扩展尺寸，但超出着色器局部预算应拆块。
- 每条接口的坐标、材质相位、笔触尺度、颜色、法线方向与 alpha 约定一致。变体只改变接口保护带之外的内部；不能让多个独立生成的整平台图依靠拉伸、镜像或遮盖“碰巧”拼上。
- 草只沿朝上的外露表面生长；相接内部不重复草帽。左右侧壁、底边与内凹角按同一光照方向解释，不能旋转带方向的完整纹理充当四边。
- 正式地图包含非整格和极薄碰撞体。build_rectangles 在实际矩形并集上裁切，合并共线边界后判断角与预算，不把输入分块当边界；禁止改碰撞对齐网格。超密局部超出预算则恢复基线，不截断边界。

## 当前真实消费者

`resources/art/plains_tile_catalog.json` 由 `tools/terrain_tiles.py` 产生，Godot `PlainsTileComposer` 实际读取并为每个绘制块记录其 mask。手绘母版 `assets/plains_v8/painted_limestone_material.png` 被运行时 shader 共享采样；绘制分块改变不应改变采样相位或显露边界。

入口：Development Demos → Module Lab → More Trials → Terrain Tiles。NEXT SAMPLE 轮换形状、47邻接、非整格样板；MACROS/1x1 ONLY 对照分块。PLAYABLE REGION STUDY 通过实际 PlainsRegionStage 生成与玩家控制对照候选/基线；正式 PlainsRegionStage 默认启用同一表现；开发入口只额外提供旧版对照按钮。几何变化后重建，包括 Boss 延迟破桥；不把开发对照或生命周期 fixture 称为完整路线通关。

当前水粉石灰岩母版已获用户认可。共享边界保证连接的一致性，不能自动保证美感：过硬轮廓、明显重复、糊边、草土比例、手机缩小后的落点辨识必须看实际画面。新变体先做黄金合屏，经用户认可后扩产。

## 可复现验收

| 场景 | 方法 | 可观察通过条件 | 失败 |
| --- | --- | --- | --- |
| 全部八邻接 | 枚举 256 输入及 47 输出，运行时与目录对照 | 合法映射、直边不丢、每种有消费者 | 漏形态、未知 mask、角盖住洞 |
| 小形状及孔洞 | 307 种 1–6 格固定形状，加环与非矩形孔；不同宏块覆盖 | 每个实体格恰好一次，空域保持 | 漏格、重复、填洞、改变几何 |
| 分块不变性 | Godot 同图切换 1×1 与宏块，GPU 截图像素对照 | 地形区域像素保持；UI 标签除外 | 块界细线、草帽重现、纹理跳相 |
| 可见边界 | gallery 单行、多行、L/T、阶梯、洞、孤立列 | 外露边清楚，内部接缝消失，内外角一致 | 接缝凸起、底边当顶边、细块被角片覆盖 |
| 正式合屏 | 实际随机地图、真实角色与镜头，多长度/厚度/相邻模块 | 画面统一、身体与可站面吻合、危险可读 | 仅 gallery 好看、落点偏移、装饰掩盖边缘 |
| 主观及设备 | 用户看黄金合屏、正常速度视频、目标设备 | 有实际认可和测试证据 | AI 自评代签、构建代性能 |

失败保留截图与源版本，回到素材/连接/导入/GPU 对应步骤。自动测试与人工审查分开；不得给“漂亮”编造分数。

## 手绘质量与边界寿命

2026-10-13 用户明确拒绝褐土材质的精美程度，旧 v7 已退出消费者，历史 SHA/原话留在 rework/rejected_meadow_material.json。v8 参考既有背景和主角，使用暖白石灰岩、冷紫灰阴影、黄绿苔草的统一水粉笔触。侧边/底边采样同源手绘边界母版，透明 RGB 以 alpha 隔离；内部与边缘共享相位。用户已认可该合屏风格；它使用共享手绘母版，不能称为 47 张逐张手绘完成品或全形状最终美术。

验收分开：材质与轮廓的精美、连接连续性、同一并集不同作者分块的不变性、实际几何变化同步、目标设备性能。小于支持精度的密集几何、坡面、多材质过渡和机械/单向平台各有边界，不能承诺所有任意几何均完美。普通入口默认使用已认可母版；扩展变体继续遵守接口和合屏验收。

## 复用这次经验：先看世界，再解边界，最后验证消费者

1. **从合屏定义风格**：将当前角色、远景、光照与功能色放在同一参考中；先选清晰的大形、笔触尺度、低噪声配色和材质。地表花草密度、底部轮廓和主体明度要让角色与落点先被看见。精美原图经过缩小、裁切、拼接后可能失败，必须看游戏实际比例。
2. **由物理语义分组**：实心地面/悬浮石台/墙壁共享实体并集边界；可穿透木桥保留单向视觉语义；独立移动物体不与静态地图求并集。所有碰撞、生成和能力要求保持权威实现。
3. **先解完备边界，后画变体**：八邻接归约、四边/内外角、单格单行单列、多行、孔洞和薄体组成最小覆盖集。大素材只是分块；接口保护带、材质相位、尺度和光向不得变化。连接正确、美术精致、实际游戏可读是三项不同证据。
4. **长度与厚度独立变化**：单行并非裁切完整大平台。测试短于两端帽总宽的极短台、1/2/3/多格、半格/非整格长度；厚度覆盖实际最薄体、一行及多行。两端不可重叠或中部重复端帽，顶草/底边需随厚度分配空间；两排相邻台还需检查间隙和可穿越语义。草仅沿外露朝上边生长。
5. **坐标选对参考系**：静态实体共享世界纹理相位，拆合模块应同图；移动物体用身体局部相位，运动时笔触不在表面滑行。翻转后光照方向仍由世界解释，不随整张纹理翻转。
6. **不变量驱动审查**：同一实体并集换作者分块/顺序/重叠表示应得到同一轮廓和像素；加入间隙必须露出空域；破坏或恢复几何后不可留假落点。以这些性质生成反例，用户报告只加入回归样本，不能成为唯一发现来源。
7. **真实 GPU 是独立门槛**：正确的几何数组不能证明实际绘制正确。保留宿主 build_id、日志、截图和正常速度视频；Script/Shader/WebGL 错误、旧资源缓存或同图像素差异都判失败。原生 quad 的顶点/UV 和非整数边界也需实测。
8. **正式晋级不是打开 Lab**：记录用户原话及认可版本；分别检查普通入口、第二图、重开、保存恢复、暂停、移动和破桥生命周期。正式入口不能泄漏开发比较按钮。只能把经证据覆盖的维度升级状态。
9. **失败先归档再重做**：留失败原图及 SHA、截图、版本和退回原因，再生成下一稿；禁止覆盖待审图后复用旧报告。相同代码的新 GPU/设备证据不能被旧版本通过结果代替。

当前可运行命令：`python3 tools/run_terrain_production_tests.py` 验默认两图、移动身体局部材质和薄台；`python3 tools/run_quality_review_tests.py` 验既有并集/分块/破桥；`python3 tools/verify_terrain_tiles_browser.py URL` 验 GPU 分块；正式入口 GUI 另见 `tools/verify_terrain_production_browser.py`。这些命令不自动给美感、真人或设备打分。
