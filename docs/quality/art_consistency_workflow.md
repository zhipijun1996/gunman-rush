# 跨区域与像素美术稳定输出

本说明整理本会话的实际返工，供已有skills共用，填写[Asset Specification](../templates/art_asset_specification.md)即可。它补充执行细节，不取代区域Bible、[共享style-v5](../creative_direction/bibles/style-continuity-20261022-v5.json)、原质量记录或用户判断，不另设审批流程。

## 全局规格、区域身份与资产接口

| 层级 | 固定或声明的内容 | 可以变化的内容 |
| --- | --- | --- |
| 全项目 | 当前项目：地形原生32px/32wu、世界1wu采样/nearest；同屏角色尺度、像素簇/轮廓语言和功能可读性；原邻接、碰撞与危险语义 | 只有明确另选全局画风才版本化调整；其他项目重新声明，32px不是普遍标准 |
| 每区域 | 已选Bible、与共享黄金参考的联系、主材质/生态/形体与情绪、功能色与光色关系 | 石/木/苔/铜的结构、区域色域、空气透视、地标、景深和疏密节奏；不能仅换色，也不强迫每区都有风车 |
| 每资产家族 | 母版、实际用途、源crop、运行尺寸/采样、连接与足点、导入设置、允许变体、实际消费者和来源 | 同母版内的合理形体、尺寸、状态与植生变化；不同体量需求应做对应资产 |

新区域至少把一个代表性正式窗口与现有角色、已采用地形/建筑放在一起看。某个区域获局部认可，不代表全局风格、其他用途或下一批资产自动获准。

## 像素规格要写清四件事

1. **源像素**：画布及有效内容crop各多少px，是否真正来自足够细的母源。文件1024px大不等于有效纹理细，放大16px不能成为新32px细源。
2. **世界尺寸**：游戏中占多少wu，与角色、平台和设施是什么比例。32px/32wu是地形规格，不是把房屋、人物、武器都裁成32×32。
3. **表现采样**：当前世界1wu、nearest；精灵、地形、装饰和背景执行一致的表现尺度。高分源可以通过现有shader在实际显示尺寸采样，源到世界的缩放不必全为整数，但最终像素与运动应实查；不可偷偷吸附Motor/交互坐标。
4. **屏幕呈现**：记录逻辑视口、输出尺寸、相机zoom及放大方式；HUD/字体单独保清晰。1280×720截图本身不证明素材规格一致，随意整屏降采样会丢角色/窗户细节。

导入nearest、压缩、mipmap与atlas透明边要对应实际消费者，不能只检查文件名或metadata。远景的空气感优先来自明度、饱和度、轮廓、细节密度和运动速度，不默认把远景粗粒化；光照平滑与albedo像素语言分别判断，别把所有光晕都强制切成同样的块。

## 地形从同族母版到47邻接

推荐顺序：确定实际比例的材质大形与受光关系 → 同族连续材质面、外轮廓/四边/凸凹角母版 → 明确crop与连接口 → 按原规则派生47邻接核心和精确边界适配 → 组合与正式合屏。

这里的“整套母版”是一致的材质/结构与接口设计，不是生成一张整个随机地图的背景，也不要求AI一次精确画对47个格子。外框/洞口式母版是本轮有效办法之一，不是所有地形的唯一布局。47决定拓扑邻接，不能独自解决重复纹理、长直边、内角体量或材质高级感。

快速检查优先看长短厚薄、凸凹角、孤立/相邻块、单向台、移动承载、转角与非整格边界，再回正式镜头。已有GPU partition/spill等检查在其依赖不变时可保留原来源；新材质/边界/shader改动按影响补跑，不能为了图换碰撞或删旧断言。

视觉返工先看大轮廓、材质块与留白，再看纤维/碎石。前轮通用碎石、重复斜纹说明“加更多细纹”无法替代材料的结构与地区来历；把纹理降对比也不等于解决体量。

## 空间与运动

- 房屋、树木和植生使用可见足点/根/吊点连接真实宿主。逻辑位置接地不等于透明PNG里的可见脚底接地；远处石基或旧桥要避免假落点、假道路、假可交互信号。
- 分清天空/远山、中景地标、近背景和人物前景的职责。地标成组与空旷窗口沿路交替，用构图和视差组织变化；多层数量、到处都有钟塔不证明纵深。
- 前景物件的世界身份、尺度、图样与风相位应稳定；可见度单独变化。不要每帧重排候选、更换尺寸或可见阈值一到就突然画出。完整离屏再回收；回望应得到同一世界配置。
- 关键危险/弹体/HUD必须及时清楚，但整层硬隐藏会闪、局部mask又可能切断长枝。长枝整枝提前避让，草叶局部保护另审；预警、平台边缘、机关和奖励都在实际消费者范围检查。不能一律放大keepout导致前景全无后签“遮挡零”。
- 提前淡化与安全稳定后恢复可沿用现有实现；64wu、0.18/0.3/0.7秒是08当前候选，不是跨区域通用常数。暂停/重复refresh不重复推进时钟，出生/重建/回收也要查。至少证明有非零实际前景贡献，再看严格保护像素及连续画面。

## 一轮快速生产怎样执行

1. 先定位问题属于像素规格、材质形体、根基、光照还是构图/运动，查已有规范与正式消费者。锁住已经选定的粒度；用户只要打光时，不顺带改整套材质/色域。
2. 提交一个可归因的小样：一件家族母版、一个正式合屏窗口，或同源粗细/灯光对照。复用同Seed、镜头、光照与角色尺度；差异和缺before如实写，不堆多套互相混淆的变化。
3. 看正常比例画面，必要时看像素细节；有视差/动画/显隐就录10–30秒真实引擎短片，先做同入口短冒烟。静图不能验证闪现，概念图不能证明正式接入。
4. 局部成立后再扩到该家族和另一类空间，补目标随机图/Seed/高低处/回程；每次只跑改变影响的必要检查。完整集成/发布守门保持，快速实验不反复跑整套CI。
5. 保留母版/派生/提示词/参考、许可、crop/锚点、工具命令、实际源与消费者、失败及改正关系。来源未知不补造。技术通过、AI视觉意见、用户认可与设备体验分开写。

只观察即可判断的变化交短片及真实下载链接；需要操作的交准确版本可玩Preview。看图网页不当试玩，托管成功不当全区完成。交付优先让用户看到这轮唯一有效的变化，证据不要淹没评审入口。

## 后续任务可直接使用的简短输入

“基于当前style-v5与【区域Bible】，保持共享像素/角色尺度，设计【区域/资产家族】。区域变化是【材料、形体、生态、光色、情绪】，参考【当前母版/正式截图】，排除【不想出现的元素】。先做【一个正式窗口/一件家族母版】及必要10–30秒实机短片，确认空间用途后再扩产；填写现有Asset Specification，保留来源，不重跑无关CI。”

括号字段由任务上下文/已有Bible补齐；普通细节由实现者判断，只有关键缺失信息才问用户。生成工具不保证每次审美一致；稳定性来自明确规格、正确参考、同族派生、实际合屏和有界反馈，而非一条很长的Prompt。
