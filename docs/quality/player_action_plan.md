# 人物动作、动画与特效开发规划

任务 ACTION-DESIGN-01；日期 2026-10-13；范围为设计收录、skills 补充与 harness 规划。设计依据见 [入口](../design/player_actions/README.md)。本文件不提供新动作的运行 PASS；以下新专项全部 planned，不向现行 harness 注册空检查或永远通过的占位器。

## 1. 当前基础与范围

当前 InputRouter 支持 jump/jump_release/shoot_release/interact/drop_through，ShootAbility 是基础单发，PlayerMotor 是唯一运动结算。CourierVisual 有 idle/run/jump/fall/recoil/hurt/death，实际手绘六状态，hurt 复用 recoil。已有脚底/枪口、事件、暂停和死亡回归；没有六武器阶段、H/W 专项及羽翼 D 的完整覆盖。Foundry 的开发二跳是容量配置，不等于正式二跳授予和羽翼表现；hook 为未实现。

单武器：每个角色仅一个当前武器运行实例，六分支为不同配置测试，不做六武器同时装备的笛卡尔积。同武器攻击包可含多弹体；分支规定的普通/强化刃与雷实例互斥必须分别测。角色是否局中换武器仍待定，规划生命周期验证不等于授权添加换枪按钮。

先盘点角色 ID、场景路径、能力/武器消费者、当前素材与正式/开发入口。首个可核实主角为 Courier；多个可玩角色如后续确认，逐个加入 inventory。敌人和 Boss 验证各自移动/预警/攻击/受击/死亡与武器交互，不强制他们具备玩家武器和 H/W/D。不能用一个主角样板外推“所有人物完成”。

## 2. skills 工作分工

| 主导 skill | 必须提供的交付物 | 协作与边界 |
| --- | --- | --- |
| game-quality-gate | 单一任务记录、依赖、范围与消费者清单 | 各专业证据写入同一记录；不得把规划标成内容完成 |
| player-creator | 角色动作清单、组合/转换矩阵、身体与手臂/武器/能力附件的表现所有权 | 复用唯一 Motor；主角与敌人/Boss 分开盘点 |
| weapon-creator | 当前单武器 Definition/Runtime 契约、攻击包、阶段、输入用途、资源和取消表 | 三 Lv.1、六 Lv.2 逐条验证；Lv.3 候选先做对照原型 |
| ability-creator | H/W/D 状态、资格/重复接触、Motor 仲裁、授予与撤销 | 不通过 max_jumps 或标签冒充完整能力 |
| animation-vfx + art-director | 动作姿态、转换、中断、锚点、事件时间轴、素材来源、音轨和峰值预算 | 按动作选逐帧/骨骼/程序方法；未采用骨骼也能完成，不强制淡入淡出 |
| level-module-creator + region-generator | 分支专属 action driver、机关实轨、能力锁正例/反例和多 Seed 证明 | 布尔路线搜索与真实物理可达分开 |
| gameplay-reviewer | 正常速度连续音画及正式消费者审查、失败复现与范围结论 | 独立性不足写 self_review/unverified；不得自签玩家认可 |

复用现有 skills，新增专用 [动作覆盖卡](../templates/player_action_coverage.md)；没有必要再建同义总流程技能。自动选择 skills 不等于启动子代理，本规划不启用子代理或自动生产循环。

## 3. 动作与转换覆盖

每条动作应记录合法初态→真实输入→接受/拒绝→玩法阶段→运动/伤害/资源→动画/声音/特效→结束。优先级由明确状态表和正式消费者实现，不依赖节点顺序。动作阶段是权威，表现只订阅已接受事件；动画不能写玩家位置或补发伤害。

| 动作组 | 必须覆盖的阶段和反例 |
| --- | --- |
| 基础移动 | idle↔run、短/长跳、上升↔下降、落地、朝向切换；低顶/单向面/移动平台 |
| Lv.1 三家族 | 起手→攻击提交→实际弹体/爆炸→反冲→恢复；未命中也有规定的有效自运动 |
| 三连枪 | 包开始→三次真实发射与转瞄→结束；后两段不得开新包或重复扣费/返还 |
| 激光 | 开始→持续转向/伤害/推力→停止；松开/取消后无隐形推力或持续刷能 |
| 散华 | 三飞刃→第一闪→第二段短闪改向→恢复；全过程碰撞，不能变第三闪 |
| 回旋 | 投出后闪→实体控刃→直线召回→真接刃推动/接刃失败→可用；不瞬移/穿墙 |
| 磁雷 | 合法附着→人物自由移动→遥爆→范围内借爆/范围外不推动→释放；不免费第二雷 |
| 奇点 | 玩家当前位置生成→固定/牵引→方向预览→定向弹射→恢复；伤害/移动平台/无方向反例 |
| H | 起手→射钩→飞行→命中→拉近→踢跳→恢复；落空/阻挡/目标死亡/锚点消失 |
| W | 附墙缓降→蹬出→确实分离→有效重新接触→可再次蹬；同墙/双墙/危险墙，不刷二跳/弹药 |
| D | 合法第二跳→羽翼展开/下扑/散羽→回到空中姿态；耗尽拒绝/授予不补资格 |
| Lv.3 六主动技 | 候选定稿后各自起手/蓄势/释放/强反冲/恢复；Lv.2 普攻 A/B 不变、缺能量无释放 |
| 中断与收尾 | 受伤、死亡、暂停、失焦、慢时、回退、离场、升级/撤销；各动作阶段触发，不残留旧效果 |

全覆盖有限状态/转换的合法与拒绝边界；按风险补关键组合，不穷举无限连招。至少验证跑跳→当前武器反冲→落地、W蹬墙→反冲→同墙重贴、H踢跳→反冲/二跳、控刃时人物继续移动、奇点固定被环境移动、Lv.3技能→恢复Lv.2普攻。不存在能力的组合明确拒绝，S2 单能力挑战独立配置，不默认 H/W/D。

身体运动姿态与上身/武器动作能否叠加逐动作决定；奇点固定、拉近、受击等可覆盖部分层。定义每次转换的入口姿态、关键锚点、可中断点、恢复目标与有限例外。不能把所有动作换皮成同一个 recoil，不能用增加帧数代替自然衔接。

## 4. harness 专项规划

以下 ID 为待实现检查名，不是当前可执行命令。真实 runner、超时、完成标记和负例就绪后，才在 `tools/harness/profiles.json` 注册。复用现有 gameplay/art/web 和唯一检查定义，不建立平行 harness。

| 计划检查 ID | 测试入口与实际断言 | 证据 / 接入条件 |
| --- | --- | --- |
| action-inventory | 实际角色实例/注册分支/正式入口与覆盖卡逐项对应；漏动作、错消费者、旧素材不能算覆盖 | inventory 与缺项报告；先实现，接 docs |
| action-input | 三端适配器→Router 的同意图结果；primary/context/grapple/skill 与 aim mode、jump hold、capture、取消；控刃/奇点松杆不射击 | 输入/意图轨迹与拒绝原因；接 gameplay；浏览器适配器与真机单列 |
| action-runtime | 正式组件驱动阶段，唯一 Motor，每tick最多一次运动；反冲方向/时序、墙/顶/窄缝/移动平台、30/60/120Hz | 轨迹、碰撞和运动次数；接 gameplay |
| action-resource | attack_packet_id、有效 DamageResult、shoot/combat 能量独立、包内限额与共享原子扣费；同帧竞争/重放/失效 epoch | 账本与重复/无效命中反例；接 gameplay |
| action-lifecycle | 各阶段暂停/死亡/回退/离场/撤销；单武器所有权，旧刃/雷/技能回调无污染；U1分支/U2进化及实际存档消费者 | 取消与节点存活轨迹；接 gameplay；未接正式存档不能标通过 |
| action-presentation | 真实输入及接受事件驱动正式表现；转换、脚底/握持/枪口/钩点、弹体首帧、方向预览、特效起止/音频事件 | 帧号↔tick↔事件ID；接 gameplay+art；GPU/音轨连续捕获另验 |
| action-capability-lock | S2唯一能力/水钟六解、无敌断桥、Boss；S4 OR每解/S5双硬锁正例；欠缺能力及强武器越锁反例 | 多Seed/相位、资源与真实输入回放；接 gameplay；搜索结果不当通关录像 |
| action-budget | 同武器最大并发、六Lv.3与高密度战斗，节点/粒子/声音回收、帧时间 | 宿主及物理设备测量；阈值按目标设备试调后约定，未测不通过 |

每项都需要故意失败样本证明 runner 会报非零；动画专项须能拒绝遗漏转换、特效早于接受事件、错锚点、旧 epoch 和错版本。不删除旧断言或放宽基础物理。数值预算由真实配置/Definition与G0设备目标决定，规划不虚构阈值。

**现行可执行检查**：`python3 tools/harness.py --profile docs`；后续运行变更执行 gameplay，素材接入执行 gameplay+art，Web交付补 web 和实际 GUI。全部已有 profile 通过也不能算新增专项已覆盖。

## 5. 回放、录像和验收证据

扩展 Foundry/动作试验场时，记录角色/武器家族、tier、branch、behavior_version、H/W/D、次数/能量初态、配置/素材/输入档案版本、Seed/Manifest、actor/run/stage epoch及两个时间轴（物理tick与实时）。每帧记录 move、aim direction/mode、press/hold/release/context/grapple/skill/cancel；当前仅 axis/actions/position/shots 的回放不能证明控刃/奇点/技能完整行为。positions 是对照结果，不用于搬动玩家。

为每次攻击记录 packet/事件/资源事务ID、阶段接受或拒绝、运动请求、碰撞、DamageResult与视听起止。生产 basis 必须纳入新增武器/能力/能量/输入代码和配置；动画证据另含素材与表现代码指纹。旧回放不能因游戏变化沿用 PASS。

录像由同一输入回放或真实操作驱动正式实例，包含正常速度、音轨、HUD资源和可关联的输入/事件时间轴；逐帧图只用于定位。每条边界无需都录长视频，但每个武器/能力阶段、关键转换和代表中断必须对应连续证据；不足者标 unverified。脚滑、枪口漂移、动作突变、音画错位、落点遮挡分别记录，不只报截图或帧数。

自动检查证明资格、状态、资源和事件一致性；GPU输出检查客观表现约束；连续音画审查判断动作自然与可读性；实体手机/手柄测试证明实际输入与性能；用户反馈证明认可。四类证据不能互相替代。实现者自检不写 independent PASS。

各 ID 同步 [tasks](../tasks.md)，本轮只交付 ACTION-DESIGN-01。具体实现时给对应内容建立 player/weapon/ability/animation 记录，不复用本轮 process 记录签内容完成。

| ID | 顺序与范围 | 退出条件 |
| --- | --- | --- |
| ACTION-INVENTORY-01 | 盘点 Courier及真实人物、动作/转换、单武器与正式消费者 | 每个动作有实现/素材/覆盖状态，缺项明确，不臆造多角色 |
| ACTION-INPUT-01 | 统一意图/模式、三端候选操作原型 | 三连/激光/控刃/奇点/H等代表模式无误发；实际设备仍单列 |
