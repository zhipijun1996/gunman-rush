# FOREST-GRAPPLE-02 independent initial diagnosis

Reviewer: `/root/experience_audit`, independent read-only production review. Baseline: `6c61faadd511c48a267b975550da897e701fd09f`, default `forest-expedition-airborne-v11`. This diagnosis reads the baseline source; concurrent working-tree changes are not accepted by this document. No gameplay, pixels, audio, or physical device have been observed for this new task yet. Design recommendations below are hypotheses, not a claim that players find them fun.

## Findings

**EA-01 — Downward edge pull terminates on valid floor sliding.** `TraversalAbility.after_move()` cancels whenever there is any slide collision and the target remains more than `hook_stop_distance + 2` away. A standing diagonal-down pull necessarily contacts its support before the whole body clears the edge. `PlayerMotor` can still advance horizontally along that support, but this code does not distinguish useful progress from complete obstruction. A collision count alone therefore does not establish the comment's claimed “collision that prevents approach.” Fix through collision-safe real Motor movement and bounded progress detection; do not disable collision or move the body directly. Required evidence: left/right edge approaches, downward diagonal angles, broad platform approach, solid wall blockage, and timeout/cancellation.

**EA-02 — Near-vertical hooks choose a discontinuous lateral kick.** On contact the old implementation uses `sign(hook_start.x - hook_tip.x)` and an exact-zero fallback based on facing. Tiny changes in aim, capture position, or target motion can therefore select opposite full-strength horizontal kicks. This is a source-level discontinuity, not evidence that every reported unstable jump comes from it. Compare a small explicit vertical cone with a continuous angle-dependent horizontal kick; preserve intentional diagonal side-kicks needed by existing air routes. Verify mirrored approaches and small offsets, actual kick displacement, ceilings, shot interruption and second-hook timing. Existing ring/contact geometry and real body collisions remain relevant.

**EA-03 — Desktop/controller grapple aiming has no aiming interval.** PC right/E and gamepad LB request grapple on press; their grapple branch explicitly reports `aim_engaged=false`. Merely changing the tuning value to `.15` would give neither input scheme an airborne H-aim slow interval. Hold-to-aim/release-to-cast, with a fast tap preserved, is coherent with touch aiming and the new request. This is an explicit control-contract change requiring real input regression. H aiming should own the aim mode and suppress crossed primary releases. Cancel/pause/focus/device change must disarm without casting. LB release must use the last meaningful H direction when the stick centers on that same frame. An unavailable H must not capture gun input.

**EA-04 — Hang rings need a separate interaction contract.** Existing generic anchors always proceed through a brief contact stop to a kick. A new ring should visibly distinguish holding from bouncing. Hanging must remain actual collision-checked arrival and reference-following, not snapping through a wall. Define jump release, accepted shot release, refire to another target, cancellation, death, target invalidation and obstruction. Do not restore ammunition, focus budget or ground-jump resources solely because the player is hanging. H refresh is separately necessary to permit a deliberate next hook and must not imply a hidden landing. A rejected shot with no resources must not be reported as a successful recoil exit. Ring movement and blocked following need bounded behavior rather than teleportation.

**EA-05 — The ordinary forward bypass is intentionally produced.** `ForestExpeditionLayout` explicitly records `ordinary_lower_route_retained=true`. Map 2's fast prefix takes `grotto_eastward` and `undergrowth_to_old_root`; it does not take the western aerial content. `western_root_eastward` traverses approximately 2280 world pixels with three ordinary jump steps across broad root/log supports. These facts support the user's structural diagnosis. They do not independently measure real interaction-free seconds or establish a player success rate.

**EA-06 — Optional extra air modules cannot fix a weak mandatory journey.** v11 labels aerial edges `optional_lower_alternative=true`; the high-action bridge is not itself proof that the main expedition expresses H. A new vertical backbone should make meaningful H combinations part of forward progress while broad recovery roots lead back to challenge entrances. Recovery should not silently carry the player to a later goal. Prefer distinct legal combinations and readable landing choices to an invisible ability check, mandatory target identity, tiny platforms or dense spikes. Keep observation/recovery purposes; not every safe surface needs pressure.

## Alternatives and selected direction

1. Keep instant grapple and add isolated hard branches: minimal disruption, but fails H-aim slowtime and leaves the low-action primary route intact.
2. Make every current connection a long scripted air chain: increases nominal action counts but risks fatigue, resource dead ends and repeated identical choices. Reject as a general policy.
3. Repair movement feedback, add explicit hold anchors, and make a vertical route network whose short forward transfers require meaningful two-action relationships, interspersed with optional longer chains and recovery returns. This best addresses the current request; its quality is conditional on real trajectory and visual evidence.

## Evidence admission for the implementation review

- Freeze exact implementation source and actual consumer identities before review. Old `.20`/old-kick trajectories cannot certify changed H physics or `.15` aiming.
- Capture actual accepted actions, target at pull/contact, body trajectory, support contacts, resources and result; an input request count or planned `action_program` is insufficient.
- For claimed two-action passages, try strong jump-only, jump+recoil and no-H strategies from realistic takeoff positions. Removing H only from the intended driver is not a strong no-H counterexample. Describe bounded searches honestly; do not claim universal impossibility from a few misses.
- Continuous air chains must have no hidden landings. A hold-ring pause is airborne attachment, but should not be described as uninterrupted motion. A route that can delete a step and reach the same goal more directly should lose the redundant step rather than preserve a count.
- Verify representative errors and recovery, real adjacent terrain/other anchors, dead or displaced living targets, low resources, both maps, and actual forward-versus-recovery topology.
- View normal-speed actual pixels, including vertical camera anticipation, ring differentiation, target readability and exits. Technical acceptance cannot sign user handfeel, fun, entity-device input or commercial visual quality.

Initial verdict: **REVISE** for baseline design/behavior; new implementation **UNVERIFIED**. No production changes or tests were performed by this reviewer for this diagnosis.
