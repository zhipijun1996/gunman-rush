## Findings and bounded rework

**EA-07: Three translated shafts repeat the actual solution.** Formal07 legs 1, 5 and 11 each take 159 captured ticks. Their actual contact schedule relative to each leg is identical: first pull 24/contact 30, second pull 56/contact 65, recoil 80, final pull 100/contact 109. All use the same local factory and H→H→R→H relationship. The observation is stronger than merely counting repeated IDs: the actual driven solution has identical timings and decisions. Retain the root shaft as learning; an upper reprise can be reasonable, but the middle duplicate needs a different movement problem. A mirror, new label, more HP or different numeric height alone would not resolve this finding.

**EA-08: The new region prefix is one mandatory sequence.** All five route labels share the same 16-edge prefix before reaching M. Within this prefix the random choice swaps lower and upper HH/RH variants; it does not change the sequence in which meaningful goals are discovered. The old tree still contains branches, but the new large space itself does not yet provide a new exploration network. Do not present five route names as five distinct journeys through the new trunk. A future optional live branch should change a goal, risk/reward or solution choice and reconnect meaningfully; it need not be added as metadata merely to improve a count.

**EA-09: A future catch is a potential early no-H staircase.** In formal07 the middle shaft's standalone catch is `[-2005,2018,1190,40]`, only 400 feet-world-pixels above the starting support top at 2418, and approximately 200 pixels to the right. Its recovery step is at `[-2000,1916,65,20]`. The measured standalone strong two-recoil trajectory rises about 455 pixels. Therefore an early jump/two-recoil landing on that later catch is a concrete shortcut candidate that should be tested, rather than assuming graph prefix order enforces movement order. This has **not** been reproduced by an actual counterexample in this review and must not be stated as an already proved bypass. Deleting the middle duplicate and that exact catch, as proposed, makes running an old-design proof unnecessary; new final neighbors still need their own no-H attempt.

The implementer's bounded replacement proposal uses a proven narrow thorn-mouth H→R factory in place of the middle shaft, with the remaining root/upper shafts retaining over 1100 pixels of vertical ascent. This changes the relationship from successively reaching higher targets to controlling a sideways passage between visible boundaries. It is accepted as a design direction because it reuses a tested distinct interaction and removes the exact EA-09 catch candidate. Its proposed earliest future catch is 480 pixels above the new entry, only 25 above the observed 455-pixel two-recoil trajectory: that numerical margin is not universal impossibility proof. Actual early/late takeoff, legal recoil timing and realistic horizontal movement still need bounded adversarial tests against all neighboring supports.

**EA-10: Hold rings remain optional side observations in this capture.** Three real hold rings are assembled, but there are no `hook_hang` events in the fast route. This is not inherently a defect: optional observation/recovery is useful. It does mean the route does not prove that hanging adds a meaningful route decision or makes the continuous chains more readable. Do not force a stop merely to demonstrate a feature. A useful alternative is a visible side observation position that permits a different recoil/H exit and rejoins the same receiver, if it can be validated without a new resource refill.
