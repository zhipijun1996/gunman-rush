## Source reasoning and author evidence

`PlainsRegionGenerator` accepts only the current fingerprint or the single known pre-focus fingerprint and reconstructs the complete expected generated manifest with the selected supported content mode. DemoApp tries a finite sequence of supported mode/fingerprint combinations and binds only an exact saved map hash. It fails closed if no complete map matches, rather than clearing claims/actors or accepting an arbitrary imported hash.

`RunManifest._region_tuning()` rebuilds allowed item modifiers from actual item resources, requires exact tuning-key cardinality, and compares every stored tuning field against the resolved profile. Its `.20` exception requires the exact known old map fingerprint. Freshly recording an old saved map with current `.15` is legitimately accepted; this is not a claim that all old metadata must be rewritten to `.15`. A current v12 map cannot obtain old `.20` merely by changing its claimed hash because strict generator reconstruction still rejects that layout/fingerprint mismatch.

The historical forest producers change only their recorded generation fingerprint source, preserving old generated geometry/hash bytes. This fingerprint describes generation, not old runtime aim or grapple code. The new frozen v11 producer and the older v7/v9/v10 registry cases remain separate from current v12 generation and current playable-trajectory admission.

The author's final `aim_save_compat04` log and JSON were inspected: **122 / 0**, four actual v3/v11 map cases, six invalid-state loader cases, immutable historical metadata and seven tamper classes, real enemy-health and player-health/item persistence across reload, and clean teardown. These are author executions, not independent executions. The original archived two-Plains-stage prefix is actual historical RunManifest evidence. The forest `.20` historical metadata cases are constructed around independently verified actual v11 map fixtures; they are not presented as an original complete historical forest-run save.

## Scope limits

The project has no complete historical whole-run resume API. The checks cover immutable manifest parsing, serialized saved map-state fallback, current runtime focus and actual reload persistence. They do not certify a complete campaign resume, all historical Seeds/content revisions, changed grapple motion on old layouts, normal-speed readability, device behavior or player handfeel. No new incompatibility was found within the finite reviewed profile set. Later changes to these production sources require rechecking the affected scope.
