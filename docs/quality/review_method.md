# 通用游戏审查方法：从契约推导反例

审查输入是玩家目标、系统契约、实际消费者及运行版本。用户报告用于检验发现覆盖率，不能成为唯一检索词或把若干问题直接变成规范。先独立采样形成发现，再和反馈对照；已知反馈不能宣称盲测发现。记录未观察范围和主观待审，不许以“没有查到”推导没有缺陷。

## 推导顺序

1. 为对象写“向玩家承诺什么”：可站立/阻挡/可穿越、可伤害/可受击、背景/交互、移动支撑/自由运动、预警/有效/恢复。追踪实际正式消费者，不能停在组件定义。
2. 对每个承诺建立**空间×状态×时间×消费者**矩阵。覆盖长短厚薄、正反朝向/接缝/邻接、资源/能力边界、开始/稳定/中断/恢复/销毁，至少正式入口和一个最不同的开发消费者。
3. 选代表和极端样本：同一条件改一个变量、最坏相位、动态支撑、多个对象组合、另一 Seed/区域/输入设备。先观测再下结论，不以源码中存在函数当运行通过。
4. 用下面不变量提出正反例与变形测试；记录世界坐标、碰撞/图像、状态/事件、正常速度录像及玩家实际操作。失败保留，修复再运行同类横向扫描。
5. 独立报告分别列：客观矛盾、设计价值缺失、主观待认可、未验证。复审以冻结提交和原始证据为准；开发者自检不填独立通过。

## 可迁移的不变量

| 维度 | 核心问题与推导方法 | 反例方法与证据 |
| --- | --- | --- |
| 空间与素材拓扑 | 实体边界、支撑面、可达空间是否与视觉承诺一致？端头是否只出现在真实外边？ | 同资产改变宽度/厚度/位置/镜像/邻接；检查裁片连续覆盖、内部不重复端头、可见实心与碰撞差异；真实运动穿越边界 |
| 材质与构图 | 同类物件是否处于同一视觉世界？装饰有支撑/生长/建筑关系吗？功能层次是否稳定？ | 同对象跨深度/区域/状态/Seed 对照；检查光源/色温/透明度语义、根植点、间距/聚簇与留白；合屏而非独立原画 |
| 动作与参照系 | 输入/实体/动画/镜头是否共享正确的时间和运动参照系？ | 同一相对动作叠加支撑平移/旋转；比较相对构图，测试接触/脱离/反向/暂停；区分普通缓冲和共同位移 |
| 战斗模态与公平性 | 所有实体对接触/弹体/区域/护甲的接受或拒绝是否有统一且可读规则？ | 实体×模式×伤害来源×消费者矩阵；真实接触/弹体，检查安全窗口/无敌帧/判定位置/同帧死亡；拒绝须反馈，不能凭空重置危险 |
| 时间与生命周期 | 暂停/菜单是冻结，还是改变挑战？退出是否取消，恢复是否保留？ | 在每个阶段暂停/菜单/死亡/回退/重载，比较无中断与中断后的有效时间线/资源/掉落/请求；不得通过反复中断刷安全窗口 |
| 语义与演出 | 重要事件是否有准备、发生、收束和控制恢复？是否传达角色重量与机制？ | 正常速度整段及打断/跳过/重复；检查音画时序、锚点、对象上限、UI/镜头遮挡；贴大图/闪一下不是完整演出 |
| 内容与决策 | 内容改变的是玩家判断还是仅名称、数值和图像？不同机制可被及时辨识吗？ | 记录实际动作/反制/风险收益签名与轮廓/预警对应；统计遭遇分布和重复，观察三种真实路线，不按敌人数/Seed 数量评分 |
| 覆盖与集成 | 测试是否覆盖实际消费者、被绘制的函数和运行配置？ | 追踪调用链到输出；为测试制造会破坏契约的隔离变体，确认能拒绝；纯辅助函数通过不能代表真正渲染/玩法通过 |

## 从真实动作空间产生候选

在编排现有模块之前，先从实际Controller／Motor／Definition读出动作的前置状态、运动约束、终止位置和余速、下一动作何时恢复。恢复结论要追到完整生命周期的写入者：请求检查、物理到达、接触收束、成功／失败回调与落地，而不是只读入口条件。区分“目标被钩头碰到”“身体抵达”“动作额度恢复”“命中退款”的各自提交事件；调用不同资源账本的同名hit不视为同一种退款。先用一个真实成功与一个被实体截断的失败轨迹核对此表，再据此排多动作链。将入口姿态与空间方向交叉：站立／起跳／下落／接触后，前后／上下／斜向；再组合一项会相互改变结果的动作。不是把所有格子做成固定模块，而是寻找两种动作单独做不到、组合后才产生的选择。

参数须追到所选动作／装备分支实际读取它的位置，并核一次真实运行值；同名Definition字段、配置默认值和未使用的设计参数不可互代。由“释放输入”推导动作结束也须核消费者：最短按住时间、持续施力时间和松键截断余速是不同条件；驾驶应表达玩家意图及真实终止状态，不能把一个计时常量当作已到落点。

对每个有希望的假设画完整身体的轨迹与可见观察位，指出哪里作决定、哪里不可撤销、失败落到哪里。先估算射程、碰撞、输入锁与恢复余量，随后用真实帧验证；若概念不符合当前物理就换假设，不修改能力让草图成立。入口、目标和出口之间的关系比模块外形更重要；放大、镜像或多放一个台阶不自动带来新动作。

同一批内容横向比较实际玩家动词：两个Boss若都“等锁定→躲扑→追收招”，纵使模型／弹体／阶段不同，仍需要探索另一套交互；两个敌人若只改变冲刺速度与血量，优先复用已有配方，而不是新增生态类别。此比较应在批量实现之前，也在真实对照推翻假设后进行。

## 黄金推广前：玩法假设对照

技术接入正确后，先问这个机制是否值得推广。作者在现有设计卡写至少两个会产生不同判断的候选和保留旧方案，选择其中一个做最小黄金；写清它可能输给哪种便宜打法。不同作者在黄金阶段比较以下三类证据后作继续／修改／淘汰判断，作为原生产循环进入整合的前置，不能把最终G5未验当作跳过机制审查的理由。

| 对照 | 必须保持的条件与实际观察 |
|---|---|
| 目的打法 | 从可读观察到承诺、修正、收益、恢复，指出正常速度片段中哪一次选择有用；真实输入与接受事件分列 |
| 最便宜的退化打法 | 同入口、构筑、资源、相位和伤害下，实际尝试站桩／地面微移／无脑重复／先清光目标等适用策略；不能专门把它驾驶得很差 |
| 关键动作或对象消融 | 在同一空间中去掉关键动作／目标关系，区分入场能力锁与机制本身的价值；保留公平的替代策略与失败恢复，不人为制造伤害或禁掉其他合法动作 |

分别报告可达、伤害、输出机会、资源、无效等待、回程劳动、容错与读信息负担，不加权成乐趣总分。一个耗时差或动作次数差不自动证明更有趣；有限驾驶失败也不证明所有合法策略都失败。若旧策略在所有有意义选择上支配新策略，或删动作后玩法主体不变，退回设计／淘汰，不能靠加血、缩台、缩窗口继续包装。允许强玩家找到少用核心动作的替代，审核的是正常学习和掌握过程是否有独特收益。

便宜打法不能只从作者指定的起点测试。按真实稳定支撑、遮挡与攻击覆盖找持续有效的站位，检查角落、上下层及一次简单躲避后继续射击；也检查增加障碍后产生的新驻射点。安全观察位可以保留，但若它同时让玩家全场持续输出而无需回应机制，应先改空间／交互假设，再扩大血量和阶段；普通跳跃或少用特色能力的熟练解本身不是失败。

保留源／能力／原始轨迹／完整片段、候选的原拒绝和修改因果。共享底层组件不构成同质化，换名、参数、阶段编号或Hash也不构成差异。专家必须给可观察理由，仍不代签玩家认可。此方法同样用于未来冰川的摩擦选择、火山的危险相位和遗迹的路线机制；不要求它们使用森林钩索或同一几何。

FOREST-DEPTH-02的来源是旧两Boss共周期、旧实弹驾驶不使用H的可核反例；其旧技术通过仍有效于原声明范围，不能倒造过去做过这些对照。

## 发现记录格式

每项填：通用规则 ID、实际样本/基线、场景及复现、预期承诺、观察矛盾、证据、严重性、影响消费者、修复层、对照重跑、剩余范围。新缺陷一般归入已有维度；只有出现新的原理性缺口才修改规范，不把每个坐标/敌人名写成长期规则。

测试允许专门保留已发现缺陷的回归样本，但审查规范必须能发现未知同类问题。自动几何/状态检查、AI 视觉审查、独立审查与玩家认可分开记录；任何数字不能替代美感/趣味判定。

## 消费者覆盖闭环（G2/G3 退出条件）

“空间×状态×时间×消费者”必须落实到可核对的范围，而不只是写在流程中：

1. **先盘点再选样本**。从实际正式实例、运行配置、分支和回退路径导出 inventory；记录枚举范围、版本、实例数及调用路径。区别材质/碰撞语义是分类依据，不是排除依据。未改动的消费者仍可能违反此次承诺。
2. **逐项闭环**。新正式任务填写 `consumer_coverage.scope / inventory_evidence / observations`。运行 inventory JSON 含 `consumers: [{id, ...}]`；observations 对每个 ID 恰好一行，写 `consumer / output(visual或behavior) / status / reason / evidence`。视觉 passed 必须引用带同一 consumers ID 的实际截图/GUI/录像；行为使用实际运行轨迹。命令通过或未使用的 helper 不能签像素通过。not_applicable 必须是有理由的范围排除，不能被算作已验。
3. **画面覆盖与实例覆盖分开**。枚举所有实例只证明路径；代表样本的真实画面只证明观察到的尺寸/状态。分别列明；某分支无画面即 unverified，不把入口截图外推全地图。旧记录保留历史，不据新规则追造原始证据。
4. **验证门槛能失败**。在隔离 fixture 中保留错路径/漏消费者/旧表现负例，确认同一判据拒绝；修复后同版重跑。不能只测试新 helper。已知问题的回归不冒称自主盲审发现。
5. **声明范围守恒**。交付文字只能覆盖已验 scope；“整个地区/全部平台”等全称需要对应全消费者证据。保留玩法语义不等于保留旧表现免检；用户认可某母版不等于认可所有消费者。

`tools/quality.py` 校验新记录的对应关系和证据归属；`tests/test_consumer_coverage.py` 包含漏项、helper 冒充、错场景、旧版本及重复项反例。静态校验无法判断 inventory 是否真实完备或画面是否漂亮，仍须审查源调用链和实际输出。
