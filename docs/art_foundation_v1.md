## 新视觉语言的最小设计卡

首轮采用原创、轮廓明确、色块整洁的风格化 2D 候选。此描述是制作起点，不是最终审美签收；不预设必须像素画、矢量画或写实手绘。

| 项目 | 制作约束 | 现场失败条件 |
| --- | --- | --- |
| 形状 | 玩家层由统一网格构造，主要形状简洁；表面少量细节 | 装饰伪装成可站立平台，或背景边缘与落点相同 |
| 层级 | 玩家/危险/机关优先，实体边缘其次，背景与装饰退后 | 缩小后看不清落点、弹体、敌人预告 |
| 材质 | 每个家族统一边缘厚度、纹理尺度、配色与光向 | 同一家族相邻 tile 像不同图片拼贴 |
| 变化 | 几何形状由 mask 决定，内部纹理变体克制且可复现 | 变体改变轮廓、遮住边界或制造假裂缝 |
| 细节 | 成簇出现，留安静区，密度服从玩法空间 | 每格一丛草、等距灯串、满屏高对比小物 |
| 光照 | 统一环境光；局部灯有明确光源，色彩数量受控 | 发光覆盖危险提示，实体边缘过曝或淹没 |

每个新家族附一张设计卡：`family_id/version`、用途、主辅色、轮廓与边缘厚度、纹理尺度、光向、功能语义、可兼容家族、禁用组合、来源/许可与目标显示尺寸。先做一个家族，独立验证后再添加第二个。

## 网格与资产规格

首轮试验基准为 **32 × 32 世界单位/格、64 × 64 px/源 tile**，即 2 源像素/世界单位。它是新内容制作与试验场基准，不授权把正式碰撞四舍五入或修改 PlayerMotor。现有正式关卡需要显式转换方案和真实操作复验后才能迁移。

- 格坐标为整数；世界原点、格尺寸、图集尺寸和缩放由实现中的唯一配置提供，消费者不复制默认值。
- 每个 tile 对应一个固定格。输出透明、无外侧多余底色；过滤、边缘出血、像素对齐与缩放在实际渲染器中明确选择和验证。
- 图集以显式 `mask → atlas coordinate` 表为权威；布局可以替换，不能根据“看起来像第几块”硬编码。构建输出可含所有 47 个 canonical mask 的标号预览和 atlas 来源记录。
- 邻接属于同一逻辑材质家族；不同家族默认不合并。土/石等过渡必须有显式过渡家族或独立接缝规则，不能假设 blob 自动解决跨材质过渡。
- 轮廓、可站边与碰撞格对齐。圆角和纹理可向实体内部变化，不制造碰撞外的假落点。禁止拉伸完整平台图替代 tile 拼接。

## 47-mask 的唯一规则

邻居位序固定，图像/格坐标的北为 y−1：

```text
NW=128  N=1   NE=2
W=64    本格  E=4
SW=32   S=16  SE=8
```

原始 8 邻居 mask 取同一家族的实际占用。**对角 gating**：NE 仅在 N 与 E 都存在时保留；SE 仅在 E 与 S 都存在时保留；SW 仅在 S 与 W 都存在时保留；NW 仅在 W 与 N 都存在时保留。四个正交位保留。256 个原始状态经此归一化得到 47 个 canonical mask；含孤立格、单行/单列、端头、内外角和实心内部。不能凭“八方向都有图”宣称完成 47-tile。

检查必须覆盖 256→47 映射、每个 canonical mask 唯一图块、缺邻居的对角反例、孤立/细条/T/十字/洞/台阶/厚体及镜像。跨模块边界先合并占用再查询邻居；分块加载需要至少 1 格邻接 halo，增删格或家族时重算受影响的 3×3 邻域。不同分块、插入顺序和重复描述同一实体并集，不得改变最终 mask。

**47 个正确映射是拓扑验收，不是美术验收。** 必须再看无标号图集、同族大面积拼接、正常游戏尺度与移动镜头；找接缝、纹理周期、角部接不上和薄结构压缩。

## 三层内容合同

| 层 | 内容与构建方式 | 边界 |
| --- | --- | --- |
| 背景层 | 远景天空/色场、远轮廓、中景地标、近背景；各层统一设计卡、受控视差和空气透视，可使用精美独立图 | 无碰撞；对比和边缘不能伪装为玩家落点；纵横移动与镜头边缘不露空、不重复成墙纸 |
| 玩家层 | 实体平台/地板/墙由 blob 格构成；机关、危险、障碍按独立定义接在已知格/锚点上 | 碰撞与视觉共享明确几何合同；危险/交互轮廓不能藏于背景或装饰 |
| 装饰层 | 草、花、碎石、小物、悬挂物、少量前景及灯光；统一家族，可按表面锚点有界随机分布 | 默认无碰撞、无玩法效果；不能新增假台阶、遮挡敌人预告或侵占安全空间 |

背景允许多层精细制作；不要求每层都 tile 化。视差、配色、尺度和同屏层数需现场校准并记录，不能把“文件里有多层”当实际景深已成立。

### 玩家层的语义分离

- **solid**：47-tile blob 占用；全实体边界，连续墙与站立平台同一拓扑系统。
- **one-way**：独立薄平台家族，专有端头/中段/支撑语义；不加入 solid 占用，也不通过 solid blob 自动填厚。
- **moving**：独立运动对象、局部 tile 坐标/美术家族、锚点与携带碰撞合同；同一对象内可用 blob 拼形，但不能与世界静态 solid 合并邻接。
- **hazard/mechanism**：独立定义与运动/危险包络，使用 tile 或 socket 安装；不能因画在某格就推断伤害，也不能把无碰撞装饰当机关。

### 装饰与灯光的随机合同

装饰使用独立 seed/随机流与稳定 cell/socket 标识；改装饰预算、变体、灯光不得改变拓扑、敌人、奖励、机关相位或玩法随机结果。生产与回放记录装饰版本、seed 和密度 profile。

先提取地面/墙/顶面锚点，再排除 keepout：出生/复活、入出口与模块接缝、落点边缘、玩家身体通行包络、危险预告、机关行程、敌人轮廓与瞄准线索、交互物/HUD关键区域。可选前景只能使用受控位置与透明度，不能靠遮挡制造难度。

分布按“留白 → 小簇 → 偶尔焦点”设计，配置每面积/表面长度预算、簇大小、最小间距、变体权重及每屏上限；任何随机采样都须有次数上限和空结果保底。密疏应匹配空间身份，不要求每格有物件。灯光另有每屏数量/半径/亮度/重叠预算；去掉灯光后仍能辨认玩法，开启后不改变危险颜色语义。

## 模块与生成：先表达，再扩产

新增模块设计卡必须填以下字段；缺一个字段就不得作为新 tile 流程的已准入模块：

| 字段 | 必须回答的问题 |
| --- | --- |
| `tile_family_ids` / `tile_size` | 使用哪个已登记家族？格尺寸是否一致？ |
| `solid_cells` / `one_way` / `moving` | 每个支撑、墙和障碍如何表达？不同碰撞语义是否分开？ |
| `ports_and_halo` | 入出口、接缝和至少 1 格邻居由谁提供？边界如何重算？ |
| `mechanism_sockets` | 机关/危险如何挂接？运动、伤害、观察净空在哪里？ |
| `decoration_keepouts` / `density_profile` | 哪些地方必须清空？这段该密还是疏？ |
| `background_profile` / `visual_role` | 背景身份、前中后层、主焦点与相邻模块如何协调？ |
| `exceptions` | 哪些几何无法由现有家族表达？明确拒绝、设计专用资产或返工模块，不能静默拉伸图片 |

随机装配顺序：选已准入模块与兼容材质 → 拼合世界占用/保留端口与玩法净空 → 计算 blob mask → 接机关/危险/动态物件 → 按空间配置背景 → 独立流布置装饰/灯光 → 检查实际合屏与路线。先在合法几何与家族内产生变化，再按玩法合同验证；不能抽完任意几何后要求美术兜底。

跨模块接缝不重复端头、不留假裂缝；不同高度/镜像/薄结构/上下相邻都属于组合矩阵。更换视觉不能改变已验物理；要改几何就单独作为玩法变更复验。开发试验场不等于正式生成器已经消费该合同。

## 分阶段生产与停损

1. **地基**：锁定单一配置、47-mask 映射、家族与三层接口；输出全部 mask、拓扑测试和无风格依赖的调试网格。
2. **单家族**：从零制作一个原创 tile 家族；先验 47 个形状、薄平台和墙体，再验独立 one-way/moving 语义。保留源图、版本、导出流程和来源。
3. **合屏试验场**：真实玩家、敌人、机关、背景多层、装饰与灯光同时出现；覆盖安全站立、横向/纵向、洞与凹角、接缝、移动物体和镜头运动。试验场清楚标识开发状态。
4. **代表模块与种子**：用同一家族构建少量不同形状模块和组合，记录 seed/Manifest、占用、mask、keepout 及正常速度截图/影片；玩法与美术分别验收。
5. **正式晋级**：只有相关样板技术与合屏条件通过后才逐个迁移正式消费者；保留回滚，不批量覆盖全区。用户的视觉反馈决定是否继续该方向，技术测试不代签审美。

每轮只解决一个可观察的主要问题，保留前后同场景/同镜头/同 seed 对照。连续两次没有实质改善就停止该画风方向，记录问题后换方案；不得继续用贴花、噪点、光晕或更多背景层掩盖失败地基。

## 验收与完成声明

自动检查：canonical 数量与映射、有效 atlas 坐标/格尺寸/来源、同家族接缝、语义隔离、装饰不改玩法随机流、keepout 与预算。有资产运行 art；有运行接入执行适用 gameplay；文档执行 docs。保留原测试，新增测试应检验实际行为或有意义的失败反例。

现场检查：真实 GPU 正常比例、移动镜头、明暗背景、近远景、危险与安全落点、平台端部、薄结构、跨模块接缝、密疏节奏、画面缩小、性能。检查背景/装饰是否抢角色和玩法信息，不能只看独立图集或概念图。

报告分开列出 **规则/技术、试验场、正式消费者、独立审查、用户视觉认可、目标设备** 的状态、证据与未验项。首轮允许“地基已实现，视觉候选待审”；不允许“47-mask 测试通过，因此美术重制完成”。

## 本轮可执行候选与明确边界

入口为标题菜单 **NEW ART FOUNDATION / 47 TILE**、`scenes/demo/blob47_lab.tscn`；Web 可用 `?foundation=1` 直达，桌面可用 `-- --blob47`。候选采用原创 SVG 色块图形、暖砂岩/冷色远景，全部从零编写；这不是已认可的最终画风。新资产生成命令 `python3 tools/build_blob47_art.py`，验证 `python3 tools/harness.py --check blob47-foundation --release`。

`scripts/art_foundation/blob47_rules.gd` 是格尺寸/源尺寸/位序/图集与装饰预算的配置入口，构建器读取其尺寸。`Blob47Layout` 的三种模块记录实际家族、版本、整数端口、世界占用合并负责方及 1 格 halo、背景与密度 profile、空间角色和空例外清单；未知合同直接拒绝。正式地图尚未迁移，不把旧矩形静默取整。

当前 `garden-sparse-v1` 是简化的可执行配置：按世界对齐的 **40×23 格 bucket**，最多 12 个道具/2 盏灯，物件间距至少46单位、灯间距至少160单位；局部光晕半径50、中心透明度0.25。它是 bucket 预算，不是任意移动视口严格12/2；当前固定纵向镜头横跨两bucket时，上界24/4。以后纵向移动可能跨四bucket，上界48/8，须重新验证实际屏幕预算。局部光晕不承担危险可见性，也不宣称动态阴影照明已实现。

试验场包含单向/移动平台、独立危险物与实际玩家物理，提供种子切换、47格目录、网格及景层开关。中性样板人物只验证比例与输入，不代表主角最终设计；完整敌人合屏、纵向镜头、连续音画、所有可选上路及正式地区迁移仍未验。技术专项与独审不能代签用户审美或实体设备。
