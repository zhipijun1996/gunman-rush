# 177 份参考的 AI 设计初审

逐项记录见 [library_reviews.json](library_reviews.json)。本轮读取了 `map-edit` 固定库每份 `source.original`：72 资源的平台/危险/移动参数/端口与外部风铃控制关系，51 森林的实体支撑/果点/主支路/奖励/回收/动作程序，以及54工坊的实际节点顺序、短语、profile和相位。输入文档 SHA 绑定 root 生成的 `build/ai_level_design_v1/library/analysis.json`；没有把特征数量换算为设计分数。

这是一轮源码设计初审：9 份做较深入的优缺点与删改反证分析；其余168份按实际内容提出具体待验问题。全部177份都有记录，没有将未深审的内容评成劣质。结果为 retain 4、improve 2、reconstruct 2、needs_evidence 169、retire 0。第169条 needs_evidence 是深审的活摆果候选，其交互目标有潜力，但关键行为没有本轮匹配证据。

所有决定都是 AI 的设计假设。`retain` 表示值得保留并继续验证，`reconstruct` 表示当前玩法主张值得重想，均不改正式模块池或删除原资源。本轮没有运行新物理，也没有观看各模块匹配的完整真实输入录像，技术与真人认可均未赋值。初审出现差异判断只能证明工作流能表达取舍；它对真人趣味的预测能力仍待盲测或同条件试玩校准。

## 判断依据

先确定角色，再看空间和交互是否服务该角色。休整可以低交互；普通主路可以有便宜解；高奖励应有可理解的自愿投入与回程。不能把危险数量、动作长度、宽缺口或能力profile当品质。

每条评论包含具体优势、问题、改进方向和反事实输入。反事实的用途是挑战设计主张：删掉动作还到同目标、普通跳直接取同奖、敌人死亡后路线是否仍在、真实出口是否藏在同support另一侧。合法替代解不自动算失败；需要重估的是宣称的体验关系与收益结构。

分析JSON的 `geometry_signature` 与结构Jaccard仅用于找近邻。源码检查明确保留外部铃门配置、目标绑定、动作程序与实际目的地；没有把精确几何分组自动判成同玩法。

## 家族与变体的实际区别

| 家族 | 源码核对结果 | 本轮评价边界 |
| --- | --- | --- |
| `windchime_lesson / timed / sequence / patrol_meadow` | 静态载体相同；外部配置分别有普通铃门、4秒限时、两铃顺序或没有库内敌人 | 控制关系可产生不同学习目标；各自是否实际影响决定要对照，不能全部判重或全部算创新 |
| `ferry_channel / bell_ferry_control` | 相同水道角色；后者通过actuator绑定主动开始/停车 | 区别来自控制关系；必须证明停车的体验用途 |
| `ferry_one / windchime_ferry` | 同斜向摆渡几何；后者有船上击铃开门配置 | 验岸上先开与船上开是否真的不同；名字不是证据 |

| 森林 seven/Z/fallen/fruit crossing v0-v1 | 目的地与主支路关系延续，改变高度、跨度或接收宽度 | 先作为观察时间、恢复与容错变体；具体行为变化需要同策略配对，不称新机制 |
| 36 Foundry短语 | 六模板，每模板包含不同节点顺序变体、base相位变体、二跳和四发profile | 12个实际节点次序假设有分别评论；相位/profile单独标明验证条件，不增加机制数 |

54个工坊条目全部保留 needs_evidence，并分别记录实际节点顺序、profile和phase。它们不是没有价值：最适合检验“单片可过，串联资源/观察却不成立”。本轮没有看到匹配manifest的完整回放，不能从旧batch accepted字样重签新源物理或趣味。

## 优先取证与改进

1. 先让代表样本进入同条件的正式Motor输入记录：低交互休整、单发双用途、主动载具、普通缓冲、回望高奖、长重复攀升及多余末动作。
2. 同时跑最便宜合法解与设计方案；保留原失败，不强制动作密码。只比较设计声称的行为，记录入口/出口、资源、事件因果、停顿、相位和实际失败恢复。
3. 活摆果单独优先验证高/低相位、受伤/死亡和固定替代。接触踢不是移动挂载；到达观察根不算完成活果交换。
4. 高价值候选再采真实录像，审正常镜头可读性及操作负担。由真人试玩验证公平、学习、风险回报和重试意愿；AI判优候选也可被试玩否定。
5. 按实际证据升级同源记录。若只证技术可行，保留AI/human字段各自状态；不覆盖原通关数据，也不改变正式入口和既有有效关卡。
