# 小规模玩法关系实验

最终轮新增 `near_reward` 强替代，几何仍为v3，不再内容返工：从真实出生点沿低路走到奖台下，再完整跳跃直取奖励位置。平原167帧/一跳、森林170帧/一跳均真实到达；原三跳路线分别270/257帧。直取没有返回标记，不能当完整奖励回程。两者高路编舞的必要性被反证，保留普通分路草案并RETHINK，不封堵合法替代来制造复杂度。根盆455帧六跳对同几何删回原岸后的319帧三跳，尚没有状态或收益证明原回环值得保留；优先删冗余或重想目的。回望候选两轮后仍失败，本轮停止。所有帧数是这套bot策略的观测，不是人类时长或成功率。

早轮v1/v2没有保存完整producer源字节，虽保留原始失败raw/hash，也不声明可完全复现。最终轮按固定Git基线+完整实际文本覆盖层、逐成员SHA/CRC及输入/日志恢复，不拿当前v3解释旧源成功。

四份候选只证明如何提出、运行和淘汰设计假设。全部通过现有 `PlatformingModuleDefinition → PlatformingModule → InputRouter → PlayerController → PlayerMotor` 消费；不修改正式入口、原资源或物理参数。新东西是 Cell 关系，基础动作与运行消费者均复用。森林两份先测试空间选择与回返，不声称产生了新的钩索机制。几何是清楚标记的工程小样，尚未完成区域自然轮廓、美术或真人体验验收。

|候选|玩家判断|强便宜路线与反例|需要的设计判读|
|---|---|---|---|
|plains_overlook_choice|在低安全通路与两次换高的奖励观察台之间选择；高处回落汇入前路|普通主路满跳/直走；从入口满跳加合法下射反冲尝试直取奖励；去跳跃|高路是否提供新视野与目的，或只是额外跳台；若直取更好则允许替代解，不封死它|
|plains_backlook_cache|先向右进展，再从中继高台回看左后方奖励，随后回到主路|普通主路满跳；入口直取奖励的满跳+反冲样本；去跳跃|奖励改变行进方向与回程，不以两次升高自动评为优秀；直接反冲若可行，记录为合法多解|
|forest_crown_root_choice|在上冠短跳与下根宽路之间选择，二者汇入同一出口|低路满跳；从入口直取上冠的满跳+反冲样本；去跳跃|检查上下路选择是否有意义；目前只是基础动作关系，若和已有蘑菇岔路体验相同，应归同族或淘汰|
|forest_basin_homecoming|主动下降进入根盆，再沿另一侧支承回到熟悉出发岸，然后转入前进路|先降后进的主路；入口满跳+反冲直达奖励位置；去跳跃|必须真实访问奖励位置并返原岸；若回环只有重复路程，应重构而非为拓扑数量保留|

`config/level_pilot_candidates.json` 保存确定 Seed、父参考、基因和实验范围。每份运行输出完整逐帧请求、实际 jump/shot 事件、位置、普通/反冲速度、落地状态、资源、身体危险扫掠、奖励位置访问与回返、几何和路线。`accepted_events` 只写真实信号；请求未获接受不能当作动作已执行。没有奖励实体，因此 `reward_claim=unverified_no_reward_entity_in_this_fixture`。

```sh
bash tools/godot.sh --headless --fixed-fps 60 --path . --script tools/level_pilot_validate.gd -- --candidate=plains_overlook_choice --strategy=reward --output=res://build/ai_level_design_v1/pilots/plains_overlook_choice/reward.json
```

每候选分别运行 `main / reward / direct / no_jump`。`direct` 是完整持跳与一次合法下射反冲的有界强替代采样，失败仅表明这一输入策略未达目标，不能证明该几何无解或能力必需。`no_jump` 去除实际请求并保留原请求记录，正常应失败；此失败由上层实验判定为预期反例，不改写为物理 PASS。`reward` 除抵达出口还要求真实奖励位置访问及回返标记。没有动态危险的候选记录空危险集合，不能伪称已验证机关相位、公平性或伤害策略。

脚本采用原 Foundry 的手动 `controller.physics_tick` 模式；每帧仍由唯一 Motor 完成移动，`manual_motor_step=false / manual_controller_tick=true` 明示这个实验条件，不外推为正式 App 路线证据。首次构造允许放置出生点，之后只通过 Router 输入。资源使用实际 tuning 与真实精力规则，并记录 tuning 源 SHA。全部 `production_pool=false`，最终 `fun/device=unverified`。

外部搜索可复制有限候选并设置新 `id` 与已有 `blueprint`；`--catalog` 读取同格式候选。`--variant=1` 将单向承台与对应站位上移 8wu，保留关系作为几何变体对照。森林根盆的 `gene.route_order` 由 `reward_then_return_then_progress` 改成 `reward_then_progress` 会真实删掉返原岸的周期，构成关系消融。此有限接口故意不接受任意几何 DSL，未知候选、基因路径或 variant 不自动生成成功结果。

另外三份既有代表 `plains_low_arch / plains_long_meadow / forest_root_meadow` 供优秀假设、休整用途与普通跨越对照。等级只是预先假设，结果必须由实际轨迹与设计审查决定；长草甸若作为休整有效，可以保留为 Cell，但不能因此称独立动作挑战优秀。

## v2：保留首轮失败并修正声明空间

`pilot-main-r1` 原件中，平原观察台 `reward` 真实抵达奖励位置、回岸与出口，270 帧，但满跳由上层 y94 起跳后顶点达到 y-56.39，超出原 `world_bounds.y=0`。`direct` 的一次合法反冲顶点达到 y-77.55，同时未达到奖励位置；后者即使修复范围也不能改签通过。此处不存在天花板实体，失败是设计声明漏掉上方合法运动空间，并非穿透碰撞。

v2 只把四新候选的声明占地从 `[0,0,840,400]` 改为 `[0,-256,840,656]`，显式预留上方开放飞行区；所有支承、站位、动作规则、原边界守卫与侧/下边界保持。`definition_version=2`，旧 r1 原件不改写，后续单独采集。既有代表仍用原始占地，不把新候选修复扩散到旧关卡。此改动不是调低成功阈值；直接替代策略是否到达目标仍以真实结果判定。

## v3：真实分路策略与根盆完整身体净空

`pilot-main-r2` 保留。观察台主路/奖励路线和森林上冠奖励路线通过；回看主路的通用满跳实际落到 y94 高台，森林低路满跳实际落到 y158 上冠。它们说明驾驶策略选中了合法上路，不能解释为低路无解。v3 不改通用 driver，仅在本实验里通过同一 Router 执行低路短释放、走出岸边下降，以及从真实岸边完整持跳并继续移动越过上方接收台。请求与实际事件照常记录，未写入位置或资源。
