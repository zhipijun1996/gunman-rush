# Codex完善剧情的方法

从一个具体片段开始，不要每接到一个NPC任务就重写整个世界。本流程适用于补剧情、改对白、设计剧情房和安排多次通关的信息；接入游戏时继续遵守仓库原有开发流程。

## 1. 先知道以哪份资料为准

用户最新要求优先。然后按下表查当前资料；V0.1/V0.2只是历史，不从里面挑方便的解释拼进新稿。

| 想弄清什么 | 读哪里 |
| --- | --- |
| 故事总体讲什么 | [故事简版](story_overview.md)；它是导读，不单独决定新事实 |
| 时间、家园、死亡和重玩怎么成立 | [循环规则](loop_rules.md)，是这些问题的唯一规则来源 |
| 事故与人物到底做过什么 | [故事圣经](story_bible.md) |
| 本区发生什么、Boss为什么拦路 | [区域卡](region_narratives.md)、[Boss卡](boss_narratives.md) |
| 玩家什么时候知道、哪些东西会保存 | [呈现方案](narrative_delivery.md)；运行另查[家园保存](../../home_and_save.md)和[地区能力](../player_actions/regions_v0.3.md) |

已确认方向、当前工作提案、代码已有内容，必须分清。资料矛盾时，写明冲突和影响，保留当前基线，给出可审阅改法；不要偷偷加新能力来补洞。用户明确改变方向时直接按新要求同步，不为普通写作选择反复索要许可。

## 2. 每次按五步做

1. **限定这次要补什么。** 例如“一间平原剧情房、一次初遇、一次回家对白”。写明只做文档还是已经授权接入游戏，列出允许修改的文件。
2. **查清当天顺序。** 这个人几点在哪、知道什么、消息从哪里来？玩家抵达前发生的事故，不能由到场后的动作倒过来阻止。查主线信息是否在同层其他路线也能得到。
3. **写玩家看得见的场景。** 用一个物件、一个动作、几句对话表现一个重点。先交代人物在做什么，再交代原因，不用角色站着讲一页世界观。
4. **写清五种结果。** 初遇、救回家后、下一轮原处、失败/重复互动、真正结局后。另写“不进这间房”时主线怎样继续；救援和普通交谈不能混为一件事。
5. **检查、同步、交付。** 用[模板](story_templates.md)检查时间、记忆、能力和保存，再更新受影响的资料。保留提案/实现/验证的区别，报告真实检查结果和一个下一任务。

普通对白只需相关材料和轻量检查；不必填满所有模板。新角色或新区域先写卡片；改结局必须同时查主线信息表和最终一轮的救援方案。

## 3. 写作要让人能直接读懂

每段只讲一件事，先写谁做什么、为什么，再写后果。使用常用词，同一个概念不要换三种称呼。需要技术字段时，放在“给开发者的记录”里，不塞进角色嘴里。

| 原来的写法 | 更清楚的写法 |
| --- | --- |
| 完成身份脱网与持久化提交 | 这个人被安全带回家园；下一轮不会回到原处。开发记录另写何时保存 |
| 解除中央对地方制动的旁路锁 | 让各地的人能自己停下机器 |
| 给予玩家情感闭合 | 老师坐回空椅子，和主角把那顿饭吃完 |

不要以“他很悲伤”代替场景。可以写他每天多摆一只碗。不要靠全知角色故意不说关键话拖长周目；要说明他确实不知道什么，或为什么选择隐瞒并承担后果。

短对白通常2–4句起步，一次交互只承担一个新信息。长资料由玩家主动打开。建议的句数与停留时长是试写预算，不是必须压短一切，也不是已冻结的运行参数。

表达方式参考用户要求采用的 [i-have-adhd](https://github.com/ayghri/i-have-adhd/blob/main/skills/i-have-adhd/SKILL.md)：先给重点、分短段、减少岔题。本项目不依赖安装外部插件，本文已写出实际采用的规则，也不据此推断用户的健康情况。

## 4. 用三个小变化表现循环

- **外界重复：** 送信人下一轮仍在同一个地方掉帽子。玩家提前接住，他应有新的反应，不是所有事情命定照演。
- **家园接着过：** 烘焙师在外面说“明天做新口味”，回家后的下一次说“昨天答应你的，想好了没有？”
- **真结局向前：** 同一位送信人送来不同的信，上面写第二天的日期。

这些变化说明规则，不需要每个NPC再解释一遍。若人物已经安全留在家园，原位置要空着、交班或换成留言，不能生成另一个本人。独特物件也不能靠循环无限复制；普通金币/音符仍按现有经济，不为一句故事台词改系统。

## 5. 提交前问五个问题

1. **规则是否还是同一天回返？** 新段落有没有又引入局部停时、加速、抽寿、时间搬运或新复活法？枪有没有又被写成维修工具？
2. **角色凭什么知道？** 对应记忆、当轮目击、旧文件或家园记录在哪里？办公室会重置，不能自己攒几十轮新日记。院长也靠报告，不是另有记忆魔法。
3. **错过是否还能理解主线？** 不进随机房、不救可选NPC、不换路线、不死直通，是否仍有必要事实？高阶支路不能独占结局答案。
4. **下一轮和失败后是什么？** 留在家园的人不会复制，外界阀门会复位；最终必须同轮先救人再停回返。未提交救援、保存失败或同帧死亡不能假报成功。
5. **玩家真的能看到、做到吗？** 信息位于安全点，入口符合本局能力和所有合法武器分支；读文字不被机关杀死、不抢跳跃/瞄准。没有实测就写未验证。

检查通过只说明对应范围。文档检查不证明故事好玩，也不证明运行、中文显示、真机和保存已经完成。独立审查发现问题时保留原结果，修完再审，不把自评写成用户认可。

## 6. 改了设定，更新哪里

| 本次变化 | 必须一起核对 |
| --- | --- |
| 循环/死亡/家园边界 | loop_rules、故事圣经、各受影响人物与呈现方案；旧证据引用的源稿需原字节保留 |
| 人物动机、知道的事 | 故事圣经/人物卡、相关对白、证物来源和登场时点 |
| 区域事件或Boss理由 | 区域卡、Boss卡、同日天气/事故顺序及能力要求 |
| 重要事实的出现位置 | 呈现方案的六层表、同层替代路线、钟心补漏与重复展示 |
| 仅措辞精简 | 对应对白或片段；确认意思、保存条件与角色知识没被改掉 |

不要为了缩短话而改剧情含义。例如“忘记了伤痛”不等于“伤害没发生”；“主机停了”不等于“回返取消”。如果只是写作方法调整，不需要再重写原故事并让旧质量记录的哈希失效。

## 7. 后续接入游戏的顺序

先做平原一个真实样板：同一动作重复、一个人可被接回、下一轮原处不再有本人、家园有一条接着昨天的对白。验证同一局重复交互、救援后死亡、重启存档、跳过对白和写入失败。

样板成立后再接主线信息、老师首通回家、试验记录、最终一轮的应急步骤。不要一次开放16区或先建无人使用的剧情大框架。复用现有StoryDiscovery、Meta和Run边界，只有实际消费者需要时再增加字段/服务。

修改Boss战斗用boss-creator，地图/能力入口用region-generator等现有技能，美术与动画用原专业技能，独立体验审查用gameplay-reviewer；共用现有任务ID、G0–G5与质量记录，不另外创一套验收编号。未开放地区先写文档，不假装已经能玩。

## 8. 给Codex的可复制任务

```text
使用 $story-writer。先读 AGENTS.md、docs/current_state.md、docs/handoff.md，
再读 docs/design/story/README.md、story_overview.md、loop_rules.md、
codex_workflow.md 和 story_templates.md，按本任务补读其他资料。

本次只完善“风铃平原的一间烘焙师剧情房”，不改运行代码或基础玩法。
保留当前V0.3基线，不重写世界观，不新增时间机制。

请给出：当日时段、人物在做什么、玩家可见物件、2–4句初遇对白、
接回家园后的对白、下一轮原处、失败与重复互动的结果、结局后近况。
这间房只补人物，不承担唯一主线答案。剧情只能要求本局已有能力。

按模板检查因果和角色知识，更新相关文档并执行适用检查。
说明哪些只是提案、哪些检查确实执行、还有什么未验证。
交付先用不超过五项说明具体改动，再列实际文件与一个下一任务。
```

后续换任务时改掉引号中的范围和交付物；明确授权接入游戏后，再指定真实场景、保存消费者、允许修改路径和对应验证，不靠“继续完善剧情”擅自扩大成全游戏改造。
