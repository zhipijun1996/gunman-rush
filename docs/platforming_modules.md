# 原创平台挑战模块设计草案

本目录服务于 [模块化生成](procedural_generation.md)。参考《空洞骑士》平台段的动作节奏、危险预告、落点可读性与安全停顿；不复制原地图、尺寸、素材或独有动作。当前玩家动作仍是可配置跳跃、松手射击及反冲，不假定存在下劈弹跳、冲刺、蹬墙或攀墙。

**八个蓝图均已制作固定样片，分批真实Motor/动态/Boss边界证据见交接；技术验证限定实际配置和路径，不代表所有变体或完整生成地图。** 难度、尺寸、动作次数需求与权重未锁定。`candidate` 表示拟优先制作的静态原型；`planned` 表示待静态模块与生成链验证后制作。已存在相似灰盒机关或动作测试不等于这些模块已验证。

## 共用契约与读图规则

- 稳定 ID 对应一种拓扑；具体内容用独立版本、变体 ID 与实例 ID 标识。横向、纵向、近方形指世界空间布局，不指横屏手机方向；整个小关仍支持横屏操作。
- 平台轴 P、战斗轴 C 的 0–3 是候选标签：0 为安全交互，1 为单动作/单威胁，2 为短动作链/双威胁，3 为长动作链/多威胁。它们不是玩家等级或固定数值，不简单相加为总难度；高 P 模块优先低 C，避免首版同时拉满。
- 端口记录位置、朝向、可站立面、净空、允许进入速度范围、必需能力、最少动作资源、接收区域与机关相位范围。除另行验证的连续段变体外，模块边界先设安全可站立区，支持静止起步与减速后进入，不要求继承上一模块的高速反冲。
- 资源按关卡生成时的能力/武器快照校验，不能把当前默认次数写成所有模块共同常量。必经路线不得依赖局内尚未获得的增益、精力充足或慢时；无相容模块时使用已验证保底布局，不能伪造兼容性。
- 安全段起点与模块端口不是同一个对象。每个挑战段设置独立 SegmentAnchor、出生净空与短暂环境保护；段回退遵循 [伤害规则](damage_and_respawn.md)，保留奖励账本与机关相位，不能借回退重置领取或等待时序。
- 必经路线不能要求每次失误扣血才能通过。能力奖励支路只通向可选收益，并提供安全返回或单向汇入必经路线；撤销增益不会把人困在无出口空间。
- 手机镜头先展示下一个落点、危险方向及可等待位置，再允许玩家进入动作链。反冲朝向以原创箭头/枪口提示表达，底部触屏控件区域不作为唯一落点信息区。复杂段可配置镜头区与前视偏移，但不改玩家物理。
- 所有尺寸从真实轨迹验证反推，不能按屏幕像素或原作地图坐标决定。装饰不能遮挡平台边缘、敌方弹体与补给。初版禁止随机镜像含单向时序、特定射击方向或奖励出口的模块，除非镜像版本单独验证。

## 1. `safe_hub`：停靠庭院

状态：静态样片已实现（自动证据范围见下方，真机待验）。主形状：近方形，可作为横向或纵向图的入口、连接点、奖励区与出口汇合区。候选 P0 / C0。

- **入口与出口**：至少一个入口与一个出口，路线选择版本提供两个清晰标识的出口；地面落脚区与入口净空隔离，允许静止、步行及已经减速的落地。端口无危险相位约束，不要求剩余跳跃或射击次数。
- **安全段**：可放小关入口或挑战段起点；交互区、候选道具、商店和出口之间留清晰操作距离，出口请求沿用只切换一次的契约。
- **基线必经**：走过地面即可到出口，不引入奖励类型自身不需要的战斗完成条件。能力奖励支路可提供一个低台展示位，领取仍由对应 RewardService 决定。
- **变体**：窄入口宽庭院、上下层安全连接、双出口平台。不能将敌人或周期危险随机放进交互区，也不能把出口隐藏成要求额外能力的高台。
- **手机读图**：玩家进入即看见当前类型与下一关选项；奖励与出口标志分开，避免右摇杆瞄准遮挡交互目标。

## 2. `stepped_crossing`：错层踏桥

状态：静态样片已实现（自动证据范围见下方，真机待验）。主形状：横向阶梯，可折成近方形的两层通道。用途：早期教学、基础平台挑战、连接战斗庭院。候选 P1–2 / C0–1。

- **入口与出口**：两端各有安全落脚台；静止可启动，出口允许落地后停稳。端口无周期相位；每个必经跨越的动作需求由快照校验，平台落地可恢复动作资源，不要求跨多个模块保留跳跃次数。
- **安全段**：每个短阶梯链后安排停靠台；段起点设在链前稳定平台，不能放在窄边缘。
- **基线必经**：上跳、短按小跳通过低顶段、落地重整。可选支路使用额外跳跃或反冲跨越较高台，回到后方宽台；不把额外跳跃写成默认必需。
- **变体**：升阶、降阶、宽窄交替、带低顶的侧道。首版不在狭窄必经落点放接触敌人，不与紧邻入口的下压机关直接连接。
- **手机读图**：至少提前显示当前与下一落点；低顶与长跳提示用环境轮廓表达，背景台阶不与可站立台同亮度。

## 3. `recoil_shaft`：反冲升井

状态：静态样片已实现（自动证据范围见下方，真机待验）。主形状：纵向。用途：突出向下射击抬升与空中调整，形成向上的主路径。候选 P2–3 / C0。

- **入口与出口**：底部宽站台起步，上端设可站立接收台与侧向出口。入口普通/反冲速度范围必须经测试，首版从静止起步验证。危险相位无关；所需跳跃、射击次数及枪支反冲参数明确列入兼容条件，不能只写“有枪即可”。
- **安全段**：每段升井之间有停靠侧台；SegmentAnchor 位于底部或中间安全台，出生时头部净空足够，不放在井内半空。
- **基线必经**：仅在当前基础快照具备足够反冲与资源时作为必经；其他快照改选错层侧梯变体或其他模块，不能临时赠送动作次数掩盖不可达。可选支路为高位小奖励台，要求更多动作资源且可安全落回主台。
- **变体**：单段升井、带停靠的双段升井、偏移式侧出口。首版不叠加井顶伤害机关、空中强制射击敌人或精力慢时需求；禁用没有逃离路径的光滑长井。
- **手机读图**：镜头提前上看接收台与顶棚；起跳前展示“向下瞄准→向上反冲”的原创提示，下方靶物只作视觉引导，不引入下劈弹跳机制。

## 4. `timed_gallery`：节拍回廊

状态：动态样片已制作（验证范围见交接，真机待验）。主形状：横向，可沿方形地图一边布置。用途：观察—等待—短穿越，机关时序的专门挑战。候选 P2–3 / C0。

- **入口与出口**：入口等待台处于完整安全区，允许任意相位到达；出口同样安全。端口记录初始相位与可出发窗口，玩家可等待可行窗口，不要求上一模块的相位恰好匹配。
- **安全段**：危险段分成短组，每组之间有完整停顿区；回退不重置机关相位，等待台仍允许重新观察。持续触碰伤害去重由 DamagePolicy 处理。
- **基线必经**：以观察周期、短跳或一次反冲穿过单组危险。能力支路增加高位绕行或更快节奏路线，不减少主路安全窗口到只有慢时可过。
- **变体**：单组往返锯轮、交错两组、上下交替危险。首版不与移动接收平台、敌方弹幕或盲落段叠加；不随机缩短已验证窗口。
- **手机读图**：机关轨迹、预警和等待台在同一镜头中；一个周期足以辨认运动方向，特效与慢时遮罩不覆盖危险轮廓。

## 5. `descending_switchback`：折返降廊

状态：静态样片已实现（自动证据范围见下方，真机待验）。主形状：纵向或近方形，多层左右交替。用途：下降节奏、短按控高与落点选择。候选 P1–2 / C0–1。

- **入口与出口**：上层静止安全台入场，下层宽平台接收，再横向离开。进入速度必须低于已验证上限；危险相位无关。下降必经不能以剩余射击次数作为救命前提，必要落点可凭基础移动到达。
- **安全段**：层间安排停靠台，落点失误回退到当前下降段顶部安全台；回退不会重新生成层内奖励。
- **基线必经**：可控的小段下降与左右空中调整；不进行画面外连续长落。能力支路用反冲抵达侧面奖励台，再返回宽接收台。
- **变体**：双层折返、三层分段、可见底部的侧落口。首版不加入上锁门堵住回路，不把单向平台下穿作为必需输入，直到该动作的跨设备提示与实测完成。
- **手机读图**：进入落口前镜头显示下一层；危险坑与可落平台轮廓区分，镜头不能追随过慢导致玩家先落入未知区域。

## 6. `moving_transfer`：摆渡接力

状态：动态样片已制作（验证范围见交接，真机待验）。主形状：横向，也可作为纵向图的跨井连接。用途：稳定移动平台与观察登乘，验证 Motor 平台速度契约。候选 P2–3 / C0。

- **入口与出口**：两端固定站台，静止可等待平台靠近；出口不可位于移动平台上。记录平台轨迹、周期、初始相位、停靠区与携带速度；任意到达相位均有可等候的可行周期。
- **安全段**：固定站台提供安全起点，回退后平台继续当前相位；出生不能重叠平台或被它挤压。
- **基线必经**：单平台登乘—下船，使用已验证跳跃范围；平台速度只能由 PlayerMotor 统一处理。可选支路为第二平台上的更高奖励台，回主路的降落区始终可达。
- **变体**：水平往返、带停靠停顿、轻度竖向摆渡。双平台接力等到单平台稳定后再做；首版禁止摆渡同时穿锯轮缝、临界跳距与移动出口。
- **手机读图**：同时看见登乘点与接收台，平台轨迹有明确参照；不使用强镜头晃动制造运动错觉。

## 7. `square_loop`：环庭双路

状态：固定双路样片已实现（实际路径与真机范围见交接）。主形状：近方形蓝图，围绕中央地标形成局部环路。用途：让小关不是单条直走，容纳探索、战斗及奖励取舍。候选 P1–2 / C1–2，具体变体限制一轴占主导。

- **入口与出口**：入口进入安全中心或底边，左右路径在安全出口台汇合；图内岔路与小关两个出口是不同契约，不能每个岔口都触发关卡切换。端口允许停稳与观察，无强制相位要求。
- **安全段**：中心停靠点与每条长支路前设段起点；两个方向都能返回或汇合，不把回退点放在正在战斗的中心。
- **基线必经**：至少一条基础能力可达路线；另一条可选路承载额外平台挑战或战斗收益。资源需求分支独立验证，不能仅验证两路合并后“总有一个出口”而忽略被选分支困住。
- **变体**：上路平台/下路战斗、左右镜像但独立验证、短环与长环。首版不生成奖励区软锁，不引入三维方向切换或按隐藏钥匙才能出去的规则。
- **手机读图**：入口处给出两个方向的短标签与清晰地标；局部地图/相机区域设计先保留接口，不声称已实现小地图。奖励标记不能隔墙造成可穿行误读。

## 8. `boss_approach`：战前缓冲廊

状态：固定准备区与既有Boss核心衔接已实现（真机待验）。主形状：短横向或纵向入口，连接固定 Boss 核心区。用途：主题过渡、战斗前停顿与明确开始边界。候选 P0–1 / C0。

- **入口与出口**：安全入口到固定 Boss 场地入口；进入时允许资源不足，不能要求额外动作次数才能见到 Boss。入口相位与 Boss 攻击相位分离，Boss 只由 BossEncounter 的正式开战条件启动。
- **安全段**：场地入口前有清晰站台；是否提供补给由类型/奖励策略配置，模块不擅自回满血量或精力。段起点与 Boss 遇敌开始/重置策略分别管理。
- **基线必经**：简单走跳抵达战斗区，不消耗血量过门。可选装饰支路不承载必须领取的金道具；胜利金奖励由 Boss 结算服务发放一次。
- **变体**：短楼梯、低台门厅、开阔入口。核心战斗区、必要躲避空间与战斗平台只使用匹配该 Boss 的已验证模板，不自由拼接反冲升井或节拍回廊作为战斗区。
- **手机读图**：入场前同时识别 Boss 门与安全准备区，开战后镜头稳定展示战斗边界，装饰不造成假落点。

## 首版制作与验证顺序

1. 先制作 `safe_hub`、`stepped_crossing`、`descending_switchback` 的静态实例，建立端口与 SegmentAnchor 的实际消费者。
2. 验证 `recoil_shaft`，覆盖不同跳跃/射击次数、反冲武器配置与能力撤销的兼容筛选；不合格组合明确拒绝。
3. 用前四种模块构建短横向、短纵向与紧凑折返小关。全局外形是布局计划的选择，不能只把同一横向链旋转后宣称支持纵向。
4. 再制作 `timed_gallery`、`moving_transfer`、`square_loop`，逐一补动态时序、平台携带与分支回路验证。`boss_approach` 接入既有 Boss 模板，独立验证其外围随机边界。

每个模块升级为 verified 必须具备真实场景、内容版本、入口状态集合、实际 Motor 成功轨迹、失败边界、资源需求、环境回退与安全出生证据。组合还要验证出口可达、奖励不重复、镜头可读和固定 Seed/版本 Manifest 重放。批量 headless 不能代替手机操作与视觉验收；初步固定关卡验收不自动覆盖新模块。


## 当前静态样片实现与验证范围

主菜单 `MODULE LAB` 进入固定模块练习场；八个模块按钮与 `RETRY MODULE` 明确开始新尝试。菜单返回家园沿用确认流程。练习场不参与Run胜负，不发道具/金币或永久进度；没有接入随机生成器。每个样片为1280×720固定世界窗口，尚无大世界CameraRig。

实际资源为 `resources/generation/modules/*.tres`，对应 `scenes/generation/modules/*.tscn`。PlatformingModuleDefinition持有版本、平台/危险矩形、完整身体安全锚点及两端口；PlatformingModulePort记录朝向、正常/反冲速度、爆发剩余时间、射击冷却与动作余量约束。实例深拷贝定义，状态不会污染资源。当前静态端口不需要危险相位字段；动态模块必须另补相位策略。

| 样片 | 实际通过条件 | 实际轨迹证据 |
| --- | --- | --- |
| safe_hub | 无跳跃、无射击 | 实际行走到出口 |
| stepped_crossing | 配置1跳、0射击 | 逐台跳跃、落地补动作，到出口 |
| descending_switchback | 0跳、0射击 | 左右折返下降，逐台落地到出口 |
| recoil_shaft | 1跳、1空中射击、已验证burst反冲 | 向下射击上升抵达接收平台；3跳/3射击配置另有实测 |

`tests/platforming_module_tests.gd`直接驱动真实PlayerController/Motor，每物理帧一次；整个24×36身体检查危险交叠与安全出生，真实庭院→踏桥平移连接轨迹，不靠传送完成路径。筛选覆盖0/N、禁用能力、过小/非法反冲、资源不足、冷却/残余爆发拒绝。配置筛选不是任意武器参数的可达性证明；没有验证的参数组合不能擅自标verified。

`tests/module_lab_tests.gd`使用真实App/练习场验证菜单设置、暂停冻结、取消旧释放、段回退保留已扣血量/精力/冷却/已用补给/模块实例与时钟、补给一次、致命伤害优先回Home及旧epoch失效。超出固定练习边界按环境伤害回安全锚点，避免无限掉落；不创建阻挡未来模块接缝的隐形墙。明确重试才重置练习尝试。

生成用组合端口相位、横/纵/方形完整小关、Manifest重放、动态平台与手机手感均仍未验收。不要用静态样片通关替代GEN-LAYOUT或A50–A54全部通过。


## 动态样片批次契约（实现与实测分开记录）

本批先实现 timed_gallery 与 moving_transfer，保持静态入口/出口和1280×720固定练习视窗。节拍回廊只放一组上下往返锯轮，有入口等待区和穿越后安全区；可用普通移动、观察并等待通过，不要求慢时、射击或损血。摆渡接力只放一个水平移动平台，固定两岸与停靠等待时间，通过登乘/携带/下船完成；需要一个可用跳跃，不要求空中射击。具体长度、周期、停靠时间是样片参数，不锁定正式难度。

动态定义保存稳定ID、版本、轨迹、周期/停靠时间与初始相位。实例持有独立游戏clock，使用受Engine.time_scale影响的物理delta；暂停冻结。RETRY或选择模块显式建立新实例，段回退保持实例/clock/当前相位。初始相位可以配置，后续生成Manifest必须记录实际选用值；本批不声称完整生成重放已实现。

动态危险运动/表现与受伤提交分开，接触提交ENVIRONMENT DamageRequest交FrameDamagePolicy；不调用旧SawHazard即死行为。检测考虑人物完整碰撞体与相对扫掠，actor_epoch变化后重基准，避免回退传送被误认为跨越危险。安全锚点与端口拒绝整个危险运动包络相交，不能只在初始相位安全。

移动平台为AnimatableBody2D，由Godot碰撞平台携带进入现有PlayerMotor唯一move_and_slide；禁止组件直接搬玩家或二次位移。固定岸和出生身体与平台整个运动包络保持安全间距，不把出口/回退锚点放在移动平台上。离开平台速度行为使用既有Motor/Godot契约，实测后记录，不借新模块暗改角色参数。

新增验收：四个分散初始相位均有实际输入轨迹通过；节拍无跳无枪无损，摆渡单跳零枪无损并实测静止携带；相位任意到达可等待完整周期。真实段回退不重置phase/supply，暂停冻结动态对象，慢时同倍率缩放；错误运动包络/周期/ID明确拒绝。导入、自动物理、Web浏览器和真机分别记录。具体通过计数以交接实测为准。


## 环庭与战前样片批次契约

square_loop为固定窗口的局部双路环庭：共享入口/出口，底路无跳无枪，六级上路每次落地恢复后只需一个可用跳跃。上路可回落到底路再汇合，不用道具、射击、损血或慢时；不是完整近方形小关生成。未放敌人、宝箱或局部地图，不把蓝图里的可选内容算已完成。每个上层锚点与底路通道均做完整身体安全验证。

boss_approach为固定准备区与既有Boss核心的衔接样片：准备区无动作资源门槛，不自动回血/补精力；x890为开始边界，真实存活玩家站稳进入核心才启动一次Encounter。可用核心地板接触面x890–1240/y600与上平台(1000,500,220,18)保持一致，不能用随机外围改变必要战斗空间。

本批练习暂定允许退回准备区，Boss生命/阶段/已发动战斗保持；准备区拒绝双方战斗伤害，玩家也不能从安全区偷打Boss。此为练习消费者策略，不锁定正式Boss封门/撤退规则。练习胜利复用RewardService保证一次GOLD，只修改本次练习局部BuildState，重试/离开丢弃，不更新Run胜负、金币或Meta。零血优先于Boss败亡和金奖励、旧epoch请求失效，段回退保留Boss状态与领取账本。

实际自动/浏览器证据见handoff；八个模块全部有场景不等于所有变体、全图组合、手机读图或完整SeedManifest生成已通过。下一阶段再验证ModuleGraph/端口组合与CameraRig，详细设备门槛单独跟踪。
