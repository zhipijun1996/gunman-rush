# 失序之钟预组与组合推荐

本文件提供两种内容：**预组**保存可整体摆放的稳定联动，**组合推荐**提供可改编的房间玩法用法。每个预组以“可使用区域”说明范围，默认“全部”。基本行为与共用合同以[基本机关库](失序之钟_基本机关库.md)为准。

## 1. 使用与读取

- 房间作者按基本库的[房间设计与验证](失序之钟_基本机关库.md#room-design)形成主要判断与空间构思，再按需求查阅相关预组或用法；可以直接定制组装基本机关。
- 预组是可选起点。选用后遵循其成员、驱动与状态合同，位置、地形和开放参数按本房调整；玩家路线与操作选择由房间设计决定。修改内部联动时，作为自定义组合重新校验。
- 组合推荐是开放参考；新的合法组合和成熟用法使用同一套房间验收标准，复用与原创按体验需要选择。
- 逐房任务按名称或所需行为读取相关段落。机关库实现任务读取全部已收录预组、结果类型及基础依赖；组合推荐作为示例供查阅。

## 2. 预组装配合同

1. **定义**：列出基本成员、可使用区域、默认相对位置、信号或驱动关系、可调参数、摆放条件及恢复方式。成员直接引用基本机关或注册的内部驱动；复用另一预组时在制作阶段展开为平坦成员。
2. **实例**：整体创建后保存为可独立编辑的基本实例。成员保存稳定实例 ID、基本定义与版本、实际参数和连线，同时记录 `assembly_id`、`assembly_definition_id` 与组合来源版本。
3. **编辑**：支持整体移动和逐件调整；编辑分组、运行联动与恢复关系分别管理。修改联动后按实际成员和连线重新校验。
4. **复制与版本**：复制生成新实例身份并重写内部引用，外部连接明确指定。预组更新用于新建实例；已有房间保留实际布局与参数，升级通过显式迁移和复验完成。
5. **共同状态**：共轴、配重、顺序与互斥等关系由基本库中的共用行为执行。共同驱动组使用一个时钟所有者，按已配置的状态寿命与挑战组提交结果和恢复。从动成员的输入映射、直接受击反馈与布尔状态汇总沿基本库的共用规则，各预组声明实际运动入口。
6. **空间**：预组提供装置及必要的局部支撑；入口、出口、主要地形、落点、镜头、怪物和奖励由房间设计掌握。采用预组后验证本房实际动作与能力资格。
7. **可使用区域**：沿基本库的定义级 `usable_regions`，默认 `["*"]`。实际可用范围为预组声明与全部基本成员范围的交集；编辑器和装配器按展开后的成员一致校验。名称与审核编号保持稳定，跨区复用引用同一预组定义。

### 参数继承与展开

开放参数表定义预组关系的独立变量，基本成员参数沿基本库；成员位置、几何和已开放属性可逐件编辑。表中的默认位置仅提供可摆放预览，房间以实际职责与能力验证选定布局。变更内部成员归属或连线后，保存为自定义组合并按真实关系校验。

预组输入只在创建或明确重新生成时展开为实际成员。房间保存成员的实际参数、内部驱动配置和来源版本；整体移动时同步平移位置及绝对坐标字段，局部路径保持相对关系。数量、周期、速度与窗口之间的派生值在编辑器只读显示。

`C15` 的限时由风铃负责，`C16` 的运动由载台负责；`G12/P01/P02/P04` 的共享运动由对应驱动负责。`G14` 的目标受理由互斥组件协调，具体形态沿成员合同；`G16` 的结果由世界行动与终态协调器共同提交。普通连线使用同寿命、同挑战组；永久事务通过 C09 完成。

## 3. 预组目录

### C15 风铃与机关门

**可使用区域：全部。**

- **玩法**：射中风铃改变门的开合，用于直接开路或限时通过。
- **构成与变化**：C01＋C02，预设开关到门的控制关系；配置永久开启或限时通行，铃与门的位置由房间调整。
- **恢复**：永久开路保留结果；限时模式按既定到期时刻关闭，沿门的防夹规则处理，可再次触发。

| 字段 | 类型／单位 | 默认值 | 合法值与作用 |

| `member_offsets` | 角色→点 | `bell:[-96,0]`；`gate:[96,-64]` | 成员的局部参考位置；门参考点为其矩形左上角。展开后编辑相应成员的真实位置字段。 |

**验收**：一次开启与限时开启分别可用；重复命中、到期防夹和读档符合基础件合同；实际射线可命中，玩家身体到达门体前已经完成需要的开门提交。

### C16 风铃与升降台

**可使用区域：全部。**

- **玩法**：一枪启动载台，再次命中暂停，恢复后沿原相位继续。
- **构成与变化**：C01＋C03，配置路径、行程、速度与操作站位；开关和载台保持可辨认的控制关系。
- **恢复**：反复操作，临时状态随所属挑战复位。**时控：载台的运动与停靠。**

<details>
<summary>C16 风铃与升降台：装配参数与运行合同</summary>

| 字段 | 类型／单位 | 默认值 | 合法值与作用 |
| --- | --- | --- | --- |
| `member_offsets` | 角色→点 | `bell:[-96,-32]`；`carrier:[0,0]` | 铃与载台起点的预览位置；可按射线、上车点和下一落点调整。 |
| `carrier.platform_size` | 宽高 | `[128,24]` | 两维为正；承载形式沿 C03 的 `one_way` 配置。 |
| `carrier.endpoint`／`carrier.route` | 局部位移／点数组 | `[0,-192]`／`[]` | 空路线采用端点；非空路线从隐含 `[0,0]` 出发并替代端点。路径只保留一个有效来源。 |
| `carrier.period` | 秒 | `5.0` | 沿 C03 合法范围；往返移动总时长，路线速度由路径和周期派生。 |
| `carrier.endpoint_dwell` | 秒／端 | `0.20` | 大于等于零；完整循环为 `period+2×endpoint_dwell`。 |
| `carrier.phase_offset` | 秒 | `0` | 大于等于零的运动时钟初值，沿 C03 解析。 |
| `initial_running` | 布尔 | `false` | 同次初始化风铃接受状态与载台运行状态；读档使用已保存状态。 |
| `state_scope`／`section_id` | 状态寿命／分区 ID | `attempt`／`main` | 铃与载台属于同一临时挑战组。 |

**固定成员与连线**：C01＋C03；C01 为 `repeat_enabled=true`、`duration=0`，`active(bool) → carrier.set_active(bool)`。载台采用 C03 循环运动，独自持有路线时钟；风铃仅改变运行状态。暂停保留位置与相位，再次启动连续运行；时间附魔按载台的时间合同结算。

**验收**：从两端和中途暂停状态均可重新操作；源状态与载台运行一致；暂停、附魔、复位与承载均使用真实控制器验证。

</details>

### G12 配重双台

**可使用区域：全部。**

- **玩法**：站上一侧平台，该台缓慢下降，另一台同步上升；玩家选择离台时机，再跳向正在变化的另一落点。
- **构成与变化**：C03×2＋配重驱动；两台间距、高差、行程和升降速度；两台共享确定的联动进度，用于横向换位或向上接续。
- **恢复**：两台都无人承载时缓慢回到初始位置；失败后整组复位。

<details>
<summary>G12 配重双台：装配参数与运行合同</summary>

| 字段 | 类型／单位 | 默认值 | 合法值与作用 |
| --- | --- | --- | --- |
| `upper_offsets` | A／B 上端点 | `A:[-128,-96]`；`B:[128,-96]` | 两台各自上端点相对预组原点的位置，允许不同水平间距与高度。 |
| `stroke` | A／B 垂直行程 | `A:192`；`B:192` | 各自大于零；下端点由上端点加 `[0,stroke]` 派生。 |
| `platform_sizes` | A／B 宽高 | 两台均 `[128,24]` | 每台两维为正，可分别编辑。 |
| `driver_offset` | 点 | `[0,-144]` | 驱动及配重关系的编辑参考位置；装饰与可见绳路按实际布局配置。 |
| `rest_progress` | 归一化进度 | `0.5` | `[0,1]`；用于初态、双空归位和挑战复位。 |
| `loaded_rate` | 进度／秒 | `0.35` | 有限正数；单侧真实承载时推进共享进度的速率。 |
| `return_rate` | 进度／秒 | `0.15` | 有限正数；双空时向 `rest_progress` 归位。 |
| `drive_id` | 派生实例引用 | 创建的配重驱动 ID | 两台引用同一实际驱动；共享进度由驱动持有，实际线速度由各自行程乘进度速率派生。 |
| `state_scope`／`section_id` | 状态寿命／分区 ID | `attempt`／`main` | 两台及驱动共同恢复。 |

**固定成员与连线**：C03×2＋配重驱动。令共享进度为 `p`：A 位置为 `A_upper+[0,A_stroke×p]`，B 位置为 `B_upper+[0,B_stroke×(1-p)]`。A 单侧承载时 p 增加，B 单侧承载时 p 减少；双侧承载保持，双空按返回速率归位。承载事实在同一物理步汇总，p 钳制到 `[0,1]`。编辑器拖动一台时平移其上下端点，运行位置仍由共享进度派生。两台消费驱动位姿并提供 C03 承载；独立往返周期由本组共享进度取代。

**验收**：单侧、双空、双侧及边界进度均正确；两台不同行程仍保持互反进度；离台、换台和失败复位后可重新挑战。

</details>

### G14 双路切换组

**可使用区域：全部。**

- **玩法**：射中控制点，在 A、B 两组装置之间切换激活状态，例如一条路打开时另一条关闭，一组载台运行时另一组暂停。
- **构成与变化**：C01＋互斥切换行为＋实际目标；连接门、载台、转向梁或发射口，用可见线路与状态灯表达当前启用的一组；复用射击开关、反向信号与目标组件。
- **恢复**：两组状态一起切换；关门空间被玩家占用时等待。临时组随本段复位。

<details>
<summary>G14 双路切换组：装配参数与运行合同</summary>

| 字段 | 类型／单位 | 默认值 | 合法值与作用 |
| --- | --- | --- | --- |
| `member_offsets` | 角色→点 | `bell:[-128,0]`；`driver:[0,-96]`；`gate_a:[64,-64]`；`gate_b:[160,-64]` | 最小预览由铃、协调器和两扇门组成；可替换为本预组允许的实际成员，逐件编辑位置与形状。 |
| `groups` | A／B 成员列表 | `A:[gate_a]`；`B:[gate_b]` | 两组各有至少一个目标；同一目标只有一套明确的互补状态映射。成员数量由列表派生。 |
| `target_bindings` | 类型化端口与值 | 两门均为 `set_active`，激活 `true`、停用 `false` | 门、载台、转向梁或发射口引用自身声明的输入端口；姿态值、布尔值等与端口类型一致。 |
| `initial_route` | 枚举 | `A` | `A`／`B`；初态为该组激活、另一组停用。 |
| `warning_duration` | 秒 | `0.25` | 大于等于零；由切换协调器持有一次预告时钟。成员的预告表现读取该阶段。 |
| `coordinator_id` | 派生实例引用 | 创建的切换协调器 ID | 关联目标受理事务；成员具体运动仍有自己的时钟，运动 `drive_id` 保持原归属。 |
| `state_scope`／`section_id` | 状态寿命／分区 ID | `attempt`／`main` | 临时控制源、协调器与两组目标保持一致。 |

**固定成员与连线**：C01＋互斥切换协调器＋A/B 目标。C01 为 `repeat_enabled=true`、`duration=0`，`active(bool) → coordinator.set_active(bool)`，`false` 对应 A，`true` 对应 B；铃的 `initial_active` 按初始路由一致初始化。协调器使用 `motion_mode=targets`，各成员保持自己的运动所有者。真实命中提出另一组目标，经过预告和全组占用检查后原子接受两组目标值；成员随后按自身合法动作执行。持续运行的载台或发射口在进入目标运行状态后，视为本次控制已完成；有限转动等动作完成本次姿态变化后，整组重新待发。

**忙态**：预告、占用等待和切换执行期间，再次触发只反馈当前目标与进度；维持本次目标，清空该次新请求，不排队。当前接受状态、当前请求目标和成员真实形态分别保存。不同类型成员保留自己的动作时长，整组接受时刻统一。

**验收**：A/B 互补、门防夹等待、异类成员不同动作时长及忙态重触正确；控制源与目标事务保持一致，实际碰撞始终对应成员真实形态。

</details>

### G16 一次性开路组

**可使用区域：全部。**

- **玩法**：射中锁扣，使装置到达预设终态，形成永久通路；例如射掉桥头锁扣，吊桥落平，两岸连通。
- **构成与变化**：树干倒下搭桥、铁闸升起、悬石落稳成为踏脚台。每个实例采用一种结果，复用 C01、C09、永久结果协调与对应地形组件，预告、危险与占用规则沿用原组件。
- **恢复**：完成后永久生效；形态、碰撞与世界结果一致提交，死亡、回访与读档恢复终态。重复命中保持已完成结果；完成前中断按本段安全重试。

<details>
<summary>G16 一次性开路组：装配参数与运行合同</summary>

| 字段 | 类型／单位 | 默认值 | 合法值与作用 |
| --- | --- | --- | --- |
| `member_offsets` | 角色→点 | `latch:[-96,0]`；`action:[-96,32]`；`coordinator:[0,-64]`；`result:[96,-64]` | 预览采用锁扣、世界行动宿主、协调器和一扇门；结果形态与位置可按选定基本件编辑。 |
| `action_id` | 世界行动 ID | 必填；编辑草稿可空 | 展开时写入 C09 宿主，生产验证解析真实世界行动、资格与永久结果；协调器从宿主读取，完成事实使用世界服务的成功收据。 |
| `section_id` | 分区 ID | `main` | 绑定当前房间的实际分区，并用于完成前的安全恢复。 |
| `result_kind` | 枚举 | `open_gate` | `open_gate`／`lower_beam`／`settle_block`；每个实例采用一种结果，分别引用 C02、G08 或 G10。 |

**固定成员与连线**：C01 锁扣＋C09 世界行动宿主＋永久结果协调器＋一种结果成员。展开时将 C09 的 `action_owner_id` 写为本组协调器的真实实例 ID，形成唯一受托行动宿主；运行时玩家入口为射击 C01 锁扣。`latch.active(bool) → coordinator.request(bool)`，首次合法命中的 `true` 提出执行请求；协调器从该宿主读取真实 `action_id`，统一执行资格检查、结果实体运动与正式世界服务提交。目标到达安全终态后，行动结果、最终形态和碰撞一致提交；完成收据同时决定锁扣的完成表现。门初态关闭；降梁默认 `pivot_fraction=0`、`angles_deg=[0,-90]`、`initial_pose=1`，终态为姿态0；落块采用 G10 默认悬挂和 `[0,192]` 落点。各结果成员沿自身预告、运动、危险及占用参数执行，组层读取过程状态。

**验收**：行动缺失、资格不足和提交失败均保持已成立的永久事实；完成前中断可安全重试；完成后重复命中、死亡、跨房与读档恢复同一终态。验证 C09 的唯一受托绑定、复制后的归属、锁扣启动入口及终态提交时机；桥、门和落块分别验证最终支撑与真实通路。

</details>

### P01 风车渡台

**可使用区域：全部。**

- **玩法**：数个保持水平的踏台绕可见风车轴转动，射铃统一启动或暂停；玩家搭乘踏台，在合适高度反冲离台。
- **构成与变化**：踏台数量、缺位、半径、转速和出口高度。复用 C01＋C03 和共轴运动行为，由同一轮轴驱动圆周轨迹，保持各踏台相位关系。
- **恢复**：反复操作；岸边提供稳定准备台和可再次命中的风铃，失败后整组复位。**时控：共用轮轴的转动进度。**

<details>
<summary>P01 风车渡台：装配参数与运行合同</summary>

| 字段 | 类型／单位 | 默认值 | 合法值与作用 |
| --- | --- | --- | --- |
| `member_offsets` | 角色→点 | `drive:[0,0]`；`bell:[-224,0]` | 驱动位置为轮轴中心；铃可自由调整，其他射击点沿 C01 配置。 |
| `radius` | 距离 | `160` | 有限正数；踏台中心的公转半径。 |
| `angle_offsets_deg` | 角度列表 | `[0,90,180,270]` | 至少一个有限偏角，按 360° 归一化后互异；列表是踏台数量及缺位的权威来源。偏角绑定成员稳定 ID。 |
| `initial_angle_deg` | 角度 | `0` | 有限数按 360° 归一化；所有踏台共用的初始轮轴角度。 |
| `period` | 秒／整圈 | `8.0` | 有限正数；角速度由 `360/period` 派生。 |
| `direction` | 枚举 | `clockwise` | `clockwise`／`counterclockwise`，分别使用正／负角速度。 |
| `platform_size` | 新成员默认宽高 | `[128,24]` | 两维为正；展开后可逐台编辑实际尺寸。 |
| `initial_running` | 布尔 | `false` | 同次设置铃的控制状态与轮轴运行状态。 |
| `drive_id` | 派生实例引用 | 创建的共轴驱动 ID | 所有踏台引用该所有者；初始位置由中心、半径、偏角与初始轮轴角度派生。 |
| `state_scope`／`section_id` | 状态寿命／分区 ID | `attempt`／`main` | 铃、驱动与踏台共同复位。 |

**固定成员与连线**：C01＋共轴运动驱动＋偏角列表对应的 C03 踏台。C01 为反复切换、`duration=0`，`active(bool)` 控制驱动运行。踏台保持水平，位置读取同一角相位；数量由偏角列表长度派生，初相位显示由 `initial_angle_deg/360` 派生。共享运动及合法时间附魔按 `drive_id` 结算一次。

**验收**：数量、缺位、正反转与初始角度生效；启停和时控保持相对偏角；各踏台尺寸、轮轴装饰与完整角色包络相容，真实承载和离台可执行。

</details>

### P02 交替翻板桥

**可使用区域：全部。**

- **玩法**：前后两组短桥交替展开与向下折起。初始 A 展开、B 收起；从 A 起跳后射铃，借反冲落到展开的 B，再前往终点。
- **构成与变化**：桥面数量、高差、间距与风铃位置。使用 C01＋多件 G08，采用 G14 同源的互斥切换行为；射铃交换两组状态；风铃射向与反冲落点共同决定布局。
- **恢复**：反复操作，支持来回通行；转动有预告，整组沿共用扫掠占用规则同步切换。两端稳定，失败后按实际进入侧恢复可重新起步的初始状态。

<details>
<summary>P02 交替翻板桥：装配参数与运行合同</summary>

| 字段 | 类型／单位 | 默认值 | 合法值与作用 |
| --- | --- | --- | --- |
| `member_offsets` | 角色→点 | `bell:[-224,32]`；`drive:[0,-64]`；`bridge_a:[-160,0]`；`bridge_b:[32,0]` | 两桥位置为铰点参考，G08 的 `pivot_fraction=0`。可编辑数量、高差、间距与铰点；成员几何仍由各 G08 持有。 |
| `bell.access_points` | 预组原点下的点数组 | `[[224,32]]` | 默认两端可操作同一风铃；仅加预组整体偏移一次，转换成 C01 的房间坐标，可按两向射线调整。 |
| `groups` | A／B 翻板列表 | `A:[bridge_a]`；`B:[bridge_b]` | 两组各至少一个 G08，数量由成员列表派生。 |
| `beam_size` | 新翻板默认宽高 | `[128,24]` | 两维为正，分别映射至 G08 的 `beam_length`、`beam_thickness`；展开后每块板可独立调整。 |
| `deployed_angles_deg` | 成员→角度 | 各成员 `0` | 写入各板 `angles_deg[0]`，沿 G08 的支点和角度合同解析。 |
| `folded_angles_deg` | 成员→角度 | 各成员 `90` | 写入各板 `angles_deg[1]`，可分别选择向下折叠方向；与该板展开姿态不同。 |
| `initial_route` | 枚举 | `A` | `A`／`B`；激活组展开，另一组收起。 |
| `warning_duration` | 秒 | `0.25` | 大于等于零；驱动统一预告一次。 |
| `turn_duration` | 秒 | `0.40` | 有限正数；全组同次转动的统一时长，成员转动进度由驱动派生。 |
| `drive_id` | 派生实例引用 | 创建的翻板驱动 ID | 共用互斥目标、扫掠占用和转动进度；成员使用该所有者的姿态进度。 |
| `state_scope`／`section_id` | 状态寿命／分区 ID | `attempt`／`main` | 整组随当前挑战复位；房间按真实进入侧选择安全恢复点。 |

**固定成员与连线**：C01＋G14 同源互斥切换行为＋多件 G08。C01 为 `repeat_enabled=true`、`duration=0`，`active(bool) → drive.set_active(bool)`，`false` 对应 A，`true` 对应 B；铃的 `initial_active` 与已接受路线一致。驱动使用 `motion_mode=synchronized_beams`，统一替代成员的转动时钟。默认 A 展开、B 收起，命中后交换两组目标；预告与全组扫掠占用通过后，所有翻板按同一转动进度前往各自目标角度。预告、等待和转动中再次触发反馈当前目标。铃的两端受击点共用身份与命中收据。

**验收**：A/B 姿态互补，任意一块板占用时整组安全等待；正反来向均能从稳定准备位置调整到可起步状态；原地复位、射线和反冲落点符合本房实际参数。

</details>

### P04 传铃栈道

**可使用区域：全部。**

- **玩法**：射响起点铃，铃声与亮光沿栈道逐段传递，木板依次展开、向下收起；玩家用跳跃与反冲跟随通路前进。
- **构成与变化**：相邻段启动间隔、完全展开保持时间、展开／收起时间与高差；稳定重叠窗口由时序推导，长路线设置稳定歇脚台。复用 C01＋G08 和顺序波次行为，由同一进度调度整串木板。
- **恢复**：反复操作，一轮结束后重新待发；运行中显示当前进度。失误后回本段准备台，整串复位。**时控：整串展开与收起进度。**

<details>
<summary>P04 传铃栈道：装配参数与运行合同</summary>

| 字段 | 类型／单位 | 默认值 | 合法值与作用 |
| --- | --- | --- | --- |
| `member_offsets` | 角色→点 | `bell:[-96,32]`；`drive:[0,-64]`；`board_0:[0,0]`；`board_1:[160,0]`；`board_2:[320,0]` | 板位置为铰点参考，G08 的 `pivot_fraction=0`，允许改变空间走向与高差；起点、终点和歇脚地形由房间配置。 |
| `members_order` | 有序成员 ID 列表 | `[board_0,board_1,board_2]` | 至少一件、每件恰出现一次；该列表确定启动顺序与数量，空间坐标保持独立。 |
| `beam_size` | 新翻板默认宽高 | `[128,24]` | 两维为正，分别映射至 G08 的 `beam_length`、`beam_thickness`；展开后可逐板调整几何。 |
| `deployed_angles_deg`／`folded_angles_deg` | 成员→角度 | 各成员 `0`／`90` | 依次映射到各板 `angles_deg[0/1]`，沿 G08 角度与支点合同解析。 |
| `warning_duration`（W） | 秒 | `0.25` | 大于等于零；整串启动前的统一预告。 |
| `deploy_duration`（E） | 秒 | `0.25` | 有限正数；每件从收起到展开的持续时间。 |
| `start_interval`（Δ） | 秒 | `0.60` | 有限正数；相邻成员开始展开的时间差。 |
| `hold_duration`（H） | 秒 | `1.20` | 有限正数；从完全展开开始，到开始收起为止。 |
| `retract_duration`（R） | 秒 | `0.25` | 有限正数；每件从展开到收起的持续时间。 |
| `stable_overlap`／`stable_gap` | 派生秒数 | `0.60`／`0` | 分别为 `max(0,H−Δ)` 和 `max(0,Δ−H)`；显示相邻稳定窗口的重叠或空档。 |
| `total_duration` | 派生秒数 | `3.15` | 三件默认实例为 `W+(N−1)×Δ+E+H+R`；这里是没有占用等待时的一轮阶段时长。 |
| `drive_id` | 派生实例引用 | 创建的顺序波次驱动 ID | 整串只有一个波次进度；子件的开始、保持、收起和相位从该进度采样。 |
| `state_scope`／`section_id` | 状态寿命／分区 ID | `attempt`／`main` | 失败时取消旧波次并把所属整串恢复待发状态。 |

**固定成员与连线**：C01＋顺序波次驱动＋有序 G08 成员。C01 为 `repeat_enabled=true`、`duration=0`；所有木板固定采用 G08 的 `rotation_mode=step`，展开时写入 `initial_pose=1`。通过 `bell.active(bool) → drive.trigger(bool)`，波次驱动把每次已接受变化作为一次启动请求，两个变化方向都可启动下一轮。待发时同次接受源状态变化与波次启动，运行中再次命中仅反馈当前目标与进度，源状态保持当前接受值。玩家通过控制铃启动波次，木板的直接受击按从动成员合同反馈，运行姿态始终由波次驱动采样。

**初态与恢复**：新实例与挑战复位时，铃的 `initial_active=false`，波次驱动以已接受输入 `false`、零进度和待发状态静默初始化，并统一安装所有木板的姿态1（收起）。一轮结束后木板保持收起，驱动恢复待发，铃保留本轮已接受的布尔值，下一次合法变化可启动下一轮。装载已有尝试状态时，铃、驱动与成员姿态按同一状态快照静默恢复，恢复值本身不产生新的波次请求。

**时序**：第 i 件从 `W+i×Δ` 开始展开，在 `W+i×Δ+E` 完全展开，保持 H 后用 R 收起，i 从 0 开始。数量由顺序列表派生；重叠、空档和总时长为只读计算结果。成员几何和先后次序可分别编辑，时序使用统一权威参数。

**安全与时间**：预告完成后，驱动按物理步检查所有子件下一步扫掠；需要占用等待时保持当前安全相位并暂停整串进度，条件满足后继续。合法时间附魔作用于该顺序驱动，装备寿命沿基本库独立计时；子件姿态、传铃反馈和收起进度读取同一波次时钟。

**验收**：三件默认时序与公式一致，调整顺序、数量和高差后仍正确；重叠与空档显示准确；任一成员占用等待保持全串相位，忙态无排队。验证首次装载与挑战复位的全部收起、连续两轮由两个布尔变化方向启动、运行状态静默恢复，以及直接命中木板时与驱动一致的反馈。

</details>

## 4. 房间组合推荐

以下用法提供行动与空间关系的启发，地形、布局、数量和参数按本房目标设计；房间作者可以提出其他符合基本行为的组合。

| 组合方向 | 玩家体验与关键条件 |
| --- | --- |
| 射击开路＋反冲 | 射中风铃打开通路，同时借反冲前进；布置保证弹丸开门后身体才到达门口。 |
| 坍塌台＋换向 | 落地恢复后及时选择下一射向；准备位置与终点有稳定支撑。 |
| 滑轨台＋换位 | 先调整站位，再处理载台前进与身体反冲；台宽和操作位置容纳所展示的动作。 |
| 伸缩刺＋爬墙 | 等露墙窗口贴墙，再离墙接续；按真实动作耗时配置窗口。 |
| 移动钩点＋接力 | 先取得射线，选择截获和离钩时机；钩空有合法失误去向。 |
| 压力板＋探索回环 | 离板保持覆盖全身通过的真实耗时，另一侧取得永久开路成果。 |
