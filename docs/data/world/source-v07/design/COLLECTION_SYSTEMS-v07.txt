收集、成长、装备与休息周期：v07 完整设计规则
============================================

定位与依据
----------
本文件整合此前 collection-system-v03.json 中不依赖旧位置的系统规则，
并以最新用户确认与当前 world-room-layout-v07.json 为准。位置以当前309房主数据为准；收集总量不随扩容增加。
配套 collection-catalog-v07.json 保存系统参数分层与50个装备来源槽的引用。

权威顺序：最新用户确认 > 当前世界 canonical 的位置/分区/行动/库存身份 >
本文件明确标注的试制默认与效果提案。所有房号、section、领取前置、Boss、
修钟与物品门条件只从当前 canonical 读取，不使用旧收集表的 anchor/requires。

状态分三层，不能混淆：
  【已确认】用户明确决定的规则与数量方向。
  【当前设计预算】世界图已据此分配唯一ID/来源，可以用于结构灰盒。
  【试制默认/提案】先前给出的具体数值或效果预算，仍可通过实机调整。

尤其：旧资料没有已经选定的50件完整装备效果表。原文是“48件旧装备＋2件
新工具，具体48件尚未锁定”。本次保留完整数量、渠道、功能/负荷预算及
迁移合同，不把50个来源槽包装成50件已经完成的装备设计。

一、总量与三套武器账
--------------------
【已确认】攻击合金8份，四次升级分别消耗1、2、2、3，永久提高武器攻击力。
【已确认】另一套是6件独立武器分支材料＋2枚共享技能材料，总计8件大奖励。
这两套“8”不同：合起来是16个武器成长材料来源，不能相互挪用。
初始枪之外的手里剑、炸弹本体是另外2个解锁，不计入这16件材料。

【当前设计预算】
  装备50件：28地图＋12商店＋6任务＋4齿轮兑奖，包含灯与抗毒滤芯。
  失步齿轮40枚；负荷扩容6份，每份+1。
  生命碎片12片；共鸣碎片6片。
  所有这些奖励均是永久、唯一，不随死亡、休息、切房或读档再次发放。
  新增商人只是分配已有12个商店槽，当前9家商店不扩大50件总额。

二、攻击、分支与技能
------------------
攻击材料同一种，工作名“恒时合金”。三种武器家族及其分支共享攻击等级，
后来获得的武器继承既有等级；这是当前采用的成长提案，避免重复升级三套。

攻击等级       0      1      2      3      4
本次合金消耗   —      1      2      2      3
累计消耗       0      1      3      5      8
普通枪单枪B    5      9     13     17     21

消耗1/2/2/3已确认。B=5/9/13/17/21是试制数值，不是最终平衡承诺。
当前武器匠攻击升级动作 gold_fee=0 是工作默认；不能据此把其他未定价服务
解释成免费。普通结局不要求满级，敌人也不随玩家升级自动等比例涨血。

【最新已确认攻击规则】完整攻击就是一枪；三连枪或激光完整命中同一目标
合计1.5B。普通Boss安全窗口通常2枪，第3枪属于贪刀。最简单普通敌人9HP。
本设计不沿用旧表“早期8HP”或以统一40枪推导所有Boss血量的示例。
三连分弹、激光分段必须共用一次发射预算；不能每个tick另发一整份1.5B。
发射持续时间、射速和Boss具体血量属于后续战斗调试，不由收集表擅自改动。

六件分支材料与当前武器匠服务：
  三联机芯 -> forge_triple       枪的三连分支
  恒流晶匣 -> forge_laser        枪的激光分支
  散华刃胚 -> forge_fan          手里剑散华分支
  回旋轮轴 -> forge_boomerang    遥控回旋刃分支
  磁轨引信 -> forge_magnetic     磁吸遥爆雷分支
  坍缩线圈 -> forge_singularity  坍缩奇点分支
每件只解锁自己的分支，不升攻击等级，不自动解锁别的分支。最终招式细节
仍属武器设计，不因材料已经定位就视作实现完成。

两枚共用技能芯属于同一种库存，当前方案在武器匠分别安装到全局技能层1、2。
第一枚开放各武器家族的第1技能，第二枚开放第2技能，后来取得的武器继承。
技能动作、消耗和效果可以继续扩展；不能把两枚芯改成每个武器都要重复收集。
材料拾取与安装是两个交互，具体行动均引用 canonical.service_actions。

三、生命、共鸣与装备负荷
------------------------
【试制默认，来源总量已进入当前地图预算】
  生命：初始5HP，12片，每4片永久+1基础上限，收齐为8HP。
  共鸣：初始上限100，6片，每2片永久+20，收齐为160。
  负荷：初始8，6次+1，收齐为14；“六次每次+1”已确认，初始8是默认。

生命与共鸣碎片的合成应保存已获得ID、累计数和已兑现档位，不能读档重复
增加上限。是否在凑齐时即时表现为合成动画可在UI实现中决定，不改变收据。
生命上限增长是否同时补回新增HP尚未独立确认，不能隐式充满全部生命。
共鸣碎片只增加容量：取得或装卸不免费充满，不增加慢时预算/空中动作次数。
休息对HP恢复已确认；共鸣自然恢复、技能消耗和休息补充方式另按现有系统
及后续战斗设计明确，不能拿“HP恢复”推导所有资源都自动补满。

灯与抗毒滤芯是可装卸装备，【已确认】不能做永久被动能力。
当前各负荷1；它们计入50件，不再额外占2个新来源。lamp/filter所有权与
eq_lamp/eq_filter当前装配状态分开保存。拥有但未装备时不满足相关物品门。
换装遵循休息区的装配边界。卸下后可以重新装备，不据此新增复杂防困死规则。
Q不提供实体环境抗性：抗毒效果由滤芯本身提供，Q仍不能穿毒水或熔岩。

四、50件装备如何交接
-------------------
已落地的是50个唯一来源槽及两个工具身份；另外48件尚未绑定最终旧装备ID。
collection-catalog-v07.json逐槽列出reward_id、来源渠道和当前数据引用；
shop槽引用stock记录，其他槽引用实际action。空catalog_equipment_id表示
尚待选型，不能在游戏中当作已经有完整效果的装备。

沿用的功能预算【提案】：
  普攻与武器差异8；反冲与空中作战8；技能与资源8；防御与容错8；
  探索与环境6；伴机与联动6；风险与经济6。合计50，环境两工具在其中。

沿用的负荷分布【提案】：
  负荷1：8件；负荷2：22件；负荷3：12件；负荷4：6件；负荷5：2件。
不能仅为凑分布添加新奖励，也不能由此认定某个来源槽已经绑定固定负荷。

旧目录曾盘点72件候选、16件带升级结构，这是来源信息，不是本版保留名单。
迁移每件装备时必须写明：稳定装备ID、负荷、效果触发、叠加/互斥、升级档位、
破损规则、休息周期额度、是否锁装和装卸副作用。现有永久来源不变；更换
候选效果时只改catalog绑定，保留reward_id和已领取收据。

【已确认】同名重复装备升级改为给NPC付金币升级同一个永久装备ID。
当前服务分工：织时匠负责装备升级/维修；武器匠负责攻击/分支/技能芯。
织时匠位置与NPC身份引用canonical.npcs，不能照旧P0宏观坐标再放一个NPC。
并非全部48件都自动拥有Lv2/Lv3。最终可升级名单、价目、档位和阶段限制
尚未冻结；它们是后续逐件设计，不能生成无限金钱升级或重复掉落副本。

破损装备【保留候选机制】：所有权和破损状态永久；付费维修只恢复装备状态。
维修不回血、不结束周期、不解除锁装、不刷新一次性效果。最终保留哪件带
破损属性的装备仍随48件选型决定，不能把“候选机制”套到全装备上。
依赖肉鸽商店随机刷新/稀有度的旧效果需逐件重做或移出首发；休息不补货。

五、失步齿轮与累计兑奖
--------------------
40枚是唯一可回收对象，永久保存collected_ids、delivered_ids及已领取里程碑。
交付将真实未交付ID转入累计交付集合，不因领奖降低累计数。到过NPC、路过
齿轮或看到地图标记均不算取得/交付。每枚常规金币回报是提案，数额待定。

当前里程碑（均已计入原总预算，不额外复制同类奖励）：
   4枚 -> EQ_GEAR01，装备
   8枚 -> CAP03，负荷+1
  12枚 -> HP12，生命碎片
  16枚 -> EQ_GEAR02，装备
  20枚 -> ATK08，攻击合金
  24枚 -> CAP05，负荷+1
  28枚 -> RES06，共鸣碎片
  32枚 -> EQ_GEAR03，装备；遗漏提示为候选附加服务
  36枚 -> EQ_GEAR04，装备
  40枚 -> GEAR_EPILOGUE，小站万象钟演出/纪念/短尾声提案

普通与真结局均不要求齿轮全收集或装备100%。40枚终点不再锁战力/结局。
真结局探索条件与剧情材料仍完全按canonical.endings，不借本表添加新锁。

取得方式预算【提案】：20观察探索、8短动作、8战斗机关、4局部时间异象。
复用四类模板，避免为了40枚制造40套独立时间系统。部分取得顺便修复安全
机关或回程，累计交付逐步改变小站的声音和画面，形成与世界修钟一致的反馈。
具体每枚的当前位置、环境路线和领取条件已经在canonical，不复制旧区域预算。

六、休息周期与四层保存
----------------------
【已确认】原装备文案“本局”“每图”和锁装的边界改为休息区的明确休息。
明确休息：恢复HP、登记复活点、重置普通敌人、推进周期、重新选择装配。
不会重置已败Boss、唯一奖励、材料升级、装备所有权、修钟或捷径。

换房、换区域、交通机器、进安全房、NPC对话、锻造、购物、维修、交付、
自动保存及重新读取存档均不自动休息，不刷新护盾/救命/经济等周期次数。
“休息后再次锁装”的具体逐件行为需要明确；休息不是永久强制卸下所有装备。
周期刷新只重置额度，不能让回血类装备在满HP休息瞬间白白消耗额度。

地形失败【最新已确认】：普通扣1HP，标记特别地形如熔岩扣2HP；本次失败
只扣一次，HP<=0执行死亡；仍存活则回本段实际进入侧。回退不回血、不结束
周期、不全图刷新敌人，不借回退到达尚未进入的一侧。

死亡回最后真实休息点【已确认】。沿旧提案“复活恢复HP、开启新周期并重置
普通敌人”仍是运行时试制默认，不能说用户已逐字冻结；金币死亡损失政策
尚未确定。它们不改变永久世界结果，也不影响本包结构路线的逻辑可达性。

保存层建议：
  永久世界层：唯一收据、物品/材料库存、装备等级/破损、能力、NPC任务、
              Boss、修钟、捷径、裂缝解锁、已见地标、商店售出、累计交付。
  休息周期层：周期ID、当前装配/锁装、一次性额度、普通敌人周期状态。
  挑战尝试层：当前房/分区、实际来向、挑战进入锚点、局部可复位机关状态。
  动作瞬态层：反冲位移/Q资格和2秒冷却、攻击包、当前射线等。
重新读档不能等价执行一次休息；动作瞬态以安全重建处理，不重发永久授予。

七、接口完成度与后续工作
----------------------
当前可用于世界结构灰盒：唯一收据与奖励占位、材料库存、武器匠三套成长
接口、齿轮实际交付和里程碑、NPC服务入口、商店报价/售出记录、装备槽位。
商城空价格不是0金币；当前商店未定价时可以查看报价占位，不能自动购买。
织时匠升级/维修职责已有，但全装备效果/价格/逐件升级事务尚未实现完整表。

每次付费/扣料/授予/写收据必须作为一次事务提交，失败不部分扣费、不重复
发奖。不能把模拟的唯一奖励占位或NPC到访报告当作经济/装备效果已验证。

这些缺项不要求重排整个世界：48件最终效果、商店/升级/维修价格、技能
消耗、死亡金币政策、生命升级即时回血和共鸣恢复，需要随运行时切片完善。
收集品的位置与永久ID已固定，后续调试保持这层稳定即可减少大规模返工。
