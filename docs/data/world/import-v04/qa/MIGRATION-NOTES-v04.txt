本次处理什么
------------
把“有能力才准进房门”改成“普通门进入安全预览区，房内真实地形限制深入”。
保留既有大拓扑、所有房号、边号与永久奖励身份；迁移不是重排世界。
同步最新 Q、失败扣血、过门接管、休息边界和修钟视听变化规定。

最终规模
--------
216 个房间、16 个区域、288 条房间连接、248 项行动全部保留。
22 位 Boss、40 个休息点、16 个交通机器、14 位 NPC、9 个商店、15 个地区钟。
26 条捷径，其中 15 条为上轮增加的捷径，本次没有增加新的捷径边。

310 个逻辑分区：
  216 个 main 主体；
   69 个入口安全预览区；
   25 个共享奖励/机关环境侧区。
188 条有向房内路线，即 94 对往返通路，不等于 188 个新挑战。

旧 79 条含 HWDQ 的房间边分别处理为：
  58 条迁为目标房入口至主体的环境通路；
  21 条捷径删去已由开关前路证明的重复能力条件。

除了这 58 个旧边位置，A-R11、A-R12 和 V-R05 的原前厅/战斗可达条件需
显式落实到各入口，因此共形成 69 个入口预览区。这里没有新增房间。
179 项含能力条件的旧行动全部移除隐藏领取检查；只有确实未被到场路径
保证的要求才需要环境侧区，并按“同房、同条件”合并为 25 个共享区。

正确性依据
----------
1. 对每条旧条件先规范正逻辑 DNF。分离能力条件和非能力条件后重新合取，
   必须与原 DNF 等价。遇到无法精确分离的混合 OR 就停止迁移。本次全部通过。

2. 对旧图枚举 H/W/D/Q 的全部 16 个组合，并把其他旗标放宽。这个放宽图
   给出保守的“到场是否已经必然拥有能力”证明；不是实际玩家路线。
   到场必然拥有所需能力时，行动不再加一次隐藏资格。否则落实到实际侧区。

3. 21 条捷径逐个检查每种开关能力分支是否蕴含至少一种原通行分支；
   同时检查四能力永久、不消耗。完整开关及能力证据见机器审计。
   真实开关物件、操作侧、门条件与后续房间条件仍保留。

4. 所有连接的两端分区、内部路线端点、行动位置存在；Boss defeat 均位于
   main。原房号/边号/端点/行动ID/授予内容不变。13项迁移不变量均为 true。

5. 迁移器不代替路线模拟。v04 模拟独立使用实际初始库存、行动、状态、
   Boss阻挡、已发现传送点和唯一领取凭据核对通关与回访；以其最终报告为准。

清理掉的旧权威
--------------
从当前数据移除旧 route_plans、state_verification、development_artifacts；
删除旧 Boss minimum_count_proof/route_replays/checks 与旧休息覆盖结果。
boss_plan、rest_plan、pacing_guidance 改指 v04 报告，不再声称 v03 的旧房门
图可以证明当前分区图的最低Boss数、重试距离或时长。
最低Boss数、普通12区、真结局16区等保留为设计目标；实际覆盖由新报告核对。

regions.split、房间 gate_summary/macro_gate_policy、关键房 purpose、NPC/
奖励/任务/快捷机关镜像、商品 source_requires、结局 requires 均同步分区。
世界与区域描述明确：区域时间主题不改变玩家基础移动；修钟主要改变美术、
BGM、环境音，便利旧路但不削弱独立挑战房。

仍需要灰盒来验证的事
--------------------
环境分区必须由真实运动可达性实现，尤其要检查无 H/W/D/Q 能否用现有
反冲、墙边技巧或自动过门越过本来应阻挡的段落。当前数据只给出约束，
不会凭空证明具体跳跃轨迹。

2 秒 Q 冷却的实际等待、实体危险碰撞优先级、向上自动落脚、下落安全台、
相机边界、Boss重试步行耗时、战斗质量、路线记忆效果仍待 Godot 验证。
物品价格、普通装备效果和敌人/Boss最终数值可继续在结构灰盒之后调试。

此包足以明确“该搭哪些房、连到哪里、从哪侧看到何种阻隔、通过后取得什么、
什么状态打开旧路”。它不把尚未施工的房内几何与战斗宣称为完成品。
