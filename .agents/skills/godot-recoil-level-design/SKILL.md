# Godot 多能力关卡设计

## 适用任务

围绕玩家观察、能力选择与切换、位移、落点和下一步机会设计。反冲是本项目的基础动作特色，区域与房间可由不同能力或组合承担主要判断。整区任务先编排区域，单房任务从本房职责与已知来向开始。用真实游戏运行及专业审看收束。项目圣经与对象规范持有现行规则，本 skill 提供制作方法；项目路径、示例和行为线索须在目标版本核实。

按任务加载：

- 做整区、房间分工或节奏调整：读 [区域编排](references/region-planning.md)。
- 做具体房间、机关或布怪：读 [房间与遭遇](references/room-and-enemies.md)。
- 涉及多能力、能力门或获得新能力后回访：读 [能力组合](references/ability-composition.md)，再读相关能力的现行规范。
- 复现冻结试玩时可查 [旧平原应用](references/windchime-plains.md)。重做房间采用本次新设计的空间和能力约束。
- 实现、验证和交付：读 [交付检查](references/delivery-checks.md)。

只加载当前阶段及直接依赖；按需引用项目规则。用户只要求规范或规划时，完成对应交付。用户要求生成完整区域时，持续完成其范围内的房间与串联验证；代表样房只是校准环节。

各区域复用本流程，由各自 Bible 提供特色和能力侧重，能力对象规范提供真实行为与参数。不按区域复制 Skill；只有某机制需要独立、反复使用的制作与验证流程时才拆出专项方法。

## 操作

### 1. 确认当前真实输入

读仓库 `AGENTS.md`、当前工作线与模块导航，核对分支、未提交改动、实际运行入口和引擎版本。以本次用户指令确定范围；按项目现行权威关系读取世界、区域、动作、敌人及状态规则。核实文档所称“已接入/未接入”是否与真实消费者一致。

在 gunman-rush 中，新房使用 `production/` 的 Godot 资源根。按[房间制作](../../../docs/bible/room_authoring.md)选择 TileSet、机关定义和物种，检查实例 ID、来源、位置、状态及端口。启动宿主为 OrdinaryRoomSession；参考 `production/tests/assembly_room.json` 与 `tools/check_ordinary_rooms.py`。从项目锁定的世界包提取本房及直接邻房的门线、房形、通行条件和能力授予。灰盒阶段即按世界门号检查实际越界方向。

### 2. 编排整个区域

按 [区域编排](references/region-planning.md) 建一份全区职责表，覆盖每个目标房和不同来向。结合主线、支路、枢纽、休息、Boss、奖励、地标与能力回访安排学习和压力起伏。标出区域主要动作与协同能力的学习/运用节点；按实际授予和区域主题安排重点，不要求每段都由反冲单独完成。

为相邻房间安排不同的主要体验；让子区域在空间关系、遭遇方式和地标上有辨识度。根据实际路线判断重复，允许有目的的练习与回访。使用轻战斗、探索、观察和舒缓连接挑战，不把全部房间都做成多拍连跳。

### 3. 共同确定房间布局与构图

创建或重做房间时，同时读取[房间美术](../godot-room-art/SKILL.md)。同一位作者按[房间制作的构思流程](../../../docs/bible/room_authoring.md#布局与构图)把空间与画面放进同一份设计。摆放关键地形前，先从玩家视角判断此处有哪些信息需要看清、哪些可以延后揭示，再选空间关系与场景形态。房间主题、能力与可复用素材影响选择。单项调参或审查只处理受影响的关系。

每房使用一个精简合同：用途、各来向可用能力与最低通行组合、主要动作和协同关系、后续局面、敌人职责、压力、允许解法、失误去向、出口/奖励/状态引用。房间实例数据与运行时共享定义。

声明承担反冲通行的环节，用实际地形或机关让反冲承担推进；多能力环节按 [能力组合](references/ability-composition.md) 区分正式能力锁、动作练习和高效路线，接受该阶段允许的替代解。普通战斗允许站射、走位或绕行，能力通过换边、后撤、制高点及动作接续提供价值。

在普通穿越、宽落点与探索通道中主动考虑敌人。复杂连续障碍段优先保证动作可读与恢复；按 [房间与遭遇](references/room-and-enemies.md) 安排威胁，不按面积或统一配额填怪。对空白段说明观察、辨路、休息或叙事用途；无用途则缩短或设计有效互动。

### 4. 按真实能力实现

实测当前合法能力、身体包络、资源、冷却与动作范围；多能力段额外验证切换、取消、恢复和保护对象。枚举低层、梁顶、移动台端点、敌人附近与来向入口；用这些状态校准跨距、高差、净空和恢复，不把单项最大距离直接相加。

由现行输入/控制器执行动作，表现读取已接受事件。沿用项目敌人、机关、奖励和保存所有者。需要新增区域机制时先定义可观察规则、状态和恢复，做最小机制验证后再使用。根据实际配置维护参数。

并行时按房间或连接簇隔离写集，指定施工总表、共用接口和规则的单写者。先把代表房接进正式装载与相邻房，再按职责表完成剩余内容，每批都保留可运行的连通路线。

第一版可玩房按[布局与构图](../../../docs/bible/room_authoring.md#布局与构图)从邻房走进来，带上影响判断的前后景，试一次关键选择和一次失误恢复。把最早读错路线或无法继续的位置反馈给布局与美术。新遭遇接入后，沿用这条路线复查它对观察、通行与回程的影响。

## 验证与交付

执行 [交付检查](references/delivery-checks.md)：必要的结构检查、真实动作与局部反例、死亡/清怪/休息后的恢复、正式入口的跨房路线，以及正常速度与镜头下的体验审看。

分别写技术结果、专业判断、用户反馈和目标设备结果；根据本次授权判断完成条件。发现缺口时修改对应设计或实现。避免把脚本条数、地图可达或三个样房通过当作完整区域质量。

长期规则直接更新现行正文；数值留实际配置；进度留任务表与一份当前交接。将临时日志、录屏和报告放 `build/` 或构建产物，只保留必要回放与持久来源。

交付当前范围的完整成果、覆盖清单、短原生录像和可运行入口。授权范围为整区实现时，继续到所有目标房被逐项处理并完成串联验证；只在实际阻断上报告明确缺件和可恢复工作。
