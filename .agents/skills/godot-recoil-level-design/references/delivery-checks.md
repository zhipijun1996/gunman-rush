# 验证与完整区域交付

## 对准真实消费者

在目标 Godot 版本与正式房间接口验证。gunman-rush 使用当前 `FixedWorldApp/Provider/Room`、共享玩家及世界状态服务；从现行模块导航选择输入、敌人、机关、保存与构建检查。

读取世界源、施工配置与手工场景的职责边界。构建产物由正式工具生成，实际场景负责碰撞和局部放置；将房间绑定到正式装载，保留来向入口与稳定身份。

使用项目统一镜头、真实入场动作和实体落脚约束。当前 gunman-rush 的竖向门不能横放可穿越接人平台；按现行 room_authoring 使上行短跳、下行下落到合法实体落脚面，并在落稳后恢复控制。边界普通实地保持安全，危险必须有明确实体与可读表现。

## 按风险选检查

每个目标房有覆盖记录，重复共用机制复用已有回归。为新关系和高风险状态增加针对性实机，不为每一处装饰建立测试或重跑全套专项。

| 风险 | 直接证据 |
| --- | --- |
| 反冲通行只是可选表演 | 正常通过；保留子弹/机关、关闭反冲的对照；实际跨距/高差与当前能力包络 |
| 只有第一拍有挑战 | 从已完成前拍的真实状态，省略后一拍的关键动作；包含合法较晚起跳/当前平台相位等相关反例 |
| 机关替代了位移 | 实际打开门或召回台后，再以普通动作尝试目标；射偏时观察真实碰撞/状态 |
| 返还弹药没被使用 | 真实伤害回执、资源恢复、同次腾空的下一枪消耗与之后落地 |
| 失败路变前进旁路 | 从真实低层/坡面/平台状态检查可达方向；接受仍实现核心体验的反冲替代解 |
| 敌人死亡导致卡住 | 命中后失误、已清怪重入、漏枪落地；重新取得本阶段可达目标或验证其正式重试，能退回入口不等于目标仍可完成 |
| 布怪使动作不可读 | 正常镜头查看预警、同时攻击范围、反冲落点和重试点；按主要压力减轻或重排 |
| 几何过苛刻 | 选择少量有理由的时机、瞄准或初相变化；记录覆盖范围，不把离散样本写成成功率 |
| 状态或连接失效 | 正式入口过房、不同来向、清怪/休息/死亡/地形失败/重启后的继续行动 |

“关闭反冲无法通过”的硬性要求用于声明承担反冲通行的环节。普通战斗、枢纽和舒缓房按各自职责验收，不为满足这个检查伪造能力门。

反例注明起点支撑面、资源/机关状态与输入范围。失败回放证明该输入失败；几何与能力数据支持更一般的判断。有限测试不声称穷举全部解法。

## 先单房，再真实路线

验证每房的实际落地、子弹命中、承载、伤害与目标领取；随后通过正式世界路线验证：

- 首访主线可达区域目标并继续/返回，所需能力已经合法授予；核对必经反冲学习与运用节点，核心推进不能全部被普通动作替代。
- 支路能进入、得到当前收益或看懂远期目标，并回到主线。
- 枢纽不同来向、能力预览退回、捷径两端和回访都能正常入场。
- 普通过房不重置休息周期；清怪、开门、奖励、金币及探索按当前状态合同保存。
- 休息、死亡、地形失败与独立进程重启后可继续；唯一奖励和Boss胜利不重复发放。
- 地图、成对门位、施工尺寸与实际场景一致；未施工边界不伪装成可用出口。

图路线通过、占位场景连通、调试胜利都不代替上述实机流程。已有基础可复用，不重造样段状态系统。

## 专业审看

先看正常速度、正常镜头、不写操作答案的片段；必要时另给解释。观察：

1. 玩家行动前能否看到当前问题、相关目标与落点，成功/失败反馈是否明确。
2. 关键一枪为什么值得做，结果是否影响下一步；换坐标或多打几枪是否仍是同一体验。
3. 相邻房的动作节奏、敌人职责、空间展开与紧张程度是否有区别。
4. 失败恢复是否有可读方向和可接受的时间成本；回访是否形成新的理解。
5. 区域机关、地貌、敌人和地标是否共同建立地点特色；表现与碰撞是否一致。

给出有证据的专业判断及待改项，并实际处理本次范围内的问题。固定输入通过不等于初见玩家已学会，也不以必须等待用户试玩作为所有任务的默认终点。

## 完成口径

按请求区分：规范完成、结构灰盒完成、可玩内容完成、正式世界接入和美术完成。完整区域请求须覆盖当前世界源的全部目标房，结合来向、能力和状态验收；某些内容仍是占位时明确列出，继续完成不受阻部分。

整区交付保留：

- 覆盖全部目标房的职责表和实际场景/合同引用。
- 当前有效规则、参数配置、必要回放及其真实消费者。
- 一份简洁结果：覆盖、实际检查、专业判断、明确缺口和入口。
- 少量正常速度原生短片，展示不同类型房间及跨房路线；需要时补一段有意义的恢复。

使用已有任务表和工作线维护进度。临时审计、日志和录像进入 `build/` 或构建产物；不把测试证据堆成需要每个新会话通读的规则库。先规划可独立验证的批次，再持续完成整个授权范围。
