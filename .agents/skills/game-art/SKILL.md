# game-art

所有命令从仓库根目录运行。现行规则见 [AGENTS](../../../AGENTS.md) 与 [当前状态](../../../docs/current_state.md)；数值和玩法不在 skill 中重复定义。

1. 读当前风格/世界锚点、docs/art_quality_target.md、docs/content_pipeline.md 和实际运行素材 manifest。明确是候选母版、技术占位还是用户已认可样板。
2. 先制作一张真实合屏黄金样板，统一角色、背景、地面、机关、UI 材质与色彩；检查危险、支撑、落点和 Boss 弱点可读性。需要用户视觉认可的批量工作先交付样板。
3. 记录原创/生成/第三方来源、许可、哈希和导入方式。母版保留；图像尺寸不决定碰撞/端口，表现不能改变物理、输入、机关相位或伤害。
4. 在真实消费者中接入，确认不是仅放到资源目录。重复资源删除前查动态引用、manifest、工具和许可；Godot 导入压缩与修改原图区分。
5. 运行 harness art；资源接入再 gameplay，查看正式 GUI 的前景遮挡、动画、UI、预警和目标设备性能。技术包检查不能代替合屏视觉/真机验收。
6. 同步消费者清单、素材来源、证据和 handoff；未获评价写候选/待验，不能因为素材多或分辨率高就标品质通过。

交付物：合屏样板、可追溯源文件、运行接入清单与视觉/设备验收状态。
