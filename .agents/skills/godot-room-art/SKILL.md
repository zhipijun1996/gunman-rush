# Godot 房间美术

视觉与关卡的规则拥有者仍是项目现行 Visual Bible、区域 Bible、房间合同和真实 Godot 消费者；本技能提供制作方法，不另外建立第二套设计权威。

## 首先读取

1. 读根 `AGENTS.md`，定位目标区域、房间ID和当前分支。按需查 `docs/bible/visual_bible.md`、目标区域 Bible 与实际房间上下文，不全文读取世界数据。
2. 读 [版本与视觉证据](references/versioned-style-standard.md) 与 [组装方法](references/godot-assembly.md)。恢复素材读 [Cloud接续](references/cloud-portability.md)，区域选择读references/region-catalog.json；47邻接、补素材和复用验收分别见references/autotile-47.md、asset-contract.md、quality-and-reuse.md。
3. 使用assets/approved-five-regions.png、approved-tiles-and-props.png与current-plains-forest-v2.png恢复同一参考；NPC/休息站/收集动画按同风格制作，状态时序沿项目animation-vfx技能，不由动画结算。
4. 检查 `art/world-art-v2/assets/terrain47/manifest.json` 是否真的存在。不存在时须说明“素材尚未接入”，不可把参考参数写成已安装资产。

## 与关卡技能分工

`godot-recoil-level-design` 决定房间职责、能力、敌人、出入口、碰撞、路线与复位；本技能消费稳定的房间几何，决定材质、地标、光照、地形外观、平台附着前景和独立视差。修改实际玩法边界前回到关卡合同验证。

## 默认任务入口

用户说“优化视觉体验”时，以指定房间或连续路线执行本技能：整屏构图、空间层次、区域材质、真实光源、环境运动、角色与碰撞可读性，以及接地、穿插、平台重叠和过门一致性共同检查。先将本房与直接邻房放在同一空间语义中，核对室内外、高度和过渡依据；下层不自动当作室内。接缝用成对正常镜头审看，结构测试不能替代。先判断已有同族素材是否适合本房；适合才复用，不适合就新绘所缺的背景层或构件，不为节省绘制强行套图。没有必要不增加装饰。关卡边界与内部内容的调整沿 Visual Bible 的整房规则，不能把旧几何当作默认不可动的条件；调整时与关卡技能共同复核能力要求、房间职责、连接和失败恢复，未决设计取舍按项目冲突规则确认。起止范围不明时先定位当前工作线，不能自行把局部请求扩为全世界重做。

## 制作步骤

1. 以整房为空间设计单位：先把已定地形、路线、出口和角色尺度放进一张整体构图，安排体量、明暗、留白、景深和地标；用实际镜头路径检查各机位及连续关系，再选素材。用户允许为构图微调时，明确标出局部几何提案并按关卡合同复验，不靠镜头缩放迁就。生成概念稿须叠实际地形核对，图中轮廓不能直接充当碰撞；概念稿不算实机验收。选素材时，按本房腔体宽高与连通方式、地点设定、空间层次、视线及进出方向判断已有资产是否适配；已有、已认可不等于适合本房。以一句地点设定约束材质、光向和运动，再取正式镜头下的入口、动作中点、落点、出口画面，保留原角色尺度与已定玩法。长房先通看整体体量、宽窄分区和结构连接，不能逐屏重复完整透视空间。先检查无装饰的大明暗块、主角剪影和连续构图，再选素材。
2. 先解决空间，再补细节：背景大体量解释地点，必要构件解释建筑或机械用途，局部亮区引导动作，前景只稀疏框边。先按房间制作规范核对是连续通路还是门前交互，再核素材视角与实际进入方向；建筑门不强套屏幕贴边规则。侧向入口以可走入的围合通道成立，不能拿正面门脸补边代替；先用灰盒确认接近落台→围合短廊→切换的空间关系，再成对检查净高、门槛和光向；不能仅尝试几张贴图就判定侧切不可行。门、窗连同台地、墙身、檐口和景深成组设计；小暗室用匹配净空的封闭背墙，不重复整座建筑插图。
3. 落地前并列绑定已认可构图、正式角色／tile材质与固定镜头；构图认可不等于允许照搬概念稿岩层或画法。通用tile用于重复地形；特殊入口的围合与承托按整体空间定制，不能因保留tile而退回通用砖块／横梁拼装。先规划前景宿主、遮挡范围、真实光源与风／视差归属，再按正式tile和角色尺度完成全房体量，逐层细化并同机位对照，不在末尾补灯光和前景；前景实例全部来自房间规划，不接入按边界随机铺景的第二套表现。通过空间适配判断的素材才复用；不适合的背景或构件按本房重新设计，缺件按实际端头、转角、梁底、洞口补画。新件先与角色和原地形合屏比像素密度、体量与对比度，画法不合就替换，不能靠缩小、调暗挽救。
4. 先判断是否需要支撑：自然短台不默认配柱，桥梁／建筑／机械才按用途保留。无碰撞支撑沿 Visual Bible 的背景结构规则降低对比和边缘强度；像实墙或切断动作带则优先删除，不补碰撞迁就装饰。对保留构件按**可见像素边缘**拼装：柱顶接画出的梁底，不拿碰撞盒底代替；整个基座落在支撑面内，平台端头在岸面收口，不能插入地形；连续结构按区域与场所统一选材，不能为修接缝整片换材质；重复落台与出口一同检查，不能按对象编号散换材质。静态体积重叠先修源数据，遮挡只是显示防护。平台前景先选有意义的岸沿、桥底或局部顶棚作为宿主，也可位于房间内部；不沿世界外框自动铺边，不逐台添加。绑定宿主身份和可见附着点，根部固定，枝梢才摆动，并检验玩家经过时的可读性。绑定正确不等于构图成立；先看整屏轮廓、枝叶体量和与原地形的连续关系，突兀外挑或孤立大枝条应删去。附着物保持世界坐标；独立景深层必须有自己的地面和遮挡，不能把贴地道具加视差伪装成远景。
5. 先定稳定环境光，再给实体灯具与真实开口配局部光；角色与怪物的原色可读性沿项目现行规范，不因环境阴影压黑。检查云层与固定地表真正分离；风、云、草叶与光中尘粒按同一空间设定运动，在最终画幅可辨且不遮危险。
6. 快速视觉迭代以一间房为施工单位，相邻房只验接缝；按开发流程同时交付整房总览／空间职责图、2–3段正常速度短片和同机位对照，默认反馈在本房闭环后再扩展；用户明确授权连续多房时，逐房重载整体空间规则，自检、修复并留齐证据后继续，不跳过单房闭环。累计2–3间确认后再整包发布，操作体验需要时提前试玩。用真实场景、正常镜头和正常速度从实际入口连续走到主路与出口并返回，复查上下层、两侧接缝、危险与回访；局部起点片段不能跳过尚未验证的连接段。对照修改前同位置画面，并看手机宽度短片；脚本通过不能代替构图通过，已见悬空、穿插或风格不合先修好再扩展。
7. 素材源图、提示词、机械裁切／锚点／哈希与实际渲染证据随变更交付。分别记录技术检查、视觉判断与未验证范围；长期规则直接改现行正文，房间坐标与任务历史不塞进技能。

## 交付

至少交付已接入素材、可编辑的正式房间或可明确复用的独立样例、所覆盖镜头的截图/短录屏、相关检查结果和未验证范围。先用同族样房校准，再验证不同几何的第二间房。按授权范围施工，不用漂亮静图代替完整玩法。
