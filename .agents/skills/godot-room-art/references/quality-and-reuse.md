# 质量与复用验证

## 按当前任务验收

整房重做先按SKILL主流程完成整屏筛选与正式材质合屏，再取下表的实现检查。局部修改的前提是整体仍成立；用户已否决整屏时，不能只取“更换或增加素材”一行关闭任务。选定意图、真实组装、美术判断和用户反馈分别记录；制作者必须自行淘汰可见的失败，不能以“审美交给用户”免除判断。

| 任务 | 必要检查 |
| --- | --- |
| 更换或增加素材 | 加载、原生尺寸、锚点、透明边缘、重复格纹、实际拼装效果 |
| 调整前景 | 素材外轮廓完整、附着层倍率1、独立近景基座遮罩、mask.surfaceY对应平台、角色局部避让、镜头移动 |
| 调整光照 | 同帧开关、灯位与发光面、材质受光、地形背面遮挡、接触影 |
| 调整风场 | 移动、暂停、方向、像素和缩略动态可见性 |
| 调整地形或危险区 | 正式角色接触、可达路线、落脚区、复位规则 |
| 扩展房型或区域 | 相关组件检查，加镜头全范围、背景覆盖、材质与构图变化 |
| 补47邻接 | 47规范掩码、唯一像素与裁切来源、每种邻域真实拼装、洞角alpha、共享边连续、Godot原生terrain选择 |

复用已有有效检查，围绕当前具体风险增加验证。将结果写回现有任务记录；交付必要的短视频和截图，保持记录简洁。

## 两类检查

程序可检查：资源是否缺失、图集尺寸与切片范围、正式区域ID、锚点、整数显示坐标、真实独立层数量、数据引用和关键碰撞行为。用本技能的 `scripts/inspect_pack.py` 快速检查包输入；它的成功只证明相应文件与配置检查通过。

实际画面检查：按art-direction方法对照当前参考与选定方案，指出空间轮廓、明暗分组、细节分布和玩法面的具体差异。先判断是否值得继续，再检查接缝。角色和危险是否醒目、材质是否协调、前景移动是否碍眼、环境运动是否可感知；把敌人和弹道放进需要战斗的房间再检查。加载成功、32px／47规范、独立图层数量和原生采样都不是美术成立的充分条件。

生成图集先检查实际列界和断开部件的归属；提示词里的等分网格不能代替源图证据。对裁切修正记录源图哈希和原因，保留本区的低对比内芯与边缘衔接。

批量拼装与内嵌预览使用同一Canvas实现时，对同一区域、同一时间和开关状态比对最终像素。带遮罩近景应有各自缓冲，不能把后一个实例或区域的像素写进前一个缓存。素材解码像素一致仍不足以证明最终组装一致；这项比对只用于相同Canvas管线，不要求Godot灯光与Canvas逐像素相等。

必要镜头包括入口、中段、出口；竖井增加顶部和底部，复杂房间增加遮挡或接缝风险位置。普通局部修正检查受影响位置，并回看同机位整屏确认没有破坏主次。

## 风场的感知检查

1. 固定镜头，录制约 6 秒实际运动，观察能否在约 3 秒内辨认主风向。
2. 检查最终编码视频连续帧；手机审核时追加 360 像素宽预览，并同时检查目标游戏尺寸。
3. 若不明显，依次判断光核尺寸与对比、可见空气区域、速度与短尾、地形遮挡；依据原因调整。
4. 回到完整房间，检查角色、弹道、荆棘和落脚点。保持环境运动的从属地位。
5. 单独检查暂停与恢复、边界循环和像素网格。

这些数值是本工作流的可调整验收起点，并非通用行业标准。坐标发生变化只能证明运动逻辑执行，感知效果必须看实际输出。

## 复用分层

| 复用对象 | 可持续使用的内容 | 新房需要决定的内容 |
| --- | --- | --- |
| 原始素材 | 相同材质与形状家族 | 选型、朝向、组合和尺寸档位 |
| 公共组件 | 地形表面、附着前景、危险物、灯光与风场 | 附着点、保护区和参数 |
| 区域配置 | 素材目录、调色、背景结构、环境运动 | 区域独有形状与地标 |
| 房间 | 可编辑的数据格式与通用加载入口 | 几何、路线、出入口、镜头和构图 |

沿用项目已有的数据格式。新增通用入口时，让地形数组完整生成、坐标由房间数据驱动，移除固定森林命名、风铃位置和水平镜头等隐含条件。房间数据决定空间，区域配置决定材质和氛围，公共组件负责组装行为。

## 小规模扩展顺序

1. 先使已认可样房通过公共入口保持效果，再扩充素材或布局。
2. 根据用户当前需求，用同一批区域素材检查竖井或低顶长廊。改变路线、主形、焦点和出口。
3. 依当前全屏方案判断现有素材是否适合；适合才复用，缺少连接面才补接续件，不为保存不合适的大件造补丁。
4. 再将一种已验证房型用于另一地区的小样，检查新材质、背景和环境运动。
5. 实际通过这些房型后，再扩展对应范围的生产任务。

保留每间房固定的关卡设计与地标，采用离线组装和手工调整。美术复用不要求运行时随机生成地图。

## 证据表述

| 已得到的证据 | 可以说明的范围 |
| --- | --- |
| 概念图 | 预期方向与构图意图 |
| 真实 Canvas 合成与视频 | 网页实现的素材、叠层、运动和观感 |
| Godot 导入与无窗口检查 | 引擎资源加载、脚本运行和已测逻辑/物理行为 |
| Godot 窗口截图与实机移动视频 | 该引擎版本、设备与镜头条件下的实际视觉效果 |

交付时写清证据类型。把用户认可的 Canvas 美术方向保存为对应美术锚点；实际引擎观察和正式玩法采用分别追加记录。五区锚点已得到美术认可，16区新增素材仍按每次实际反馈更新。不得把无窗口启动、尺寸检查或共同输入推断成 Godot 窗口视觉验收。

v1曾检查16区Canvas拼装、同帧开关、运动和HTML像素一致性，完成51项Godot无窗口节点/行为检查；森林、冰川、钟心另检查三台阶矩形组合。这些旧记录不自动证明v2新增内容。

v2地形已检查16×47=752个唯一像素变体、2,867次来源拷贝、47种实际邻域以及3,840条占格共享边；没有完全断开的共享边，局部草尖/石屑的边缘alpha允许不同。Godot4.6.3无窗口测试中，16区共752个fixture中心与256种原始八邻域全部由原生terrain连接选对。原生拼装总览用于洞口、薄柱和材质接续目视，不是已完成房间、玩法可达性或GPU视觉验收。复现入口见 `autotile-47.md`；整房新景深、光影与动态的范围以本包对应报告为准。

平原、森林v2背景仍是待用户评价的新候选。分开记录内部目视、程序通过与用户认可，不把本轮制作授权当成新画面已获批准。包身份及验证版本见 `asset-library.json`。
