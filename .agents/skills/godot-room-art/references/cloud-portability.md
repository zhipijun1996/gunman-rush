# 仓库与 Codex Cloud 接续

## 找到同一份当前素材

先定位当前项目的 `AGENTS.md`、本技能和项目素材清单。使用根目录 `bundle-manifest.json` 的 `asset_root`、`skill_root` 与版本字段；项目接入包默认素材目录为 `art/world-art-v2/`。有项目版本时以项目当前清单为准，个人技能中的归档只用于首次恢复与追溯。

方法包包含 `SKILL.md`、`references/`、视觉锚点和检查脚本，不重复内置项目完整素材。仓库已将原生素材展开到项目素材目录；个人技能的旧归档可能另含 `world-art-native-kit.zip`，只有实际存在且版本相符时才能使用，不能假定每份技能都有该ZIP。仅有方法包的新项目应从当前项目仓库或明确交付的素材包恢复，不从旧聊天临时路径猜测。

只读取目标区域条目、相关规则和参考图。保留已经认可的五区材质与光照基准；平原、森林v2背景和后续候选的认可状态按现有索引读取。记录的是具体画面与版本，不能把导入成功或检查通过视为用户对新美术的认可。

## 首次接入

完整素材接入包存在时，先阅读包根的 `ROOM-ART-START.md`，运行其 `python3 tools/art_bundle.py inspect`；方法包不含这些项目工具，不得假称已提供。检查实际文件后，把技能和素材合入项目既有结构，并将短入口合并到原有AGENTS。保留原项目指导、角色和正式入口；几何是否调整由本次设计范围决定。项目已有同名技能或素材时先比较版本，按当前项目权威定向合并，不并行维护两份互相冲突的执行流程。

按操作恢复依赖：查看PNG和清单无需安装绘图库；重建Canvas预览使用项目本地Node依赖；准备Godot样例使用Pillow；重裁源图时才安装NumPy/SciPy。实际入口以包内 `tools/art_bundle.py --help` 和锁文件为准。保持依赖安装在项目本地，不依赖旧会话绝对路径、全局Node模块或ChatGPT专用运行时变量。

运行 `prepare-godot` 从当前原生PNG恢复Godot样例的资产副本与生成遮罩，再打开包内样例工程。样例Godot版本与主项目版本分别记录，不能为了打开样例擅自升级主项目。重建会覆盖派生样例场景；手工修改过的场景先保留，再决定是否重建。

## 新素材与已有素材

复用、拼装和重建现有素材不需要图像生成服务。补画新栅格素材前确认本次环境实际提供图像生成或编辑工具；技能说明不能代替工具权限。给图像工具传入已认可画面、对应材质局部、角色尺度和所需部件布局，再用确定的处理脚本整理输出。

主包已包含使用中的PNG、47邻接与来源记录。两份可选Cloud源图包用于重裁本轮生成原图，与主包使用同一顶层目录，解压到同一父目录合并；历史 `world-art-v2-sources-*.zip` 则解压到 `asset_root` 的父目录。旧版生成原图继续按旧索引按需恢复。导入参考文件中的旧绝对路径仅是来源记录，不作为执行入口。

## 轻量验证与后续扩展

首次从干净目录恢复时检查包身份、关键引用、两区真实拼装和Godot资源/场景运行；后续只运行相关最小检查。把Canvas渲染、Godot无窗口检查和Godot实际渲染分别报告。没有实际窗口/渲染图像时，保留该项未验收的状态。

现有16区样例主要复用一套占格布局，背景覆盖仅证明该样例的镜头范围。长廊、竖井、低顶房间按新的几何适配背景覆盖、平台附着、遮罩、灯位与角色可读性，形成实际样房后再扩展适用范围；不把恢复测试写成这些房型已全部验证。

把新房间写入房间数据，新素材与来源写入现有素材清单；只在共享方法改变时修订技能规则。提交同一批素材、配方和对应预览，使下一会话能从项目当前版本接续。避免在个人技能、项目目录和临时归档里各自维护不同的正式版本。
