# Underworld 区域美术基准

## 版本与证据

使用 `underworld-regional-v1` 标识已认可的美术锚点；`v2-47-depth-expansion` 表示随后补齐邻接、改绘景深与背景的技术/素材扩展，不能把版本升级当作用户的新批准。随技能保存的五区与地形样片用于恢复对应材质关系；当前任务先对照用户本次参考、最新反馈与项目设计圣经，不能因为旧样片曾通过而默认复用它的整房构图和大件。

- 将 2026-11-07 用户明确认可的五区试片作为美术锚点：风铃平原、荆棘森林、蕈灯地穴、齿轮工城、熔火腹地。
- 区分三种状态：用户认可的 Canvas 美术方向、已经做过的 Godot 检查、是否已被正式游戏采用。五区认可没有自动确认后二者。
- 将16区新增素材视为沿用该锚点的扩展版本。用户再次确认具体扩展画面后，再更新对应区域的认可记录。
- 用户随后明确不满意旧平原、森林背景；保留旧图用于追溯，v2重绘分别以 `windchime_plains_v2`、`thorn_forest_v2` 引用。新图当前是候选，不改变五区锚点的其他已认可关系。
- 将早期 `forest-reference.webp` 视为历史方法实验；续作时以本页和五区参考为准。
- 核对项目当前实际加载入口。2026-11-07 核对的项目提交为 `7d73389feab22224d0f8bd7c09325420a7605980`；随项目演进更新事实，保留已认可基准的原版本。

## 不随区域改变的规则

| 项目 | 执行规则 |
| --- | --- |
| 地形采样 | 使用原生 32×32 素材像素对应 32×32 世界单位；最近邻采样 |
| 角色尺度 | 保留项目原角色；本基准身体高约44世界像素，62×62 PNG，脚底锚点 `(41,59)` |
| 显示网格 | 实体、视差最终位移与像素粒子使用同一1世界单位显示网格；保留物理与风场内部小数精度 |
| 镜头 | 640×360 是本基准局部取景，不能据此改动正式项目分辨率、相机或角色大小 |
| 轮廓 | 用细像素簇、局部缺口和窄亮边刻画材料；保持大形清楚、内部安静 |
| 细节分布 | 优先分配给上沿、外角、接触点、地标和受光面；给角色动作带和大片地形腹部留出安静面 |
| 可读性 | 可站立边缘、伤害边界、可交互物与角色轮廓持续可辨；前景绕开关键落脚和出口 |
| 来源 | 保留原图、提示词、裁切与烘焙参数、锚点、哈希和原作者归属 |

检查原尺寸与整数倍放大。最近邻处理只改变采样，仍需挑选像素簇、材质密度和轮廓完成度。镜头缩略图用于可读性判断，不能替代原生像素检查。

## Underworld 继承关系

区分 Asouris 发布的原始16px *Underworld Tileset*、项目 `fine_32` 派生地形、会话中新制作的区域素材。项目当前基准使用 `assets/underworld_plains/terrain/fine_32/terrain.png`，768×192，原生32px，三套草沿/47邻接家族；这是项目派生素材。

平原基准保留这张 PNG 原字节；v2 atlas逐格裁出第一组47格，保持源RGBA像素不变，不要求重打包PNG的文件哈希仍相同。参考其深蓝灰大面、局部蓝石缺口、细而稀疏的橄榄金草沿。把同样的细节组织方式迁移到根土、菌岩、金属砖基、玄武岩等区域材料。15个其他区域用既有九宫格供体加60个新绘内角，组成其各自47格；具体来源和验证见 `autotile-47.md`。

保留来源：[Asouris · Underworld Tileset](https://asouris.itch.io/underworld-tileset)。随包保留项目来源记录和归属说明；不要将第三方原始素材标为 CC0，也不要把新增生成素材说成原作者作品。

## 材质与构件

让上沿、侧壁、台底、外角、内角表达材料自身结构。树根沿土层生长，砖缝有砌筑方向，柱状玄武岩保留竖向破裂；金属只在实际金属部位受亮边。

优先保持地形中心格安静，并保留属于该材质的低对比纹理与边缘衔接。已认可森林和菌岩曾用独立安静填充片替换中心32×32格，保留其余8个边缘格；续作时检查重复根结、亮缝、明暗棋盘纹和硬切黑框。需要补画时用生成或编辑工具处理，再机械裁切。

使用角色附近的小道具与主地标的尺度差建立空间。各区选择不同的主构件：闸门、桥台、冰墙、碑群、井架、柱厅、钟轴等。让同一区域的小件沿用同一种材料加工或生长逻辑。

## 真正的层次

| 层 | 本套起点 | 生产要求 |
| --- | --- | --- |
| 远景底板 | 相机位移倍率0.12 | 低对比，覆盖允许镜头范围；保留独立文件 |
| 中景构件 | 0.45 / 0.62 | 独立透明 PNG 与实例，可移动、隐藏和替换 |
| 地形、地标、角色 | 1 | 世界坐标，碰撞与图像边缘对齐 |
| 平台附着前景 | 1 | 根部/底座固定在所属平台，局部遮挡，不随独立近景漂移 |
| 独立近景 | v2左右实例1.08 / 1.12 | 完整低轮廓靠近平台，世界几何限制基座；保留独立位移和角色避让 |

把这些倍率当作本套起点，按房间深度调整。背景底板即使画有远近结构，也仍只是一层；只有独立素材与独立变换才算可编辑视差层。改变长廊或竖井镜头范围后，重新检查边界、接缝与覆盖，不能直接宣称底板可无限重复。

旧v1使用1.15/1.22近景和±16px镜头演示；v2把近景收近平台，示范镜头扩大至±32px，并仅为这个范围做有限镜像补边。补边不是无缝循环证明。扩展长房或竖井时补充接续素材与覆盖范围。独立中近景使用各自色调和背景环境光，世界地形、灯具与平台附着层共享局部光场；角色与怪物按现行 Visual Bible 保持原色可读。

用 `platform_band` 只逐渐约束近景基座，允许上部轮廓伸过平台边缘。`mask.surfaceY` 指定依附平台的世界高度，防止多层地形时选错层；它不同于terrain的视觉顶饰偏移 `surfaceY`。用 `heroReveal` 局部减弱遮住角色的近景，不把整层降成透明雾。实际参数与行为见 `godot-assembly.md`。

## 光与影

先确定环境底光、主光源与受光方向，再加入克制的亮核、光束和粒子。让地形、地标、附着前景共享同一套局部光场；角色与怪物的原色保护沿现行 Visual Bible；背景使用对应深度的调制与低对比。

在自定义二维光场中保留浮点照明系数：`输出材质 = 材质RGB × (环境光 + Σ 光色 × 能量 × 衰减 × 可见性)`。在最后写出颜色时截断显示范围。保留大于1的能量，使局部受光面能亮于原素材。把同帧“场景光照/素材原色”作为检查工具；原色仍包含源图画出的阴影与发光颜色。

让可见灯位对准精灵实际发光面；背景日光、天光等没有实体灯泡的光不额外画悬浮亮核。用地形遮挡阻断背面受光，给脚底、灯座和落地构件短接触影。根据实际地形和光向微调遮挡轮廓内移，不把一个房间的固定 inset 当作全项目常量。

保持五区参照的关系：平原暖日光/冷天光；森林冷树冠/小暖种荚灯；菌洞暗紫底光/青绿菌褶；工城冷窗/琥珀炉灯；熔火冷却顶面/下方橙红反照。用 `study.json` 的实际灯位、颜色、半径与能量重建，不靠整屏染色代替受光。

Godot 可用 `CanvasModulate`、`PointLight2D`、`LightOccluder2D` 和独立作用层。按当前引擎版本复核接口，并观察窗口实际渲染。Canvas 与 Godot 共用资产和配置也不保证逐像素等同；未制作法线的二维光照按实际能力表述。

## 运动与收尾

用小亮核和短尾表达风尘、孢子、火星或冰尘；控制数量与空气带分布，遵守对应区域运动方向。保持发光点与其所在深度一致，并避开实体地形及角色附近。

同时检查静态像素质量、镜头移动和编码后的短视频。根据本次改动做必要检查：局部粒子改动只复核运动与可见性；新增房型再检查路线、相机覆盖和结构接续。保存通过的画面、素材版本和验证范围供后续会话恢复。
