# level-module-creator

## 当前生产入口：平台与危险同材质接口

先读 [Tile 生产流程](../../../docs/underworld_tile_production.md)，模块卡声明实际 tile 家族、像素/世界尺度、solid/one-way/moving、端口 halo、危险占据的表面区间、装饰 keepout 与例外。平台和刺的**可见材质**共边：尖端、根部与安全边过渡由同一平台表面家族表达，不另垫一块实体或改变可站立边界。伤害 Area/原 hazard 语义保持独立且沿原接触范围；视觉融合不等于把伤害隐藏进无预告安全地面。

先组合世界实体再求邻接；单向/移动平台分家族与参考系。正式非整格地图走精确边界适配而非伪 47TileMap。验证危险边界内外接触、原伤害次数/无敌窗、移动/删除支撑、seed/回程与真实 Motor；额外浮刺、悬空根和被装饰遮住的危险皆为失败。技术正例及故意坏例入口见 `underworld-pipeline`，正式危险行为由运行专项补足。

## 触发与边界

新增平台跳跃挑战、模块端口/时序/连接改动及模块准入。 从仓库根目录调用 `$level-module-creator`。使用 [总门槛](../../../docs/development_quality.md)；重要内容由 game-quality-gate 建立一次任务，专业技能补充同一记录，不重复执行共用阶段。

## 输入与依赖

读取 [AGENTS](../../../AGENTS.md)、[实际状态](../../../docs/current_state.md)、[handoff](../../../docs/handoff.md)、[架构](../../../docs/architecture.md)、[验收](../../../docs/acceptance_tests.md) 和相关最新设计。输入用户目标、基线完整 SHA、任务 ID、内容版本、受影响路径、正式消费者、已知失败与前置能力。缺信息先记录 unverified，独立可逆工作继续；重大创意不可伪称用户确认。

## 阶段流程与交付物

G0：模块名称、玩法目标、必需动作、真实能力要求、进入位置/速度/资源/冷却、入出口端口、操作序列、机关时序、观察区、安全落点、失败恢复、接缝净空、敌人允许点、镜头提示、美术语义、难度收益。先读 [模块契约](../../../docs/platforming_modules.md) 和 [能力](../../../docs/ability_components.md)，不能使用未授予能力。
G1：用现有 [PlayerMotor](../../../scripts/player/player_motor.gd)、实际能力/动作次数和反冲弹体执行。正向、需要的反向、动态相位、资源能力边界、完整身体碰撞/危险扫掠、接缝、失败恢复分别验证。入口速度/冷却写在证据里，不靠传送/手改坐标或几何路径冒充成功。
G2：art-director 验证功能色、地形端头和镜头落点；涉及动作/特效调用 animation-vfx。正常游戏尺寸合屏及连续操作录像，不能为拼图改碰撞。
G3：Module Lab 只作为定位工具；在真实邻接模块、不同端口/镜像/高差和正式随机池验证连接。单模块成功不代表拼接成功。核对正式能力/资源、存档回退和恢复位置。
G4：运行真实 Motor 专项及生成回归；gameplay-reviewer 主动检查危险扫掠、不可见落点、偶然相位和不可恢复状态。禁止擅自调整 PlayerMotor 基础参数使模块过关。
G5：玩家实操可读性、手感、公平性和设备控制；有证据才允许正式池准入。原型可保持 review/blocked 并清楚列出缺项。
交付：设计卡、可玩模块、端口/相位表、邻接矩阵、真实输入轨迹、截图录像和质量报告。

## 设计要求

使用 [专用模板](../../../docs/templates/level_module_design.md) 写场景/前置、方法、可观察结果和失败条件。复用真实配置/Definition/架构，禁止重复数值默认值、无消费者框架或为通过测试改基础物理。占位仅限明确标注的原型，不能冒充最终内容。

涉及可变形状地形时，执行 [邻接与拼接契约](../../../docs/quality/terrain_tile_contract.md)：枚举局部邻接、不同分块的同图对照、薄结构与孔洞、真实 GPU 与正式合屏分开验收。不能用覆盖率代替美术品质。

地形表现接入时引用 [地形契约](../../../docs/quality/terrain_tile_contract.md)：一行平台也须覆盖长度×厚度、短端头、相邻间隙和移动相位。物理尺寸先定，素材按外露边界适配，不为图片改变已验模块。单向桥、实体台与危险的轮廓语义分开；用正式模块合屏证明落点可读。

## 自动验收

运行 harness gameplay，定位入口 [地区测试](../../../tools/run_plains_region_tests.py)、[共享消费者](../../../tools/run_generated_consumer_tests.py)。保留正例与必失败反例，记录 Seed/Manifest、能力、入出口状态；结构测试和 Motor 验证分栏。 记录实际命令、环境、退出码、日志和版本；计划命令不算执行。执行 [质量检查](../../../tools/quality.py)；静态检查、运行测试、实际宿主调用分别记证据。

## 人工审查

采用 [通用审查方法](../../../docs/quality/review_method.md) 的不变量与对照/变形测试，覆盖实际绘制与正式消费者；用户反馈是回归样本，不是发现问题的唯一列表。

在镜头中观察危险/落点、提示与安全空间；玩家是否学得会、失败能理解且能恢复。审查相邻组合及资源边界，不能只看蓝图。

## 准入退出与返工

按 [policy](../../../docs/quality/policy.json) 的相关 G0–G5 执行。进入一阶段前上一相关阶段通过、输入与消费者明确；退出须专用模板的可证伪判据及对应证据成立。设计失败退 G0，操作/公平失败退 G1，表现失败退 G2，接入/状态失败退 G3；修复后重跑受影响门槛并复审。保留失败原件，不删除测试/降标。依赖阻塞写 blocked，缺审查写 review，缺真机写 awaiting-device。

## 完成与证据

使用 [质量报告](../../../docs/templates/quality_gate_acceptance.md) 和 docs/quality/records/<task_id>.json，逐项记录 design/technical/formal_integration/visual/animation/audio_vfx/gameplay/performance/independent_review/device/player_acceptance。只允许 passed/failed/unverified/not_applicable（有理由）；证据需路径、SHA256、提交/内容版本、观察和来源。技术通过不能宣称完整内容完成；所有适用条件具备才可 done。本技能文档本身不提供任何内容的 PASS 或用户认可。

## V2：动作链中的模块

使用 [挑战卡](../../../docs/templates/challenge_sequence.md) 与 [V2 入口](../../../docs/level_design_harness_v2.md)。challenge-choreographer 负责玩家连续动作与决策，本技能负责把它实现为 PlatformingModuleDefinition/现有模块消费者，不另建相互冲突的模块池。

输入必须包含“为什么需要这个模块”、所属主路/奖励/大师合同、动作链位置、上下游模块、合法单武器能力快照、目标设备、空间/美术需求。权威能力与资源读取实际装备/授予点、PlayerMotor、Definition、player_tuning/input_profile 和最新动作文档；规划中或仅 Studio 授予的能力不得进入正式主路。

实际步骤：把每个动作转为入口位置/速度区间、身体碰撞包络、动作次数/能量/冷却及稳定站位条件 → 列主要与替代输入序列 → 定义落点/出口状态、动态相位、观察/恢复窗口 → 检查上段出口是否满足本段入口（资源和时序也须满足）→ 复用 Foundry 验证单模块、连续短语和 itinerary → 验真实邻接、反向返回、失败恢复 → scene-composer/art-director 合屏 → 正式候选池及原生成回归。

优先验证射击在同一动作中触发敌人/机关并产生反冲的双重作用；不能为证明恢复而直接加能量、重置相位或中途传送。敌人可改变路线/时机，但不得无预告占据唯一合法落点。移动落点必须验相对运动和最低观察时间；多摇杆同时精确输入在手机上单列人工门槛。

输出在原设计卡增加：compatible_predecessors/successors、进入/退出真实状态、行动依赖、拒绝组合及原因、目标设备操作、相位矩阵、完整输入轨迹和失败帧、镜头/素材接缝需求。数值从真实运行采样，未校准写 unverified。

自动验证：执行 V2 validate/analyze（以总入口 --help 为准）、Foundry 原真实 Motor build/回放及适用 harness gameplay；保留“各单模块可过但串联资源不足”反例、错误入口速度反例、不可见落点与低能量/不利相位例。记录单模块与连续 itinerary 的独立结果，完整地区路线未回放不能外推。人工按普通/进阶/大师三张卡检查可读、流畅、失败学习、设备可操作性。

任何碰撞/资源/相位变更使相关旧轨迹失效；返工 challenge-choreographer 的衔接或本模块几何，禁止改 PlayerMotor 迁就模块。Foundry --promote 只进开发工坊，不是正式模块准入。正式晋级仍依 G0–G5、真实消费者/独立/用户和设备证据。

示例：短“跳跃→向下射击反冲→方向修正→稳定落地”作为普通黄金技术片；仅在实际 Definition 和 Motor 确认后采用。更长组合为进阶/大师候选，不能仅凭动作数命名难度。

## 自主生产闭环与 Q1–Q8

每次关卡任务先执行 [统一质量维度的权威加载与来源账本](../../../docs/quality/level_quality_dimensions.md)：自动读动作入口、regions_v0.3、weapons_v0.8 全文及最新覆盖合同，核对 LOCKED/PROPOSED、实现消费者与正式授予三种状态。继承 S1–S6/16地区、H/W/D/U1/U2、S2单能力、S4替代、S5双移动+U1；不从旧八关或旧V2摘要重创规则。Q1–Q8 映射既有十一维，不增加质量编号。

依据当前任务的最新用户授权及可写范围直接设计、实现、测试、审查、返工；历史“仅工具”或“有限切片”不覆盖后来的整区授权，也不自动授权其他地区或核心规则变更。PlayerMotor/武器/资源/随机流/保存与未授权地区仍是边界。用户负责核心创意与审美偏好/最终体验认可；常规缺陷由团队主动发现修复。

本技能负责 Q2/Q3 的真实模块消费者及 Q8，不把“编舞卡完整”当模块已完成。接卡先确认上段实际出口速度/资源/相位能进入本段，写具体 Definition/装配路径与邻接测试；沿用真实武器，不把最大能力包络当当前装备。

实现时用正式敌人/机关组合验地形：敌人存活、走离、死亡、未激活的最坏状态，唯一落点/资源恢复/返回不应消失。边界 fixture 与真实输入产生状态分别留证；单片通过后测试相邻连续链和正式地图，改动消费者不能只在Foundry有效。

修改后自动运行受影响Godot/生成/Harness与故意失败例，再交独立审查；不让用户发现穿模/盲落点/死路。返工包指出物理位置、期望/观测、失败帧和最小几何或时序调整，禁止改基础Motor/武器/资源。只有完成本轮实际正式切片与同条件对照才声明实现范围，不以计划命令或模板签收。
