# game-quality-gate

## 适用任务

新创造的区域、地图、怪物、Boss等内容。普通修复、规则调整、工程和文档维护使用当前交接及相关检查，不强制质量卡。

## 操作

1. 按任务读取现行圣经、对象规范和真实消费者，明确本次内容及玩家会观察、判断和操作什么。
2. 选择实际需要的专业，先重整受影响的规范，再制作真实可玩的样板；允许结构灰盒，明确结构与正式内容的验收边界。
3. 在正常镜头和连续操作中检查美术统一与玩家体验，修复主要缺口后再扩展。场景套件按[godot-room-art](../godot-room-art/SKILL.md)区分固定原型、同批资源跨房型复用与逐房验收；分别核静态画面、镜头运动及实际功能，不以相同像素、节点数量或不同房各有一张整图证明复用。按改动执行功能回归。
4. 按 [开发与审查](../../../docs/project/development.md) 记录适用结果与证据，不适用项省略。用户试玩、真机和额外独审只在本任务明确需要时作为完成条件。

## 验证与交付

交付实际场景、相关检查、音画观察、发现及未验范围。质量卡只记录内容审查，进度只更新任务表；专业判断、用户反馈和设备结果分别署明。

工具为 `quality.py init/check` 和显式选择的 [Harness](../../../docs/project/harness.md) 专项。任务交接见 [协作规则](../../../docs/project/cloud_production.md)。
