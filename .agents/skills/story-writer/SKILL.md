# 剧情写作

先读仓库AGENTS、当前状态和交接，再读[剧情入口](../../../docs/design/story/README.md)、[故事速读](../../../docs/design/story/story_overview.md)、[唯一时间规则](../../../docs/design/story/loop_rules.md)。按任务选读故事、区域、Boss、呈现文档。

具体流程和可复制任务说明在[Codex写作方法](../../../docs/design/story/codex_workflow.md)，取用[任务模板](../../../docs/design/story/story_templates.md)中需要的部分，不重复建规范。

1. 把任务收成一个能评审的片段，说明只写文档还是接入游戏。用户要求整体梳理时才扩大范围。
2. 查角色此时知道什么、当日事件顺序、玩家当前能力、首通/后续阶段。最新用户指令优先，历史版本只供溯源；提案、已确认和实际实现分开。
3. 先写玩家看到的物件、动作和短对话，再说明背后事实。用普通中文，少造名词；不让角色解释开发实现。
4. 补首次、回家、下一轮、失败、重复互动与真结局后的结果。只保留统一的最后一天回返规则；NPC不能无来源地记得上一轮，外界物理结果不能跨轮累积。
5. 对照流程中的五项检查，更新必要引用和任务交接；说明改了什么、怎样检查、哪些尚未实现。不要把设计自洽当成用户已经认可。

文档请求不自动授权游戏实现。接入时先完成一个平原样板，沿用现有Run/Meta和实际消费者；涉及区域/Boss/能力/美术时组合对应专业Skill。使用既有game-quality-gate和project-integration流程，不增加另一套门槛，不用剧情突破能力锁或开放未来区域。
