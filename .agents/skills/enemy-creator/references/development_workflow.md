# 怪物开发方法

适用于新物种、实质改造与局部补齐。入口为 [对象索引](../../../../docs/enemies_and_bosses.md)；共用文档规则按 [AGENTS](../../../../AGENTS.md)，完整物种的验收范围按 [完成标准](../../../../docs/quality/enemy_completion_standard.md)。本页只规定制作顺序，不重复维护行为或参数。

## 从规范到实现

1. 核当前消费者与选定区域圣经，定位唯一对象规范。已有规范直接整理正文；缺规范时用 [Enemy Design Sheet](../../../../docs/templates/enemy_design.md) 补齐本次对象，任务 ID／基线／进度放现有工作线。
2. 先写清身份与职责、状态／触发／反制、伤害／掉落、表现、生命周期及验证方法。参数只引用 Resource／Definition 字段、单位和覆写来源，不在文档维护第二套默认数值。
3. 再改 Registry／Factory／Definition／Behavior／Motor 与真实遭遇。先做一组真实输入下的攻防，再扩状态和组合；表现只消费接受事件，物种数据与实现同一任务同步。
4. 核受影响的入口、退出、中断与保存；用当前身体消费者观察正常速度音画，再依据证据更新任务结果。局部修复沿用未改变的设计，不因读到完成标准自动扩为全物种重做。

## 专业分工

| 责任 | 交付位置 |
| --- | --- |
| 机制／AI／运动／反制 | 对象数据规范及实际组件；通用原则引用游戏设计 |
| 身体／动作／命中／死亡／声音 | 同一对象的表现章节、真实资产与来源记录 |
| 地形／同伴／奖励／返程 | 具体遭遇与地图消费者，引用对象规范 |
| 进度／缺口／独审／设备 | 父任务工作线和已有质量记录，不写进长期数据正文 |

## 验证和收尾

从 [模块导航](../../../../docs/module_map.md) 选真实专项，覆盖当前状态和本次影响的转换。共享结构检查、静态图片、正式遭遇、独审和用户／真机证据分别记录；未观察项保留未验证。原始失败证据不改签，临时中途稿在结论整合后删除。

数据规范始终描述完整当前对象；它不等于该对象已获用户或设备验收。必要来源、许可和可复现原件归档，其余历史由 Git／PR 追溯。下一会话只读当前对象与工作线，不加载旧轮次全文。
